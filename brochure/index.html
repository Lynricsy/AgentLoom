写在前面

当 AI 不再只是一个聊天框

大多数人第一次接触 AI，是在聊天窗口里一问一答。可真实的工作很少是“一个问题、一个答案”就结束的：它需要好几个步骤、要用上各种工具、要读公司自己的资料，还最好能每天自动跑、整个团队一起用。

你可能遇到过

复杂任务要自己在多个 AI 对话之间来回复制粘贴，换个人就做不出同样的结果。

AI 想用公司的文档、数据库、代码仓库，却“够不着”，只能凭训练数据猜。

好用的 AI 流程只存在某个人脑子里，没法定时运行、没法复用、也没法审计。

AgentLoom 的做法

在可视化画布上把多个 AI 和工具连成一条流水线，设计一次，反复执行。

给 AI 配上工具、知识库、记忆、技能和安全沙箱，让它真正能动手。

版本管理、自动触发、团队权限、市场共享、审计日志，从个人技巧变成组织能力。

01AGENTLOOM 是什么

一台为 AI 准备的“织机”

Loom 是“织机”的意思。AgentLoom 把大模型、工具、知识库、记忆这些零散的 AI 能力当作丝线，由你在画布上设计纹样（也就是流程），最后织成一匹能自动运转的布——一个可以反复执行、可以分享、可以追溯的 AI 工作流。

AgentLoom 是一个多智能体工作流编排平台：你在可视化画布上把 AI Agent 组合成工作流并执行；每个 Agent 也能脱离工作流，独立对话、独立运行。

02两个主角

Agent 是员工，工作流是流水线

AgentLoom 里有两个并列的顶层概念。弄清它们的分工，就理解了整个平台的一半。

每个 Agent 都像一位带着专属工具的 AI 同事：有的查资料，有的写代码，有的调用外部系统，有的负责记住上下文。（AI 生成插图）

Agent · AI 员工

自由对话式协作

以对话为核心：你随时下达新指令，它结合上下文理解意图；自己判断该调哪个工具、查哪份资料；拥有长期记忆，越用越懂你。

适合：开放式、探索性、需要随机应变的任务。

代码开发知识问答数据分析项目协助

工作流 · 流水线

结构化流程编排

由节点和连线组成有向无环图（DAG），按预定步骤执行；每一步输入输出明确，可重复运行、可版本管理、可被定时或外部事件触发。

适合：重复、可预测、需要标准化输出的任务。

批量处理定时自动化多步骤编排团队模板

两者之间的桥梁：Agent 节点

AGENTLOOM 图解入门03 · 核心概念
03核心概念

六个词，读懂一张工作流

下面是一张真实结构的工作流：手动触发后，“研究助手” Agent 借助网页搜索工具和写作技能完成任务，再把文字结果和结构化数据分别输出。图中编号对应下方的概念。

① 节点 Node

画布上的“功能积木”：调用 AI、发 HTTP 请求、做条件判断……每块只负责一件事。

② 端口 Port

节点上的“接口”，像 USB-C 与 HDMI：左侧输入、右侧输出，每个端口都有数据类型。

③ 数据边

节点间的“管道”，把文本、JSON、工具、沙箱等数据从上游送到下游。

④ 执行流边

决定“谁先谁后”：前一个节点完成后，才轮到下一个。数据线和控制线通常一起连。

⑤ 类型检查

同类型直连为绿色；可自动转换（如 JSON→文本）为黄色；不兼容直接禁止连接。

⑥ 执行与版本

每点一次“运行”就是一次执行（照食谱做一次饭）；版本则是随时可回滚的存档点。

它们如何串在一起

AGENTLOOM 图解入门06 · Agent 解剖图
06AGENT 解剖图

一个 Agent 由什么组成

Agent 的核心是一个大模型，加上一段定义角色的系统提示词。真正让它“能干活”的，是你在 Agent 的配置画布上为它接入的各种能力——同样用连线的方式完成。

两种运行形态

进程内运行 no_sandbox

在服务端进程内直接驱动 Agent 内核，启动快、开销小。适合对话、知识检索、调用工具这类“只动脑不动手”的任务。

沙箱运行 sandbox

在独立的 Firecracker 微虚拟机中运行编码 Agent，拥有自己的文件系统和终端。适合写代码、跑测试、处理文件。

智能路由：让系统替你挑模型

在多个候选模型间按策略选择，兼顾成本、质量与可用性：

随机轮询规则大模型当路由降级链kNNMLPElo 评分记忆库WASM 插件

技能：可复用的“工作方法”

技能是一组写在 SKILL.md 里的行为指令，注入后 Agent 就按这套方法做事。内置 5 种，也可自定义：

代码审查文档编写测试生成代码重构调试排错

多轮对话

理解上下文，回复实时推送；Web 与手机上的对话体验一致。

版本与发布

Agent 定义有独立版本；发布后才能被工作流里的 Agent 节点引用。

子 Agent 委派

“项目经理” Agent 可把编码交给“开发者”，把设计交给“设计师”。

07知识库与记忆

读懂你的资料，记住你的习惯

知识库解决“AI 不知道公司内部的事”；记忆解决“AI 每次都像第一次见面”。

记忆：会成长的“同事印象”

AGENTLOOM 图解入门08 · 安全沙箱与插件
08安全沙箱与插件

让 AI 动手，但不越界

Agent 一旦能执行代码，安全就是第一要务。AgentLoom 把所有“危险动作”关进隔离边界：平台本身不碰虚拟化特权，代码只在一次性的微虚拟机里运行。

微虚拟机级隔离

每个沙箱会话一台轻量虚拟机，比普通容器多一层内核隔离，代码跑坏也只坏在里面。

多节点调度

可登记多台运行时节点，按实时容量择优分配；节点忙或掉线时自动换下一台。

持久工作区

Workspace 卷让文件跨多次执行保留；同一工作流里的多个 Agent 可共享一个沙箱接力。

插件：签名校验 + WASM 沙箱

平台级安全清单

登录：邮箱密码、Google / GitHub、TOTP 两步验证

调用：JWT 会话或 API Key，全部接口限流

隔离：数据库行级安全（RLS）按组织隔离数据

加密：组织级加密密钥管理

追溯：重要操作写入审计日志

兜底：沙箱与运行时异常一律“失败即关闭”

AGENTLOOM 图解入门09 · 自动运行与实时监控
09自动运行与实时监控

设计一次，自动运行无数次

工作流发布后，就可以交给触发器来启动。每一次运行都会排队、执行、推送进度，全程留痕。

手动

点“运行”，或填写表单参数后启动，适合调试和按需执行。

定时

Cron 表达式 + 时区，例如“每个工作日 9:00 生成日报”。

Webhook

外部系统发一个 HTTP 请求即触发，支持简单与签名两种鉴权。

API 事件

监听事件源，如 GitHub 新建 Pull Request 时自动开始审查。

一次执行的一生

过程透明，随时可查

节点在画布上依次亮起，状态、输出流式推送。

网络断开重连后，按事件编号增量补齐，不丢进度。

逐步骤查看 Agent 的推理与工具调用细节。

失败时定位到具体节点，配合调试面板排查。

版本：放心改，随时回

快照随时保存，不影响运行状态；只有发布的版本才能被触发器自动运行、被分享或上架市场；归档后不可编辑和运行，但保留历史记录。

从一句话到上线，经过这些关卡

为什么要这么多关卡？

AI 生成的应用“看起来能跑”不等于“真的能用”。AgentLoom 把需求、验收场景和证据串成追踪矩阵：每条核心需求对应哪些场景、哪些测试证据通过，一目了然。生成过程、修复尝试、每道门禁的运行记录全部留存。

上线之后

终端用户通过公开链接使用应用；每一次提交都可以启动绑定的工作流。创建者在 Studio 里查看提交列表、运行状态、最终输出与报告——预览地址、源码和测试报告只在创建者工作台可见。

给技术同学的一张全景图

层次技术选型
契约Zod 4 定义服务端与各客户端共享的数据格式；OpenAPI 自动生成前端类型，避免前后端“对不上”。
前端React 19、Vite 7、TanStack Router / Query、Zustand；画布基于 React Flow，端口兼容性由 Rust/WASM 引擎在 Web Worker 中检查。
后端NestJS 11 + Fastify 5、Drizzle ORM、BullMQ、Socket.IO（Redis 适配，可水平扩展）。
运行时Go 编写的运行时管理器调度 Firecracker 微虚拟机；插件经 RSA-PSS 验签后在 Extism WASM 中执行。
部署Docker Compose / Helm；生产地址 agentloom.ling.plus；以 GPL-3.0 协议开源。

契约单一来源

数据格式只在一处定义，服务端、Web、手机共用，跨端一致性由测试机械校验。

多租户到底层

业务表都挂行级安全策略，每个请求都在所属组织的事务里执行。

事件可回放

15五步上手

从零到第一个自动化工作流

跟着下面五步走，大约半小时就能看到第一个工作流自己跑起来。

1

注册登录，加入组织

邮箱或 Google / GitHub 登录；新建组织或接受邀请。创建者（Creator）及以上角色才能创建资源。

2

配置一个大模型

在「资源 → LLM 模型」里接入模型提供商，这是所有 Agent 的“大脑”来源。

3

创建你的第一个 Agent，和它聊聊

写好名称和系统提示词，按需接入知识库、工具、技能、记忆，发布后即可开始对话。

4

新建工作流，拖拽连线，点“运行”

放一个触发器、一个 Agent 节点、一个输出节点，连好线，看着节点逐个亮起。

5

发布，让它自己跑起来

发布正式版本，配置定时或 Webhook 触发；觉得好用，就分享到市场给更多团队。

常见疑问

需要会写代码吗？

不需要。搭工作流靠拖拽连线；会写代码的同学可以用代码节点、插件和 API 走得更远。

能用哪些大模型？

在「资源」里接入模型提供商（如 OpenAI、Anthropic 等），并可用智能路由在多个模型间切换。

我的数据安全吗？

组织间数据库级隔离，代码在微虚拟机里执行，重要操作写入审计日志。
