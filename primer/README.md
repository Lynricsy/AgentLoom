# AgentLoom · 通俗版说明册

一本 A4 PDF：`out/AgentLoom-是怎么搭起来的.pdf`（67 页）。

## 它跟 `interview-brief/` 的区别

|  | `interview-brief/` | 本目录 |
| --- | --- | --- |
| 读者 | 已具备后端/前端技术背景 | **不写代码、没听过 Zod / NestJS / Drizzle** |
| 写法 | 一句话一个结论，术语不解释，高密度速记卡 | 从零讲起，术语首次出现即用大白话解释，宁可啰嗦不跳步 |
| 排版 | 固定页瑞士国际主义（无衬线、发丝线、大量留白） | 书籍式流式排版（衬线正文、1.95 行距、Chrome 自动分页） |
| 篇幅 | 10-53 页，为索引优化 | 67 页，为可懂性优化 |

两者内容有重叠，结论一致；差别只在密度与预设知识。

## 重新生成

```bash
cd primer
node build.mjs
```

构建脚本会：

1. 拼接 `style.html` + `chapters/*.html`（按文件名排序）；
2. 用 headless Chrome 流式排版输出 A4 PDF，页脚自动页码；
3. 体检：横向溢出（长代码/宽表格撑破内容盒）、术语框重名——任一命中即列出并以非零码退出。

## 三种方框的语义

正文用三种带边框段落承载不同职责，改内容时不要混用：

- `.termbox`（蓝色左边框）——术语首次出现的解释。同一术语只解释一次，构建脚本会检测重名。
- `.analogy`（灰框）——类比。全书统一用「一间餐厅」作为主类比。
- `.problem`（橙色左边框）——「不这样会出什么事」。技术选型的理由主要落在这里。

## 字体依赖

正文用 `Noto Serif CJK`（长文可读性优于无衬线），标题与界面元素用 `Noto Sans CJK`，代码用 `JetBrains Mono`。CSS 通过 `file://` 直挂字体文件，绕开 Chrome 侧 fontconfig 泛用族解析失效的问题。

## 内容纪律

- **术语必须先解释再使用**。新增章节若引入名词，要么在第二部分补一条 `.termbox`，要么就地解释。
- **区分「代码存在」与「代码在生产路径上生效」**。册中所有实现描述均以生产代码为准；被环境变量门控、无调用点、或位于 `testing/`、`__tests__/` 下的实现不得用作论据。此纪律写入第 23 章正文。
- **缺口如实写**。第 23 章列出的问题（含一个未认证配额耗尽面）以源码核实为准，不做粉饰；已确认属有意设计的（审计双写入口、优化建议禁用）明确标注「这是有意的」。
- **不夸大选型收益**。第 17 章如实记录「选 Rust 的第二条理由至今未兑现」。
