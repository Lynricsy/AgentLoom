# 版本管理

版本管理是 AgentLoom 保护你工作流安全的重要机制。它让你可以随时保存进度、查看历史变更、回滚到之前的版本，以及将工作流发布为正式版本供生产使用。

---

## 版本的基本概念

### 什么是版本

版本是工作流画布在某个时间点的完整快照。它记录了该时刻的：
- 所有节点及其配置
- 所有连线
- 画布视口位置（缩放和平移状态）
- 输入参数定义（如果有）

### 版本与自动保存的区别

AgentLoom 有两种保存机制：

**自动保存**（持续进行）
- 你在画布上做的每一个改动都会自动保存到当前草稿
- 这保证了你不会因为浏览器崩溃或网络中断丢失工作
- 自动保存不会创建版本记录

**版本快照**（手动创建）
- 你主动点击"保存快照"按钮时才会创建
- 每个版本都有独立的标签，方便后续查找
- 版本是不可变的 -- 创建后不会被修改或覆盖
- 你可以随时回到任何一个已保存的版本

把自动保存想象成"随手保存"，版本快照想象成"存档点"。游戏玩家应该很熟悉这个区别。

---

## 保存版本快照

### 操作步骤

1. 在画布编辑器中，找到版本工具栏上的"保存快照"按钮。

> 界面提示："保存快照"按钮在版本工具栏左侧，带有保存图标。当工作流处于归档状态时，此按钮不会显示。

2. 点击"保存快照"按钮后，会弹出一个对话框。

3. 在对话框中：
   - **标签**（可选）：为这个版本起一个描述性的名称，例如"添加条件分支逻辑"或"修复 API 请求参数"

4. 点击确认，版本即保存成功。

### 何时应该保存版本

建议在以下时机保存版本快照：

- **完成一个阶段性的修改后**：比如添加完一组新节点并测试通过后
- **准备进行大幅度修改前**：这样即使改坏了也能回滚
- **发布之前**：在正式发布前保存一个快照作为参考点
- **修复某个问题后**：记录修复后的状态

## 查看版本历史

### 打开版本历史面板

在版本工具栏中，点击"历史记录"按钮打开版本历史面板。

> 界面提示："历史记录"按钮带有时钟图标。点击后会弹出一个面板，列出该工作流的所有版本记录。

### 版本列表

版本历史面板以列表形式展示所有版本，每条记录包含：

| 信息 | 说明 |
|------|------|
| 版本号 | 自动递增的版本序号 |
| 标签 | 你在保存时填写的描述标签 |
| 创建者 | 保存该版本的用户 |
| 创建时间 | 版本的保存时间 |
| 发布时间 | 如果该版本已发布，显示发布时间 |
| 版本快照信息 | 节点数量和连线数量 |

### 查看特定版本的内容

点击版本列表中的某个版本，可以查看该版本的详细信息，包括当时的节点和连线构成摘要。

## 发布版本

发布是一个重要的操作，它将工作流从"草稿"状态提升为"已发布"状态，意味着工作流已经准备好投入生产使用。

### 发布的前提条件

- 工作流当前状态必须为"草稿"（已发布或已归档的工作流不能重复发布同一个流程，但已发布的工作流可以再次发布新版本）

### 操作步骤

1. 在版本工具栏中，找到"发布"按钮（绿色按钮）。

> 界面提示："发布"按钮仅在工作流状态为"草稿"时显示，位于版本工具栏中，带有上传图标。

2. 点击"发布"按钮后，会弹出发布对话框。

3. 在对话框中填写：
   - **版本标签**（可选）：为发布版本命名
   - **发布说明**（可选）：记录本次发布的主要变更内容
   - **基于版本**（可选）：可以选择基于哪个已保存的版本快照发布，默认发布当前画布状态

4. 点击确认发布。

### 发布后的变化

发布成功后：
- 工作流状态从"草稿"变为"已发布"
- 状态徽章从蓝色"草稿"变为绿色"已发布"
- 工作流版本增加一个发布版本号
- 触发器开始生效（如果配置了定时/Webhook/API 事件触发）
- "分享"按钮变为可用，可以生成分享链接
- "发布到市场"按钮出现，可以将工作流上架到社区市场

### 发布后继续编辑

发布后，你仍然可以继续编辑工作流。编辑的内容会保存到草稿中，不会影响已发布的版本。当你完成修改并验证通过后，可以再次发布（发布新版本）。

---

## 回滚到之前的版本

如果发现新版本存在问题，你可以回滚到之前的某个版本。

### 操作步骤

1. 打开版本历史面板。
2. 在版本列表中找到你想回滚到的目标版本。
3. 选择该版本并执行恢复操作。
4. 画布会加载目标版本的内容（节点、连线、配置等）。
5. 确认恢复后，当前画布即替换为目标版本的状态。

> 注意：回滚操作会覆盖当前画布的内容。如果当前画布有未保存的版本快照，建议先保存一个快照再回滚。

## 归档工作流

当一个工作流不再需要使用时，你可以将其归档。

### 操作步骤

1. 在版本工具栏中，找到"归档"按钮。

> 界面提示："归档"按钮带有归档图标，通常位于工具栏最右侧。如果工作流已发布，归档按钮会显示为黄色强调色，因为归档已发布的工作流是一个需要谨慎操作的行为。

2. 点击"归档"按钮后，会弹出确认对话框。

3. 确认归档。

### 归档后的影响

- 工作流状态变为"已归档"（灰色徽章）
- 不能再编辑画布
- 不能运行工作流
- 触发器停止生效
- 不能保存新版本或发布
- 历史版本记录和执行历史仍然保留，可以查看
- 归档操作可以撤销（如果需要重新激活工作流）

### 何时应该归档

- 项目已结束，相关工作流不再需要
- 工作流已被新版本替代
- 为了保持工作流列表的整洁

## 版本管理的最佳实践

### 建立版本保存习惯

不要等到出了问题才后悔没有保存版本。建议在每次有意义的修改后都保存一个快照，并且写清楚版本标签，这样回头查看时能快速理解每个版本的变更内容。

### 版本标签写得有意义

好的版本标签示例：
- "添加代码审查分支"
- "修复 API 超时问题"
- "优化系统提示词"
- "发布前最终检查"

不好的版本标签示例：
- "v1"
- "更新"
- "修改"
- "test"

### 发布前充分测试

不要急于发布。在发布之前：
1. 运行多次测试，验证各种输入场景
2. 检查所有分支路径是否正常工作
3. 确认输出结果符合预期
4. 保存一个标注为"发布前验证"的版本快照

### 及时归档废弃的工作流

定期清理不再使用的工作流，将它们归档。这样可以保持工作流列表的清晰，避免团队成员误用废弃的工作流。
