# 版本管理

本页说明如何为工作流保存快照、发布版本、回滚和归档。前提：工作流处于草稿或已发布状态（已归档的工作流是只读的）。

画布的自动保存只更新草稿。快照是手动保存的画布状态；发布会生成一个带版本号的发布版本，工作流状态变为「已发布」。

## 保存快照

1. 在画布顶部工具栏点击「保存快照」。
2. 在「保存快照」对话框中可选填写「快照标签」（例如「添加了审批节点」），点击「保存快照」。

右下角提示「快照已保存」。

## 发布

1. 在工具栏点击「发布」，打开「发布工作流」面板。
2. 可选填写「发布标签」与「发布说明」。
3. 在「发布版本来源」中选择：
   - 「当前编辑稿」：把当前画布状态创建为新的发布版本。
   - 「选择已有记录」：在「选择记录」中挑一条已保存的快照或历史发布。没有记录时显示「暂无可发布记录，请先保存快照」。
4. 点击「发布」。

面板显示「工作流已成功发布」，状态徽章变为「已发布」。存在兼容性问题时同时列出兼容性警告，提示形如「工作流已发布，并返回 N 条兼容性警告」。点击「完成」关闭面板。

已发布的工作流继续编辑后，工具栏仍显示「发布」：选择「当前编辑稿」即把修改后的草稿发布为新的版本（版本号递增），之前的发布变为「历史发布」。

发布前会校验画布结构，以下情况发布失败（错误类型 `workflow-publish-validation`），面板列出每条原因，修正后重新发布：

- 连线构成环路（容器节点内部的连线单独检查），提示「工作流图存在环路，执行顺序无法确定」或「复合节点 … 内部的连线存在环路」。
- 连线的起点或终点节点已不存在，提示形如「连线 … 的目标节点 … 不存在」。
- 连线接在节点上不存在的端口，提示形如「连线 … 的源端口 … 不存在于节点 …」。

只有已发布的工作流才能创建触发器，见 [触发器与自动化](/guide/triggers/)。发布到市场是另一个操作（工具栏「发布到市场」），见 [市场](/guide/collaboration/marketplace)。

## 查看历史与回滚

1. 在工具栏点击「历史记录」，打开「历史记录」面板。每条记录显示为「快照 #编号」或「版本 v编号」，附标签、创建者与节点、连线数；当前发布版本带「当前发布」标记，旧的发布带「历史发布」标记。
2. 在某条记录上点击「回滚」，确认对话框提示「当前未保存的更改将丢失」，点击「确认回滚」。

右下角提示「回滚成功」，画布恢复为所选记录的内容。在历史记录中也可以对某条记录点击「发布」或「重新发布」。

## 归档

1. 在工具栏点击「归档」。
2. 在「确认归档」对话框中点击「确认归档」。

提示「归档成功」，工作流变为只读，不能再编辑或发布。此操作不可撤销。
