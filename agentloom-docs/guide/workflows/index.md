# 工作流概述

工作流是 AgentLoom 的核心功能。它让你可以将多个 AI 智能体和工具按照特定的逻辑组合成一条自动化流水线，从而完成从简单到复杂的各种任务。

---

## 什么是工作流

在 AgentLoom 中，工作流是一组节点通过连线按照有向无环图（DAG）结构组成的自动化流程。

**有向无环图**听起来很技术化，但概念其实很简单：

- **有向**：数据和执行指令只朝一个方向流动，从上游节点流向下游节点，不会反过来
- **无环**：数据流不会形成死循环（A 传给 B，B 传给 C，C 又传回 A 这种情况不允许）

> 注意：虽然工作流整体不允许形成环路，但 AgentLoom 提供了专门的"循环"和"迭代"容器节点来支持需要重复执行的场景。这些容器节点在内部管理循环逻辑，不会破坏工作流的 DAG 结构。

用更直白的话说：工作流就像一条单行道的流水线，数据从起点出发，经过一个个处理环节，最终到达终点产出结果。每个环节可以有多个并行路径，也可以有条件分支，但不会走回头路。

---

## 工作流能做什么

工作流的本质是"编排 AI 能力"。通过将不同功能的节点组合起来，你可以构建各种各样的 AI 自动化方案。以下是一些典型的应用方向：

### 多 Agent 协作

将复杂任务拆解为多个子任务，由不同的 Agent 分别处理：

- 一个 Agent 负责收集信息
- 另一个 Agent 负责分析数据
- 第三个 Agent 负责撰写报告

这种分工方式让每个 Agent 可以专注于自己擅长的部分，整体效果优于让单一 Agent 处理所有事情。

### 数据处理流水线

构建从数据采集到结果输出的完整流水线：

- 通过 HTTP 请求从外部 API 获取数据
- 用输入预处理器清洗和格式化数据
- 用 Agent 分析数据并生成洞察
- 最终以文本或 JSON 格式输出结果

### 自动化触发流程

配合触发器实现完全无人值守的自动化：

- 定时触发：每天早上自动运行，生成日报
- Webhook 触发：收到外部系统的通知时自动启动
- API 事件触发：监听 GitHub 等平台的事件（如 PR 提交时自动做代码审查）

### 条件分支与并行处理

工作流不只是简单的线性流程，还支持：

- 根据条件将数据导向不同的处理路径（条件分支节点）
- 多个 Agent 同时处理不同的任务（并行路径）
- 将多条并行路径的结果汇合（合并节点）
- 对数组中的每个元素逐一处理（迭代容器）

## 工作流的组成要素

一个完整的工作流由以下几个要素构成：

### 节点

节点是工作流的基本构建单元，每个节点负责完成一项具体操作。AgentLoom 提供了丰富的节点类型：

| 分类 | 主要节点 | 典型用途 |
|------|---------|---------|
| Agent 智能体 | LLM 模型、智能路由、Agent、Skill | AI 推理、模型选择、技能增强 |
| 工具 | HTTP 请求、代码执行、MCP 工具、沙箱、输入预处理器、工作区 | 外部集成、代码运行、数据转换 |
| 触发器 | 手动、定时、Webhook、API 事件 | 定义工作流的启动方式 |
| 知识与记忆 | 知识库、Memory | 文档检索、长期记忆 |
| 输出 | Text Output、JSON Output | 定义最终输出结果 |
| 流程控制 | 条件、循环、迭代、合并、可复用块 | 控制执行逻辑和数据流向 |

### 连线（边）

连线定义了节点之间的关系，包括数据传递和执行顺序。连线从一个节点的输出端口连接到另一个节点的输入端口。

### 端口

端口是节点上用于连接的接口点，每个端口有明确的数据类型。系统会自动检查连线两端的类型兼容性。

### 输入参数

工作流可以定义输入参数，让每次运行时可以接收不同的外部数据。支持表单、对话和混合三种输入收集方式。

### 版本

工作流支持版本管理，可以保存快照、发布正式版本、查看历史和回滚。

## 典型使用场景

### 场景一：每日竞品分析

一家 SaaS 公司需要每天早上汇总竞品动态。

**工作流设计**：
1. 定时触发器 -- 每天早上 8 点自动启动
2. 信息采集 Agent -- 收集指定竞品的最新动态
3. 趋势分析 Agent -- 分析市场趋势和竞争态势
4. 文本输出 -- 生成结构化分析报告

**效果**：团队每天一上班就能看到最新的竞品分析报告，无需人工收集和整理。

### 场景二：客户反馈自动分类

产品运营团队收到大量用户反馈，需要及时分类和处理。

**工作流设计**：
1. Webhook 触发器 -- 客服系统提交反馈时自动触发
2. 反馈分类 Agent -- 自动进行情感分析和主题分类
3. 条件分支 -- 根据分类结果导向不同路径
4. JSON 输出 -- 输出结构化的分类结果

**效果**：每条用户反馈都能被即时分类，产品团队可以快速了解用户关注的焦点。

### 场景三：技术博客创作

技术团队需要定期产出高质量的博客文章。

**工作流设计**：
1. 手动触发 -- 输入博客主题
2. 选题 Agent -- 确定写作方向和大纲
3. 研究 Agent -- 收集技术素材和参考资料
4. 写作 Agent -- 撰写文章初稿
5. 审校 Agent -- 润色终稿

**效果**：将内容创作从零散的人工操作变为结构化的流水线，大幅提高产出效率。

### 场景四：多维度代码审查

开发团队希望在代码合并前进行全面的自动化审查。

**工作流设计**：
1. API 事件触发 -- 监听 GitHub PR 提交事件
2. 代码输入处理 Agent -- 提取代码信息
3. 安全审查 Agent、性能审查 Agent、规范审查 Agent -- 三个 Agent 并行审查
4. 汇总 Agent -- 合并所有审查结果，生成综合报告

**效果**：每次提交 PR 都能自动获得多维度的代码审查报告，提升代码质量。

### 场景五：数据报表自动生成

运营团队需要定期产出数据分析报告。

**工作流设计**：
1. 定时触发器 -- 按周/月自动运行
2. 数据源 Agent -- 从数据源提取关键指标
3. 分析 Agent -- 进行趋势分析和异常检测
4. 图表描述生成 -- 产出图表建议和描述
5. 文本输出 -- 输出完整的数据分析报告

**效果**：报表生成从耗时数小时的人工操作变为全自动流程。

## 工作流的生命周期

### 创建

通过以下方式创建工作流：
- **空白创建**：从零开始，在空画布上搭建
- **从模板创建**：基于预置模板开始，预填好基本结构后调整
- **从分享链接创建**：复制他人分享的工作流
- **从市场安装**：从工作流市场安装社区方案
- **从文件导入**：导入 `.agentloom-workflow.json` 文件

### 编辑

在画布编辑器中自由编辑节点、连线和配置。编辑过程中系统会自动保存。

### 测试

通过"运行"按钮手动触发执行，验证工作流的正确性。可以在执行调试页面检查每个节点的输入输出。

### 发布

验证通过后，将工作流发布为正式版本。发布后工作流可以被触发器自动运行、被分享给他人。

### 运维

- 查看执行历史和统计
- 根据反馈调整节点配置
- 发布新版本更新
- 不再需要时归档
