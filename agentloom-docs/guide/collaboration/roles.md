# 角色与权限

AgentLoom 提供了基于角色的访问控制（RBAC），通过 5 种预设角色来管理组织成员的权限。本文详细介绍每种角色的定位和权限范围。

## 角色概览

AgentLoom 中的 5 种角色按权限从高到低排列：

| 角色 | 英文标识 | 定位 | 适合的人员 |
|------|---------|------|-----------|
| 所有者 | Owner | 组织的最高管理者 | 团队负责人、公司管理层 |
| 管理员 | Admin | 组织的日常管理者 | 技术主管、运维负责人 |
| 创建者 | Creator | 资源的构建者 | 工作流开发者、AI 工程师 |
| 操作者 | Operator | 日常操作执行者 | 运营人员、一线使用者 |
| 查看者 | Viewer | 只读访问者 | 领导层、外部审计人员 |

## 所有者（Owner）

所有者是组织的最高权限角色，拥有组织内所有功能的完全控制权。

### 核心权限

- 管理组织设置（名称、描述、配置等）
- 管理所有成员的角色，包括提升或降级为任何角色
- 转让组织所有权
- 管理资源配额和治理策略
- 查看监控仪表板和审计日志
- 管理私有部署配置
- 执行所有管理员、创建者、操作者和查看者可以执行的操作

### 特殊说明

- 每个组织有且仅有一个所有者
- 组织创建者自动成为所有者
- 所有者角色只能通过转让变更
- 所有者不能被其他人移除出组织

## 管理员（Admin）

管理员负责组织的日常管理工作，权限仅次于所有者。

### 核心权限

- 邀请新成员加入组织
- 管理除所有者外的其他成员角色
- 移除组织成员
- 管理 MCP 工具配置（连接、导入、停用）
- 管理 API Token
- 管理知识库和文档
- 查看监控仪表板和审计日志
- 管理资源配额和治理策略
- 管理私有部署配置
- 执行所有创建者、操作者和查看者可以执行的操作

### 适用场景

- 技术团队的主管或架构师
- 负责平台配置和维护的运维人员
- 需要管理团队但不需要最高权限的负责人

## 创建者（Creator）

创建者是内容的主要构建者，可以创建和管理各种资源。

### 核心权限

- 创建、编辑、删除工作流
- 创建、编辑知识库和上传文档
- 创建、编辑、归档技能
- 创建触发器
- 执行工作流
- 发布工作流到市场
- 管理 API Token
- 从市场安装工作流和插件
- 查看执行历史和触发器历史

### 适用场景

- 工作流的设计和开发人员
- AI 应用的构建者
- 负责创建和维护自动化流程的工程师

## 操作者（Operator）

操作者是日常使用者，可以执行已有的工作流和管理基本资源。

### 核心权限

- 执行工作流
- 上传文档到知识库
- 从市场安装工作流和插件
- 查看工作流、Agent、知识库等资源
- 查看执行历史
- 管理自己的通知和偏好设置

### 适用场景

- 日常使用工作流完成任务的运营人员
- 需要执行但不需要创建工作流的一线使用者
- 客服团队成员

## 查看者（Viewer）

查看者是只读角色，可以浏览组织内的资源但不能进行修改。

### 核心权限

- 查看工作流列表和详情
- 查看 Agent 列表和详情
- 查看知识库列表和文档
- 查看执行历史
- 查看触发器列表和历史
- 查看市场中的工作流和插件
- 管理自己的通知和偏好设置

### 适用场景

- 需要了解团队工作流运行情况的管理层
- 外部审计或合规检查人员
- 新加入团队的成员（在获得更高权限之前）

## 权限管理建议

### 遵循最小权限原则

给每个成员分配能够满足其工作需要的最低角色。例如，如果一个成员只需要执行工作流和查看结果，给他分配操作者角色就够了，不需要创建者权限。

### 限制管理员数量

管理员权限较高，建议只给真正需要管理组织的人分配管理员角色。一般来说，一个中等规模的团队有 1-2 个管理员就足够了。

### 新成员从低权限开始

新加入的成员建议先分配查看者或操作者角色，在熟悉平台和了解团队规范后再考虑提升权限。

### 定期检查权限

定期检查成员列表和角色分配，确保没有不再需要高权限的成员保留着过高的角色。
