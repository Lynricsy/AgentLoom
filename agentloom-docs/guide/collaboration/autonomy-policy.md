# 组织自治策略

组织自治策略为组织内所有 Agent 节点设定自治模式的上限：节点的自治模式高于上限时，运行时按上限执行，发布时被拒绝。本页说明如何查看与调整上限，以及收紧上限时如何批量降级已有节点。

前提：

- 你在当前组织的角色是 owner。其他角色打开页面看到「无权访问组织自治策略」；admin 也不例外。
- 当前账号已归属一个组织，否则页面显示「无法确定当前组织」。

## 自治模式

从严格到宽松依次为：

| 模式 | 页面上的说明 |
| --- | --- |
| 手动确认 | 缺失输入必须由人工确认后再继续执行，不做自动推断。 |
| 规则补全 | 仅按白名单字段进行规则补全，未命中时再走兜底策略。 |
| LLM 建议 | LLM 可以给出建议，但建议可回退，不构成强承诺，仍可随时撤销或修改。 |

- 组织从未保存过策略时，上限为「LLM 建议」，即不限制。
- 节点没有设置自治模式时按最宽松的「LLM 建议」处理，因此上限设为「规则补全」或「手动确认」后，这类节点都会被计为超出上限。工作流画布的节点配置面板不提供自治模式选项，节点的自治模式只能来自节点数据中的 `autonomyMode` 字段（例如导入的工作流文件），收紧上限后用下文的「批量降级」统一写入。
- 旧版取值会先换算再比较：`FIXED` 按「手动确认」，`LLM_DECIDE` 与 `FULL_AUTO` 按「LLM 建议」。

## 查看当前上限

1. 点击侧边栏底部的「设置」，在「安全」分组中点击「自治策略」（路径 `/settings/security/autonomy-policy`）。

   页面标题为「组织自治策略」，标注「仅 owner 可访问」。「当前组织策略」卡片写明「当前自治上限为 …。」以及「组织 ID」「版本」「更新人」「更新时间」；「当前超上限工作流」「当前超上限节点」两个数字统计现有工作流中超出上限的工作流与节点。

## 放宽上限

1. 在「调整自治上限」卡片的「目标自治上限」下拉框中，选择比当前更宽松的模式。

   右侧显示所选模式的说明，按钮为「保存策略」。

2. 点击「保存策略」。

   页面提示「组织自治策略已更新」「当前自治上限已更新为 …。」，「当前组织策略」中的「版本」加一。

## 收紧上限

选择比当前更严格的模式时，页面出现提示「这次变更会收紧组织自治上限……」，有两种做法。

### 只更新上限

1. 点击「仅更新策略」。

   页面提示「组织自治策略已更新」。现有节点的配置不变，但运行时按新上限执行；含超上限节点的工作流再次发布时会被拒绝，直到把节点降到上限以内。

### 先预览，再批量降级现有节点

1. 点击「预览批量降级影响」。

   页面提示「已生成降级预览」「发现 N 个节点可能需要降级。」，下方出现「批量降级预览」卡片：「预估受影响工作流」「预估受影响节点」两个数字，以及每个受影响节点的名称、所属工作流、「当前」「规范值」「将降级为」三个标签和原因说明。没有节点受影响时显示「当前预览没有发现需要批量降级的节点。」

2. 核对列表后，点击「确认批量降级并更新策略」。

   页面提示「已确认批量降级」「已将组织自治上限更新为 …，并处理 N 个节点。」，预览卡片消失，「当前超上限节点」随之减少。

预览之后再改动下拉框，「确认批量降级并更新策略」按钮消失，需要重新预览。

## 上限在哪里生效

- **运行时**：Agent 节点运行前，服务端读取组织上限，把节点的自治模式压到上限以内再执行。
- **发布时**：发布含超上限节点的工作流返回 `workflow-publish-autonomy-cap` 错误，错误中逐个列出节点、当前模式与应降级到的模式。
- **优化建议**：收紧上限时，尚未处理、且建议的自治模式超出新上限的自治升级建议被标记为已阻断。
- **审计**：每次更新策略都写入审计日志，在「设置」→「审计日志」中查看。
