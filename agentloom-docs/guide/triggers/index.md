# 触发器与自动化

触发器让一个已发布的工作流在没有人点击「运行」的情况下启动。本页说明三种触发器的区别，以及创建、启停、查看历史与删除触发器的通用操作；每种触发器的配置见各自页面。

| 触发器 | 由什么启动 | 启动时的输入参数 | 页面 |
| --- | --- | --- | --- |
| Cron 定时器 | 服务端按 Cron 表达式与时区定时启动 | 无 | [定时触发](/guide/triggers/cron) |
| Webhook | 外部系统向该触发器独有的 URL 发送 `POST` | 请求体 JSON 的顶层字段；GitHub 验证模式外加 `_eventSource`、`_eventType`、`_deliveryId` | [Webhook 触发](/guide/triggers/webhook) |
| API Event | 你的服务向 `POST /api/v1/api-events` 发送事件，组织内所有匹配的触发器各启动一次 | 事件 `data` 的字段，外加 `_eventSource`、`_eventType` | [API 事件触发](/guide/triggers/api-event) |

工作流定义了 [输入参数](/guide/workflows/input-parameters) 时，触发器启动只保留已声明的字段，其余字段（包括上表中以 `_` 开头的字段）被丢弃；缺少必填字段时启动失败。

画布上的 [触发器节点](/guide/nodes/trigger)（Manual Trigger、Schedule、Webhook、API Event）只是工作流的起点，负责把启动参数从「触发数据」端口交给下游；它们的配置不会创建定时任务或入口地址。工作流实际何时被自动启动，只由本页所述「触发器」面板中的触发器决定。

前提：

- 工作流已发布。未发布时「添加触发器」按钮不可用，面板显示「触发器仅能绑定到已发布的工作流版本。请先发布当前工作流，再启用自动调度入口。」发布方法见 [版本管理](/guide/workflows/versions)。
- 创建、编辑、启停、删除触发器需要 owner、admin 或 creator 角色；operator 与 viewer 只能查看触发器与历史。
- 每个工作流最多 10 个触发器（三种类型合计），超出时返回 409 `trigger-limit-exceeded`。

## 打开触发器面板

1. 打开工作流画布，点击顶部工具栏的「触发器」。

   右侧出现「工作流设置」面板并停在「触发器」标签，标题为「触发器管理」，列出当前工作流的全部触发器。没有触发器时显示「未配置触发器」。

## 创建触发器

1. 在「触发器管理」中点击「添加触发器」。

   弹出「创建触发器」对话框，显示三种类型：「Cron 定时器」「Webhook」「API Event」。

2. 点击一种类型，按对应页面填写配置。所有类型都有「触发器名称」（必填，最长 255 个字符）、「描述」（最长 2000 个字符）与「启用触发器」开关（默认开启）。选错类型时点击「重新选择」返回。
3. 点击「创建触发器」。

   页面提示「触发器已创建」，列表中出现该触发器的卡片。Webhook 触发器会额外显示「保存 Webhook 凭证」，见 [Webhook 触发](/guide/triggers/webhook)。

## 启用或停用触发器

1. 在触发器卡片右上方切换开关。

   页面提示「触发器已启用」或「触发器已停用」，卡片状态随之显示「已启用」或「已停用」，切换立即生效：

   - 停用的 Cron 触发器不再排程，卡片「下次执行」显示「—」。
   - 停用的 Webhook 触发器对新请求返回 404 `trigger-not-found`。
   - 停用的 API Event 触发器不参与事件匹配。

## 编辑触发器

1. 在触发器卡片上点击「编辑」，修改后点击「保存更改」。

   页面提示「触发器已更新」。触发器类型创建后不能修改；修改在下次调度或下次请求时生效。Webhook 触发器的 Token 与 Secret 不随编辑改变。

## 查看触发历史

1. 在触发器卡片上点击「历史记录」。

   弹出「触发历史记录」，按时间倒序每页 20 条。每条记录显示状态、时间、记录 ID 与执行 ID，失败时显示错误信息；有执行 ID 时点击「查看执行」跳转到该次执行的详情页。可以按状态筛选：

   | 状态 | 含义 |
   | --- | --- |
   | 成功 | 已创建一次工作流执行。执行本身之后是否成功，在执行详情中查看 |
   | 失败 | 创建执行时出错，例如启动参数未通过工作流输入参数校验 |
   | 跳过 | 到点时触发器已停用（Cron）；GitHub 验证模式下的 `ping` 事件或重复投递（Webhook） |
   | 签名失败 | Webhook 请求未通过签名或时间戳校验 |
   | IP 被拒 | Webhook 请求来源不在 IP 白名单中 |

卡片上的「最近触发」「下次执行」「触发次数」三项随每次触发更新；「下次执行」只对 Cron 触发器有值。

## 删除触发器

1. 在触发器卡片上点击「删除」，在浏览器确认框「确认删除触发器「…」吗？」中确认。

   页面提示「触发器已删除」。删除不可撤销；Webhook 触发器的 URL 随之失效，重新创建会得到新的 Token。
