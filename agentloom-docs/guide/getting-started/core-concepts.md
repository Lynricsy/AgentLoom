# 核心概念

> 本页回答：工作流、Agent、节点、端口、执行与版本分别是什么，它们之间是什么关系？

## 工作流

工作流是画布上的一张有向图：节点表示一个步骤，连线表示数据或执行顺序如何从一个步骤传到下一个步骤。工作流由触发器或「运行」按钮启动，同一个工作流可以反复运行，每次运行的输入可以不同。

工作流有三种状态：草稿、已发布、已归档。新建的工作流是草稿；发布会把当前画布或某个已保存的版本定为正式版本；归档用于停用不再需要的工作流。

## Agent

Agent 是一个可以独立完成推理任务的智能体。它的能力不在工作流里配置，而是在它自己的 Agent 画布上配置：画布中心是自动创建的 Agent Main 节点，其他节点通过端口为它提供模型、系统提示词、工具、知识库、记忆、技能、沙箱和子 Agent。

Agent 发布后有三种用法：

- 在 Agent 页面直接与它对话，见 [与 Agent 对话](/guide/agents/conversations)。
- 在工作流中用 [Agent 节点](/guide/nodes/agent) 调用它，见 [在工作流中使用 Agent](/guide/agents/in-workflows)。
- 让外部系统通过 Agent API 调用它，见 [通过 API 调用 Agent](/guide/agents/api-access)。

Agent 有两种运行形态。「有沙箱」的 Agent 运行在隔离的沙箱中，带工作区、终端和内置文件工具；「无沙箱」的 Agent 不提供文件与终端工具，只做推理和资源编排。运行形态在创建时选择，见 [创建 Agent](/guide/agents/creating)。

## 节点与端口

节点是画布上的一个功能单元，例如调用 Agent、发送 HTTP 请求、判断条件、输出结果。节点左侧是输入端口，右侧是输出端口。每个端口有数据类型（如 `text`、`json`、`model`、`tool`），只有类型兼容的端口才能连线。

端口分两类：

- **数据端口**：传递文本、JSON、模型配置、工具描述等数据。
- **执行流端口**（类型 `exec`，在节点上不显示名称）：只表示先后顺序，上游完成后才触发下游。

一个节点在它所有输入连线的上游都结束后才会执行；没有任何输入连线的节点在执行开始时就会被调度。端口类型与兼容规则见 [什么是 AgentLoom](/guide/getting-started/)，每个节点的端口见 [节点参考](/guide/nodes/)。

## 执行与步骤

一次运行称为一次执行，执行中每个节点的运行称为一个步骤。执行的状态有等待中、执行中、已暂停、已完成、失败、已取消；步骤还可能处于排队中、已跳过（例如所在条件分支未命中）或等待干预（需要人工确认后继续）。执行过程中，节点状态和 Agent 的流式输出会实时推送到画布。查看与排查方法见 [运行与监控](/guide/workflows/running) 与 [调试工作流](/guide/workflows/debugging)。

## 版本

版本是画布在某一时刻的快照。编辑时可以随时保存快照（工作流工具栏「保存快照」，Agent 工具栏「保存版本」），发布时可以发布当前编辑稿或某个已保存的版本。版本历史可以在工具栏的「历史记录」中查看。见 [版本管理](/guide/workflows/versions)。

## 资源

LLM 模型配置、MCP 服务、技能、知识库、记忆实例、工作区、沙箱和插件属于资源，在侧边栏「资源」分组中创建和管理。节点只保存对资源的引用，所以同一份模型配置或知识库可以被多个 Agent 与工作流共用。
