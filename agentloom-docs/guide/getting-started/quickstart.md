# 快速开始

本教程带你创建一个 Agent，再用一个工作流调用它，最后在画布上看到 Agent 的回复。完成后你会得到：一个已发布的 Agent「入门助手」，和一个由 Text → Agent → Text Output 三个节点组成、运行状态为「已完成」的工作流。

开始前需要准备：

- 一个可以访问 [https://agentloom.ling.plus/](https://agentloom.ling.plus/) 的浏览器。
- 一个 LLM 服务商的 API Key（创建模型配置时填写，服务端加密保存）。可选的服务商以「Provider」下拉列表为准。

## 第 1 步：注册并创建组织

1. 打开 `https://agentloom.ling.plus/register`，填写「邮箱」「密码」（至少 8 个字符，含大写、小写和数字）与「确认密码」，点击「注册」。已有账号时在登录页点击「登录」即可，也可以用「使用 Google 继续」或「使用 GitHub 继续」登录。
2. 注册后进入初始化向导，标题为「欢迎使用 AgentLoom」。按向导进入「创建组织」步骤，填写「组织名称」后点击「创建组织」，再完成「偏好设置」步骤。

完成后进入 Studio，左侧侧边栏显示「构建」「探索」「资源」「运维」四组入口。

## 第 2 步：创建 Agent

1. 在侧边栏「构建」组点击「Agent」，在页面右上角点击「新建」。
2. 在「新建 Agent」对话框中，「名称」填写 `入门助手`；「运行形态」选择「无沙箱」（不需要沙箱运行时，适合纯推理）；点击「创建」。

页面跳转到这个 Agent 的画布，画布上已有一个 Agent Main 节点，节点面板中它被标记为「自动创建」。

## 第 3 步：为 Agent 连接模型和系统提示词

1. 从左侧节点面板的「模型」分组把「LLM 模型」拖到画布上，点击它打开配置面板「LLM 模型配置」。
2. 切换到「创建新配置」，填写「配置名称」，选择「Provider」与「模型」，在「API Key」中填入你的 API Key，点击「保存并应用新配置」。右下角提示「LLM 配置已保存」。
3. 从 LLM 模型节点的「模型」端口拖一条线到 Agent Main 的「模型」端口。
4. 从「提示」分组把「Text」拖到画布上，点击它，在文本框中输入：

   ```text
   你是一位友好的助手。请用简洁明了的语言回答用户的问题。
   ```

5. 从 Text 节点的「文本」端口拖一条线到 Agent Main 的「系统提示词」端口。

画布上三个节点之间出现两条连线。如果某条线拖不上，说明两端端口类型不兼容，检查是否连到了正确的端口。

## 第 4 步：发布 Agent

1. 点击画布顶部工具栏的「保存画布」，按钮短暂显示「保存中…」后变为不可点击。
2. 点击「发布」，在「发布 Agent」对话框的「发布来源」中选择「当前编辑稿」，点击「发布」。

右下角提示「发布成功」，工具栏左侧的状态徽章从「草稿」变为「已发布」。只有已发布的 Agent 才能在工作流中选择。

## 第 5 步：创建工作流

1. 在侧边栏「构建」组点击「工作流」，在页面右上角点击「新建」。
2. 在「新建工作流」对话框中，「名称」填写 `我的第一个工作流`，点击「创建」。

页面跳转到空白的工作流画布，左侧是节点面板，按 Agent、Tool、Trigger、Knowledge、Memory、Output、Control 分组。

## 第 6 步：添加并连接节点

1. 从「Output」分组把「Text」拖到画布左侧，点击它，在文本框中输入 `请用三句话介绍你自己。`
2. 从「Agent」分组把「Agent」拖到画布中间。点击它，在配置面板「选择 Agent」列表中点击「入门助手」（列表项带「无沙箱」标记）；「版本」保持「使用最新发布版本」。
3. 从「Output」分组把「Text Output」拖到画布右侧。
4. 连线：Text 的「文本」端口 → Agent 的「文本」端口；Agent 的「回复」端口 → Text Output 的「文本」端口。

画布底部状态栏显示「3 节点」「2 连接」，并在自动保存后显示「已保存」。

## 第 7 步：运行并查看结果

1. 点击画布顶部工具栏右侧的「运行」。弹出「启动工作流」对话框，提示「当前工作流没有需要填写的字段，确认后将直接启动执行。」
2. 点击对话框中的「运行」。工具栏按钮变为「执行中」，等待底部状态栏的执行状态变为「已完成」。
3. 点击 Agent 节点，在配置面板中切换到「输出」标签。

「实时执行」区域显示节点状态「已完成」，下方的输出是 Agent 用三句话做的自我介绍，这也是 Text Output 节点记录的内容。如果状态为「失败」，同一区域会显示错误信息；排查方法见 [调试工作流](/guide/workflows/debugging)。
