# Agent 记忆

本文介绍 Agent 的记忆系统，包括记忆的工作原理、如何查看记忆图谱、以及如何管理记忆条目。

## 什么是 Agent 记忆

Agent 记忆是一套基于知识图谱的长期记忆系统。它允许 Agent 在多次对话之间保留和利用关键信息——就像一个人可以记住之前的谈话内容并在将来的交流中引用这些记忆。

### 为什么需要记忆

默认情况下，每次对话中 Agent 只能看到当前对话的历史消息。如果你在昨天告诉 Agent "我们的项目使用 TypeScript + React 技术栈"，今天开始新对话时 Agent 并不知道这件事。

记忆系统解决了这个问题。启用记忆后：

- Agent 会在对话过程中自动提取重要信息并存入记忆图谱。
- 在新的对话开始时，Agent 可以检索相关记忆来理解上下文。
- 随着交互的增加，Agent 对你、你的项目和你的偏好的理解会越来越深入。

### 记忆存储了什么

Agent 记忆以知识图谱的形式存储，主要包括：

- **事实信息**：你提到的具体事实，如项目名称、技术选型、团队成员等。
- **偏好设置**：你表达过的偏好，如代码风格、命名规范、工作习惯等。
- **决策记录**：重要的决策及其原因，如"选择 PostgreSQL 是因为需要复杂查询支持"。
- **任务上下文**：正在进行的任务的关键信息，如项目目标、进度、待解决的问题等。
- **关系和关联**：不同信息之间的关联关系，如"用户的项目"使用了"某技术栈"，该技术栈包含"某些具体工具"。

## 为 Agent 配置记忆

### 创建 Memory 实例

在使用记忆功能之前，你需要先创建一个 Memory 实例。

> 界面提示：在左侧导航栏中找到 "Memory" 菜单项，进入 Memory 实例列表页面。点击 "创建 Memory" 按钮。

创建时需要填写：

- **名称**：为这个记忆实例取一个有意义的名字，例如"项目知识记忆"、"用户偏好记忆"。
- **描述**（可选）：说明这个记忆实例的用途。

### 将 Memory 绑定到 Agent

在 Agent 配置画布中：

1. 从左侧节点面板拖拽一个 Memory 节点到画布上。
2. 在 Memory 节点的配置面板中，选择已创建的 Memory 实例。
3. 设置角色为 `primary`（可读写）或 `readonly`（只读）。
4. 将 Memory 节点的"记忆"输出端口连接到 Agent Main 节点的"记忆"输入端口。

一个 Agent 可以绑定多个 Memory 实例。多个 Memory 同时绑定时，可以设置融合优先级来控制不同记忆来源的权重。

### Memory 角色

| 角色 | 说明 |
|------|------|
| primary | 主记忆。Agent 既可以从中读取记忆，也可以向其写入新记忆。每个 Agent 通常有一个主记忆。 |
| readonly | 只读记忆。Agent 只能从中读取记忆，不能写入。适合多个 Agent 共享同一份知识但不互相干扰的场景。 |

## 记忆如何帮助 Agent

### 对话中的记忆工作流

1. **消息到达**：当你发送消息给 Agent 时，Agent 首先会检索记忆图谱中与当前话题相关的记忆条目。
2. **上下文增强**：检索到的记忆会被注入到 Agent 的推理上下文中，帮助 Agent 理解背景信息。
3. **生成回复**：Agent 结合当前消息、对话历史和记忆内容进行推理并生成回复。
4. **记忆更新**：对话结束后，Agent 会分析对话中产生的新信息，将有价值的内容提取并存入记忆图谱。

### 典型应用场景

**项目长期协作**

当你与 Agent 就一个项目持续对话数天甚至数周时，Agent 的记忆会逐渐积累：

- 项目的架构和设计决策。
- 你提到的 Bug 和它们的修复方案。
- 代码风格和团队约定。
- 项目进展和待办事项。

这样即使你开始新对话，Agent 也不需要从头了解项目背景。

**个性化偏好记忆**

Agent 会记住你表达过的偏好：

- "我喜欢用函数式组件而不是类组件"
- "请用中文注释代码"
- "回复不需要太长的解释，简洁为主"

后续的对话中 Agent 会自动应用这些偏好，无需你反复说明。

**知识积累与传承**

如果一个 Memory 实例被设置为 readonly 并绑定到多个 Agent，这些 Agent 可以共享同一份知识。例如，一个团队的"编码规范"记忆可以被所有 Agent 只读访问。

## 查看记忆图谱

### 进入记忆详情页

> 界面提示：从 Memory 实例列表页面点击某个实例，进入 Memory 实例详情页。

详情页包含以下主要区域：

### 图谱可视化

记忆图谱以交互式的节点-关系图呈现。每个节点代表一个记忆实体（如人物、概念、事件），节点之间的连线代表它们的关系。

- **节点**：不同颜色和大小的圆点，颜色表示实体类型，大小表示重要程度或关联密度。
- **关系线**：连接两个节点的线段，线上标注关系描述（如"使用"、"属于"、"创建于"等）。
- **布局**：图谱使用力导向布局（d3-force）自动排列节点位置，关联紧密的节点会聚集在一起。

### 图谱操作

| 操作 | 说明 |
|------|------|
| 缩放 | 使用鼠标滚轮或触控板缩放图谱视图 |
| 平移 | 按住鼠标拖拽来移动视图 |
| 选择节点 | 单击节点查看该记忆条目的详细信息 |
| 查看关系 | 鼠标悬停在连线上查看关系描述 |

### 记忆时间线

除了图谱视图，你还可以查看记忆的时间线，了解记忆是何时创建和更新的。

## 管理记忆条目

### 查看记忆详情

在图谱中选中一个节点后，详情面板会显示：

- 记忆内容（文本描述）
- 创建时间
- 最近更新时间
- 来源对话
- 关联的其他记忆节点

### 审计记录

Memory 实例详情页提供审计记录功能，你可以查看：

- 记忆的创建和修改历史
- 哪些对话触发了记忆的更新
- 记忆变更的时间线

### Memory 实例设置

> 界面提示：在 Memory 实例详情页中，可以找到设置入口来管理实例配置。

在设置页面你可以修改：

- Memory 实例名称和描述
- 其他元数据配置

## 多 Agent 共享记忆

### 共享场景

多个 Agent 可以绑定同一个 Memory 实例。常见的使用模式包括：

**主-从模式**

- 一个 Agent 绑定 Memory 为 `primary`（可读写）。
- 其他 Agent 绑定同一个 Memory 为 `readonly`（只读）。
- 主 Agent 负责积累知识，其他 Agent 可以利用但不会修改。

**对等共享模式**

- 多个 Agent 同时以 `primary` 角色绑定同一个 Memory。
- 每个 Agent 都可以读写记忆。
- 适合需要多个 Agent 协作积累知识的场景，但需注意可能的冲突。

### 融合优先级

当一个 Agent 绑定了多个 Memory 实例时，可以为每个 Memory 设置融合优先级（默认为 1）。优先级更高的 Memory 中的记忆在检索时会获得更高的权重。

例如：

- "项目专属记忆"优先级设为 2
- "通用编码规范记忆"优先级设为 1

这样当两个记忆源的信息存在冲突时，项目专属记忆的内容会被优先采纳。

## 最佳实践

1. **及时创建 Memory**：在开始一个新项目或新主题的协作前，为 Agent 创建并绑定一个专用的 Memory 实例。
2. **合理划分 Memory**：不同类型的知识使用不同的 Memory 实例。例如项目知识和个人偏好分开存储。
3. **定期检查**：通过图谱可视化定期检查 Agent 存储了哪些记忆，确保记忆内容准确且有价值。
4. **善用只读角色**：将通用知识（如编码规范、团队约定）设为只读 Memory，让多个 Agent 共享但不能随意修改。
5. **注意 Memory 容量**：过多的记忆内容可能影响检索效率。如果发现 Agent 开始混淆不相关的信息，可以考虑清理或分拆 Memory。
