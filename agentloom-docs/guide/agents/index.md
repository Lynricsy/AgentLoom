# Agent 智能体

## 什么是 Agent

在 AgentLoom 中，Agent（智能体）是一个独立运行的 AI 助手。你可以把 Agent 想象成一个拥有特定技能、知识和工具的虚拟成员——你为它设定角色、配备工具、赋予知识，然后通过对话与它协作完成任务。

与简单的"提问-回答"不同，AgentLoom 中的 Agent 具备更强的能力：它可以调用外部工具、在沙箱中执行代码、检索知识库、记忆你之前的交流内容，甚至还可以将子任务委派给其他 Agent。

## Agent 与工作流的区别和联系

AgentLoom 平台上存在两个并行的核心概念：**Agent** 和 **工作流（Workflow）**。

### Agent：自由对话式协作

- Agent 以对话为核心交互方式，类似于你与一个 AI 助手的自然对话。
- 你可以随时发送新的指令，Agent 会根据上下文理解你的意图并做出回应。
- Agent 具备自主决策能力，能够根据任务需要，自行选择调用哪些工具、查阅哪些知识。
- 适合开放式、探索性、需要灵活应变的任务场景。

### 工作流：结构化流程编排

- 工作流通过可视化画布将多个节点组织为 DAG（有向无环图），按照预定义的步骤依次执行。
- 每个节点有明确的输入和输出，数据在节点间按设计好的路径流转。
- 适合重复性、可预测、需要标准化输出的任务场景。

### 两者的联系

Agent 和工作流并非完全割裂，它们之间存在一座"桥梁"：

- **Agent 可以作为工作流中的一个节点**：你可以在工作流画布上放置一个 Agent 节点，让已创建的独立 Agent 在工作流中执行特定步骤。这意味着你可以在结构化的流程中嵌入自由灵活的 AI 推理能力。
- **共享沙箱环境**：工作流中的沙箱节点可以被多个 Agent 节点共享，让它们在同一个代码执行环境中协作。
- **共享技能和工具**：工作流中的技能节点和工具节点都可以连接到 Agent 节点，扩展 Agent 在工作流中的能力边界。

## Agent 的核心能力

### 自然语言对话

Agent 支持多轮对话，能够理解上下文语境。你可以像与同事交流一样，用自然语言描述需求。Agent 会根据对话历史、系统提示词和你当前的输入进行推理和回复。

### 工具调用

你可以为 Agent 配备各种工具，Agent 在对话过程中会自主判断是否需要调用工具，以及调用哪些工具。例如：

- **MCP 工具**：通过 Model Context Protocol 连接的外部工具（搜索引擎、数据库查询、第三方 API 等）。
- **原生文件工具**：在沙箱中读写文件、编辑文件内容。
- **终端工具**：在沙箱中执行命令行操作。

### 代码沙箱

Agent 可以关联一个隔离的代码执行环境（沙箱）。在沙箱中，Agent 能够：

- 编写和运行代码。
- 操作文件系统（创建、读取、编辑、删除文件）。
- 执行终端命令。
- 安装依赖包。

沙箱环境是完全隔离的容器化运行时，不会影响你的本地环境。

### 知识库检索

Agent 可以绑定一个或多个知识库。当你提出问题时，Agent 会在知识库中检索相关文档，并将检索到的内容作为参考来生成更准确的回答。这是 RAG（检索增强生成）的典型应用。

### 长期记忆

Agent 拥有基于知识图谱的记忆系统。在对话过程中，Agent 会自动提取和存储关键信息（如你的偏好、项目背景、重要决策等）。在后续的对话中，Agent 可以回忆起这些信息，从而提供更加个性化和连贯的服务。

你还可以通过记忆管理页面查看和管理 Agent 存储的记忆内容。

### 技能增强

技能（Skill）是一组预定义的行为指令，可以注入到 Agent 的系统提示中。例如"代码审查"技能会让 Agent 遵循特定的代码审查流程和标准。AgentLoom 内置了 5 个常用技能：

- 代码审查（Code Review）
- 文档编写（Documentation）
- 测试生成（Test Generation）
- 代码重构（Refactoring）
- 调试排错（Debugging）

你也可以创建自定义技能来扩展 Agent 的能力边界。

### 子 Agent 委派

一个 Agent 可以注册多个子 Agent。当任务过于复杂或超出当前 Agent 的能力范围时，它可以将子任务委派给专门的子 Agent 处理。例如，一个"项目经理" Agent 可以将代码编写任务委派给"开发者" Agent，将设计任务委派给"设计师" Agent。

## 适用场景

### 适合使用 Agent 的场景

| 场景 | 说明 |
|------|------|
| 代码开发 | 让 Agent 在沙箱中编写、调试和测试代码 |
| 技术文档 | 让 Agent 阅读代码库并生成技术文档 |
| 数据分析 | 让 Agent 编写分析脚本并解读结果 |
| 知识问答 | 绑定知识库后，让 Agent 基于专属资料回答问题 |
| 项目协助 | 让 Agent 记忆项目上下文，持续提供个性化建议 |
| 探索性研究 | 自由对话式地探索新问题，Agent 灵活调用各种工具 |

### 适合使用工作流的场景

| 场景 | 说明 |
|------|------|
| 批量处理 | 每次按固定步骤处理同类任务 |
| 定时自动化 | 通过触发器定时运行一组标准化操作 |
| 多步骤编排 | 需要严格控制执行顺序和数据流向 |
| 团队协作模板 | 把最佳实践固化为可复用的工作流模板 |

## 快速入门

如果你是第一次使用 Agent，建议按以下步骤开始：

1. **创建一个 Agent** — 进入 Agent 管理页面，创建你的第一个 Agent，设置名称和系统提示词。详见 [创建 Agent](./creating.md)。
2. **开始对话** — 创建完成后，进入对话页面，发送你的第一条消息。详见 [与 Agent 对话](./conversations.md)。
3. **探索记忆** — 对话结束后，查看 Agent 的记忆图谱，了解 Agent 记住了什么。详见 [Agent 记忆](./memory.md)。
4. **在工作流中使用** — 当你需要将 Agent 能力嵌入到工作流中时，可以添加 Agent 节点。详见 [在工作流中使用 Agent](./in-workflows.md)。
