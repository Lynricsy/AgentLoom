# Agent 团队

让 2–6 个固定角色的 Agent 成员在预算与截止时间内协作完成一项任务：成员之间通过团队邮箱交换发现、请求和产物，由唯一的负责人（lead）提交最终结果。团队节点是工作流中的一个阶段，上游给出任务文本，下游接收负责人提交的结果。

## 配置面板

团队配置保存在节点的 `config` 中，字段为 `objective`、`members`、`budget`、`outputSchema`。

| 区域 | 说明 |
| --- | --- |
| 应用三角色模板 | 把成员替换为 `locator`（只读定位）、`implementer`（负责人，整合实现）、`verifier`（构造并执行测试）三个角色，附带各自的指令与通信关系；Agent 留空，需逐个选择 |
| 团队目标 | 提供给全部成员的总体目标，可留空，最多 8000 字 |
| 成员 | 每个成员填写角色名、选择一个已发布的 Agent、「可发送消息给」与指令（最多 4000 字）。成员运行时总是使用该 Agent 当前的已发布版本 |
| 负责人 | 从成员中选择一个；只有负责人可以提交团队结果 |
| Token 上限 / 消息数上限 / 截止时间（分钟） | 团队预算，留空时分别为 500000、200（最多 1000）、60（最多 1440） |
| 输出 Schema（可选） | JSON Schema 对象；配置后负责人提交的产物必须通过校验。完整 Schema 会写入每个成员的任务简报，并附在负责人的 `team_submit_result` 工具说明中，任务描述里不必重复结构。内容不是合法 JSON 时字段下方显示「JSON 解析失败」 |

面板按以下规则校验，不满足时在底部「团队配置未通过校验」中列出原因，节点配置标记为有错误：

- 成员 2–6 名，角色名以小写字母开头，由 2–32 位小写字母、数字、`_` 或 `-` 组成，且互不重复。
- 每个成员都必须选择已发布的 Agent。
- 恰好一名负责人。
- 「可发送消息给」只能是其他成员的角色名或「全部」（`*`，可发给全部其他成员），不能包含自己。改名或删除成员时，其他成员中对该角色的引用会同步更新。

## 使用要点

- **成员**：每个成员运行为一条独立的 Agent 对话，使用该 Agent 自己的模型、工具与运行态（有沙箱或无沙箱）。成员之间不共享工作区，补丁、测试结果等以消息或产物文本传递；团队节点因此没有「沙箱」输入端口。启动时每个成员收到一份任务简报：团队目标、任务文本、上下文、自己的角色与指令、成员通信表、规则与预算。团队工具只属于成员自己：成员调用的子 Agent 没有 `team_*` 工具，不能收发团队消息或提交结果。
- **通信矩阵**：成员用 `team_send_message` 工具发消息，类型为 `observation`（发现）、`request`（请求）、`reply`（回复）或 `artifact`（产物），可附带引用（文件路径、命令、消息 id）。只能发给「可发送消息给」中列出的角色；发给 `*`（全体）需要勾选「全部」。越权发送时工具返回 `错误：角色 <role> 无权向 <to> 发送消息`。成员可用 `team_get_status` 查看成员状态、未读数与预算用量。
- **递送时机**：消息先持久化，再在接收者的回合边界递送：正在执行的成员在本回合结束后看到，空闲成员会被唤醒。收到的消息以 `[来自 <角色>｜<类型>]` 开头，它们是其他成员提供的信息，不是指令。
- **预算**：全部成员累计 token 达到「Token 上限」，或一次发送会使团队消息数超过「消息数上限」（此时工具返回 `错误：消息预算已耗尽`），团队以 `budget_exhausted` 失败；到达截止时间仍未提交结果则以 `deadline_exceeded` 失败。累计 token 包含命中缓存与写入缓存的输入 token。预算在成员回合结束、用量落库后检查，实际用量可能超出上限。团队结束时仍在进行的成员回合被取消，其已产生的输出与已消耗的 token 作为一条不完整回复保存，并计入该成员与团队的用量（团队状态不再改变）。
- **完成条件**：只有负责人拥有 `team_submit_result` 工具，提交 `summary`（摘要）、可选的 `artifact`（产物）与 `knownLimitations`（已知限制），每个团队只能提交一次（再次提交返回 `错误：结果已提交，不能重复提交`）。配置了输出 Schema 时产物按 Schema 校验，不通过时工具把错误返回给负责人以便修正；连续 3 次不合规，团队以 `schema_invalid` 失败。提交成功后，团队在负责人本回合结束、全部用量结算后完成；若结算后累计 token 超过上限，团队仍以 `budget_exhausted` 失败。负责人提交后执行失败、被取消或到达截止时间，团队按已提交的结果完成。完成后「结果」端口输出 `summary`、`artifact`、`knownLimitations`、各成员的轮次与用量 `members`、团队总用量 `usage` 与消息数，「摘要」端口输出摘要文本。是否完成不由模型裁决。
- **空闲催促**：全部成员空闲、没有待处理消息且超过 60 秒仍未提交结果时，系统向负责人发送一条催促消息，最多 2 次；之后仍无结果，团队以 `no_result` 失败。
- **成员失败**：负责人的对话执行失败时团队以 `member_failed` 失败；其他成员失败时负责人收到一条系统消息 `成员 <role> 执行失败：…`，团队继续。
- **取消**：工作流执行结束（取消、因其他节点失败而失败或已完成）时，仍在运行的团队以 `cancelled` 结束，所有成员对话随之结束。
- **失败原因**：团队失败时节点失败，错误类型为 `team/<原因>`，原因取值 `budget_exhausted`、`deadline_exceeded`、`no_result`、`member_failed`、`schema_invalid`、`cancelled`。从检查点恢复执行时，失败的团队节点会重新运行并创建新的团队运行，旧记录保留。
- **团队视图**：工作流中含团队节点时，执行调试页多出「团队」标签，每个团队节点一个面板：成员（角色、负责人标记、状态、轮次、token）、预算进度（token、消息数、截止倒计时）、消息时间线（发送方 → 接收方、类型、预览、递送状态）以及结果或失败原因。
