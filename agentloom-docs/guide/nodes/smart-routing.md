# 智能路由

在多个候选模型之间按路由策略选出一个，并把选中的模型通过「选定模型」端口交给下游。候选模型来自连接到「模型 1」「模型 2」等端口的 [LLM 模型](/guide/nodes/llm-model) 节点。

## 使用要点

- 配置面板「智能路由配置」中的「路由策略」列表从服务端加载；registry 中声明的策略值见上方配置项表。所选策略需要额外参数时，面板会出现「策略参数」区域。
- 执行时节点先收集各候选端口连接的模型配置，再过滤掉健康监控判定为不可用的模型，然后交给所选策略决策；面板的「Provider 状态」区域显示各候选模型当前的健康状态（正常 / 降级 / 断路）。
- 过滤后没有可用候选时节点失败，错误类型为 `routing/no-eligible-candidate`；策略没有选出任何模型时节点失败（错误信息含 `未能选择模型`）。每次决策都会被记录，供历史类策略参考。
- 「LLM 路由」策略由路由模型挑选候选，路由模型按其提供商配置的 API 协议（OpenAI Chat、OpenAI Responses、Anthropic 等）调用。路由模型超时（策略参数 `timeoutMs`，单位毫秒，默认 10000）、请求失败、返回无效结果或配置有误时，节点按固定顺序回退：面板中「回退模型」选定的模型（须是候选之一）→ 策略参数中的回退规则 → 第一个候选。回退会记录在路由决策中：监控页「路由决策」标签页的对应行显示「回退：<原因>」徽标，悬停显示回退来源。
- 「KNN」「Memory Bank」策略参考相似历史任务的路由记忆。还没有任何路由记忆时（例如新环境），按模型基准评分选择；没有基准数据时选质量排名最高的候选。
- 「选定模型」端口输出的是选中的模型配置，与 LLM 模型节点的「模型」端口同类型，可连接到 Agent 画布中 Agent Main 的「模型」端口。
- Agent 画布上经智能路由连到 Agent Main 的模型，在与该 Agent 对话时和在工作流的 Agent 节点中运行时都会按路由策略选择；每次选择都记为一条路由决策，可在监控页「路由决策」标签页查看（对话的决策「路由节点」列显示 `conversation`，工作流 Agent 节点的决策显示该节点 ID）。
