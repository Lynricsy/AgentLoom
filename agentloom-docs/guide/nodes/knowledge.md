# 知识库节点

## 功能说明

知识库节点在工作流画布上引用一个向量知识库，并通过「知识库」输出端口提供 `knowledge` 类型的知识库引用。当前工作流画布没有可接收 `knowledge` 类型的输入端口，因此该输出不能连接到工作流中的 Agent 节点。

知识库底层使用 Qdrant 向量数据库进行语义检索，支持按相似度排序返回最相关的文档片段。

## 使用场景

- **企业知识问答**：将公司文档、产品手册、FAQ 等导入知识库，让 Agent 基于这些资料回答员工或客户的问题。
- **技术文档检索**：将 API 文档、设计文档导入知识库，Agent 在编写代码或回答技术问题时自动检索参考。
- **合规审查**：将法规、政策文档导入知识库，Agent 在审查内容时可以引用相关条款。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口 |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 知识库 | knowledge | 向量知识库引用；当前工作流画布中没有兼容的接收端口 |

## 配置项

### 知识库选择

在配置面板中选择要绑定的知识库。

> 界面提示：配置面板提供一个知识库下拉列表，显示当前组织中所有可用的知识库。每个知识库会显示名称和文档数量等基本信息。

| 配置 | 必需 | 说明 |
|------|------|------|
| Knowledge Base ID | 是 | 选择要绑定的知识库 |

### 前提条件

使用知识库节点前，你需要先在 AgentLoom 的知识库管理模块中：

1. 创建一个知识库。
2. 向知识库中导入文档（支持多种文档格式）。
3. 等待文档向量化处理完成。

## 如何让 Agent 使用知识库

知识库能力需要在 **Agent 配置画布**中绑定，而不是在工作流画布中连线：

1. 在 AgentLoom 的知识库管理模块中创建知识库、导入文档，并等待向量化完成。
2. 创建或编辑 Agent，在 Agent 配置画布中放置知识库节点并选择目标知识库。
3. 将知识库节点的「知识库」输出连接到 Agent Main 的「知识库」输入端口。
4. 保存并发布 Agent。
5. 在工作流中放置 **Agent** 节点并选择这个已发布的 Agent。该 Agent 会自带已绑定的知识库能力，无需也无法在工作流画布中再次连接知识库。

如需同时使用多个知识库，请在 Agent 配置画布中将多个知识库节点连接到 Agent Main 的「知识库」端口。详细操作参见[创建 Agent](../agents/creating.md)。

### 与工作流节点配合

工作流中的 Agent 节点仍可接收类型兼容的输入。例如，文本节点的「文本」输出可以连接到 Agent 的「文本」输入，技能节点的「Skill」输出可以连接到 Agent 的「Skills」输入。知识库检索能力则来自该 Agent 的配置。

## RAG 检索原理

### 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与 AI 生成结合的技术。其核心思路是：

1. **检索**：当 Agent 收到问题时，先在知识库中搜索与问题语义最相关的文档片段。
2. **增强**：将检索到的文档片段作为上下文注入到 Agent 的提示中。
3. **生成**：Agent 基于检索到的上下文生成回答，而不是仅依赖模型自身的训练数据。

### RAG 的优势

| 优势 | 说明 |
|------|------|
| 知识可控 | Agent 的回答基于你导入的文档，不会编造不存在的信息 |
| 实时更新 | 只要更新知识库中的文档，Agent 的回答就会相应更新 |
| 领域专注 | Agent 可以深入理解你的专属领域知识，而不是泛泛而谈 |
| 可追溯 | Agent 的回答有明确的文档来源，可以验证准确性 |

### 影响检索质量的因素

- **文档质量**：文档内容应准确、完整、结构清晰。
- **文档切分**：过长的文档会被切分为片段，切分的粒度影响检索精度。
- **问题表述**：用户提问的方式会影响检索结果。明确具体的问题比模糊的问题能获得更好的检索结果。

## 注意事项

1. **知识库需提前准备**：知识库节点本身不负责文档管理。你需要先在知识库管理页面创建知识库并导入文档。
2. **向量化延迟**：新导入的文档需要经过向量化处理才能被检索。大量文档的向量化可能需要一些时间。在文档处理完成前，检索结果可能不完整。
3. **检索质量**：RAG 的效果取决于知识库中文档的质量和检索参数配置。确保导入的文档内容准确、组织清晰。
4. **端口类型**：知识库节点输出 `knowledge` 类型。工作流画布中的 Agent 节点没有知识库输入端口，「上下文」端口是 `json` 类型，也不兼容该输出。
5. **绑定位置**：需要让 Agent 使用知识库时，请在 Agent 配置画布中连接知识库节点与 Agent Main 的「知识库」端口。
6. **知识库容量**：知识库的文档数量和总大小会影响检索性能。建议按主题划分知识库，避免将所有文档放入一个知识库。
