# 生成应用

用一句话描述业务需求，AgentLoom 会把它整理成应用规格（AppSpec），经过一组门禁验证后，生成一个终端用户不登录就能打开的公开应用。本页前半部分是操作步骤，后半部分「门禁与就绪状态」解释公开链接什么时候可用。

- 外部系统如何接入生成应用的公开接口，见[生成应用接入](/api/generated-apps)。
- 服务端的生成、门禁与公开运行实现，见[生成应用（服务端）](/dev/server/generated-apps)。

## 操作指南

### 前置条件

- 组织角色为 owner、admin 或 creator。operator 与 viewer 可以浏览列表和详情，但不能创建应用、运行生成或管理公开链接（`agentloom-server/src/modules/generated-app/generated-app.controller.ts` 中各端点的 `@Roles`）。
- 账号里至少有一个可用的对话模型（左侧导航「资源」组的「LLM 模型」中添加并启用），生成 AppSpec 要调用它；没有时创建按钮不可用。
- 至少有一个已发布的工作流或 Agent，应用的公开提交会执行它的已发布版本（见 [版本管理](/guide/workflows/versions)）。

### 1. 创建应用并运行生成

1. 在左侧导航「构建」组点击「生成应用」，进入 `/generated-apps`。
2. 在「一句话描述你要的应用」输入框中写需求，例如「一个问答页面：输入问题，调用知识库问答工作流返回答案与引用」。输入上限 4000 字符。
3. 「生成 AppSpec 的模型」选一个对话模型；保持「自动」时使用账号默认对话模型。
4. 「绑定目标」选一个已发布的工作流或 Agent；保持「自动」时由模型从最近更新的已发布工作流与 Agent（最多 20 个）中按需求选择。生成应用自己创建的包装工作流不出现在列表里。
5. 点击「创建并生成应用」。

应用创建后立即开始首次生成运行，提示「应用已创建，正在生成」。生成在后台排队执行：先由模型生成 AppSpec，再依次执行 Gate 0–7，通常需要几分钟。输入框下方的卡片显示这次运行的实时进度：

- 运行状态（「排队中」「运行中」「已通过」「失败」）、第几次运行与当前摘要；失败时另显示失败原因。
- 「已完成 N/8 个 Gate」与 Gate 0–7 各自的状态：已结束的 Gate 显示结果与摘要，正在执行的显示「运行中」，后面的显示「等待中」；运行因前面的 Gate 失败而结束时，其余 Gate 显示「未执行」。

进度每 3 秒自动刷新，离开页面不影响后台运行。点击卡片上的「进入详情」打开 `/generated-apps/<appId>`，详情页显示同一次运行的进度。

创建失败（例如所选绑定目标已取消发布）时提示「创建失败」，内容是服务端给出的原因，应用不会被创建。

### 2. 查看生成结果

详情页顶部的两个徽标分别是应用状态（如「规格生成中」「规格就绪」「预览就绪」「试用态」「发布候选」「已发布」「失败」）与就绪状态（「预览态」「试用态」「发布候选」「已阻断」），含义见下文[门禁与就绪状态](#门禁与就绪状态)。页面各区块：

| 区块 | 用来确认什么 |
| --- | --- |
| 自动生成与验证 | 当前阻断项与 Warning 数量，最近一次生成运行的实时进度；「运行自动生成与验证」与「重新生成 AppSpec 并运行」启动新的运行 |
| AppSpec 摘要 | 从需求整理出的目标、角色、数据策略（「公开提交持久化」「创建者可删除提交」「终端用户需登录」）与核心需求 |
| Acceptance scenarios | 按 Given / When / Then 列出的验收场景 |
| Gate 0-7 结果 | 每个门禁的状态与摘要 |
| Traceability | 核心需求到验收场景和证据的对应关系 |
| 生成证据/运行记录 | 历次生成运行、修复尝试与 Gate 运行证据，可按运行状态筛选 |
| Artifacts | Gate 3 物化的工作区文件与 Gate 5 的截图、trace（短时下载链接）；只在 Studio 中对创建者展示 |
| Resource bindings | 绑定的 Agent 与 Workflow；「打开 Agent 专业编辑器」「打开 Workflow 专业编辑器」进入对应编辑页 |

阻断项不为 0 时，先在「Gate 0-7 结果」与「生成证据/运行记录」中查看失败原因，再重新运行：

- 「运行自动生成与验证」：复用已生成的 AppSpec 重新执行 Gate 0–7（Gate 0 仍会复核规格与绑定）；还没有 AppSpec 时先生成。
- 「重新生成 AppSpec 并运行」：丢弃当前 AppSpec，由模型按需求重新生成后再执行 Gate 0–7。已有 AppSpec 时才显示。例如绑定的工作流重新发布后，要采用新版本就用这个按钮。

点击后提示「生成运行已排队」，进度在本区块刷新；运行结束后徽标、「Gate 0-7 结果」与其他区块随之刷新。同一应用同时只能有一次运行：运行进行中时两个按钮不可用（主按钮显示「生成运行中」）；如果在别处已启动了运行，点击会提示「已有生成运行进行中」，并接上那次运行的进度。

### 3. 确认提交会启动 Workflow

公开提交执行的是生成时固定的版本：绑定工作流时是那个工作流在 Gate 0 解析到的已发布版本；绑定 Agent 时是 Gate 4 为应用创建并发布的包装工作流（表单输入 → Agent → 文本输出）。「Runtime binding readiness」区块显示终端用户提交表单后能否启动执行，「固定版本」一栏是实际执行的版本；徽标旁的文字是「公开提交可创建异步执行」或「公开提交不会启动 Workflow」。

| 徽标 | 含义 | 处理 |
| --- | --- | --- |
| 可启动 Workflow | 固定版本可执行，公开提交会创建异步执行 | 无需处理 |
| Workflow 已重新发布 | 绑定的工作流发布了新版本，应用仍执行固定版本 | 要采用新版本，点击「重新运行自动生成与验证」；重新生成会再次校验输入输出映射 |
| 尚未发布 | 绑定的工作流当前不是已发布状态 | 用「打开 Workflow 专业编辑器」进入并发布，见[版本管理](/guide/workflows/versions) |
| Workflow 不可用 | 绑定的工作流已不存在、已归档，或固定版本已被删除 | 点击「重新运行自动生成与验证」 |
| 未绑定运行时 | 还没有 AppSpec，或 Agent 绑定的包装工作流尚未创建、与当前 AppSpec 不一致 | 点击「重新运行自动生成与验证」，直到 Gate 4 通过 |

除「可启动 Workflow」与「Workflow 已重新发布」外，公开提交会直接记为失败，终端用户只看到「应用暂时无法处理提交」，具体原因记在提交详情的「执行引用」里。这一项不影响公开链接能否开启。

删除应用（owner、admin，`DELETE /api/v1/generated-apps/<应用 id>`）时，它的全部生成产物（Gate 3 工作区文件、Gate 5 截图与 trace）从对象存储中删除，为它创建的运行用 Workflow 一并归档：不能再运行或发布，执行记录保留。对象存储暂不可用时接口返回 503（`storage-unavailable`），应用保持不变，可稍后重试。

### 4. 开启公开链接

公开链接的开关在列表卡片右侧与详情页「Public share」区块，两处相同：

- 就绪状态为「发布候选」时，显示「启用公开分享」。点击后应用状态变为「已发布」，区块显示「公开分享已启用」、浏览次数和公开链接，可复制或在新标签页打开。
- 其他就绪状态下按钮为灰色的「公开分享不可用」，鼠标悬停显示原因。

公开链接形如 `/generated-apps/public/<token>`，打开时不要求登录。链接开启后：

- 「重新生成」换一个新的 token，旧链接随即失效。
- 「关闭分享」使当前链接失效；之后再次启用会得到新的链接。
- 门禁结果变化导致就绪状态不再是「发布候选」时，详情页「公开访问」显示「门禁不可用」。

### 5. 查看终端用户的提交

终端用户打开公开链接后，看到按 AppSpec 生成的表单（文本、长文本、数字、单选、多选）。提交后页面显示「正在处理」，执行结束后在结果区按 AppSpec 的结果分区展示答案：纯文本、Markdown、引用列表（标题、引文、来源）或 JSON。提交内容不符合表单（必填为空、超长、选项外的值）时，错误标在对应字段下，不会产生提交记录。执行失败时结果区只显示通用原因，不暴露内部节点与错误细节。

创建者在详情页「提交记录」区块查看：

- 「来源」默认是「终端用户」。Gate 5 浏览器验收在真实公开页上提交的记录归入「Gate 5 验收」，不混入终端用户的数据，切换来源后单独查看，详情里带所属的生成运行。
- 按状态筛选；每条显示提交时间、输入、结果分区与错误。打开详情可看到「执行引用」：执行 ID、绑定的工作流与固定版本，未启动执行时显示原因（如 `workflow_not_published`）。
- 单条删除或勾选后批量删除。删除后，该提交在创建者列表、详情和公开结果页都不再可见。

## 门禁与就绪状态

为什么有的应用只能预览、不能公开？公开链接面向不登录的终端用户，所以只对通过全部门禁、且没有任何 Warning 的应用开放。

每次生成运行在后台按顺序执行 Gate 0 到 Gate 7（`agentloom-server/src/modules/generated-app/generated-app.gates.ts`），全部为阻断门禁；某个 Gate 失败后，后面的 Gate 不再执行：

| Gate | 名称 | 检查内容 |
| --- | --- | --- |
| 0 | 需求规格门禁 | 用生成模型按需求生成 AppSpec：表单字段、结果分区、要调用的已发布工作流或 Agent（固定当时的发布版本），以及每条需求可在浏览器里执行的验收场景；没有可用模型、没有可绑定的已发布工作流或 Agent、绑定与工作流的输入契约或输出节点不兼容、模型多次输出不合规或超时都会失败 |
| 1 | 架构计划门禁 | 每条需求都有验收场景覆盖，场景用到的表单字段与结果分区都映射到绑定目标 |
| 2 | 静态合约门禁 | 由表单生成的公开输入契约、由结果分区生成的结果契约，与绑定工作流固定版本的输入契约兼容；Agent 绑定的包装工作流图结构合法 |
| 3 | 构建与单元门禁 | 写出 AppSpec、运行表单与静态契约文件并保存到对象存储（详情页 Artifacts 可查看）；每个验收场景的填写值都能通过公开提交校验与工作流输入校验，未知字段、缺必填字段会被拒绝 |
| 4 | 集成门禁 | 绑定目标仍已发布、固定版本仍是当前版本、创建者仍有运行权限、Agent 用到的模型仍可用；Agent 绑定在这里创建并发布包装工作流 |
| 5 | 浏览器验收门禁 | 独立的 browser-runner 用 Playwright 在桌面与移动两个视口打开真实公开页，按场景填写、提交、等待结果并检查断言的结果分区有内容（回答每次措辞不同，不比对具体文字），保存截图与 trace；browser-runner 未运行时立即失败 |
| 6 | 独立审查门禁 | 复核 Gate 5 证据：两个视口都通过、无 console 错误与失败的接口请求、结果分区非空、截图与 trace 确实已保存；字体、图片等静态资源加载失败不算应用失败 |
| 7 | 发布候选门禁 | 写入发布候选 manifest（AppSpec 指纹、固定绑定版本、各 Gate 证据），并把运行用工作流记到应用上 |

Gate 0 调用模型生成 AppSpec，Gate 5 真实执行绑定的工作流或 Agent，两者都消耗本组织的模型用量。

就绪状态由门禁结果推导，按以下顺序判断：

| 就绪状态 | 条件 | 应用状态 | 能否公开 |
| --- | --- | --- | --- |
| 已阻断 | 任一阻断门禁失败 | 失败 | 否 |
| 预览态 | 仍有阻断门禁未通过（等待中、运行中等），但没有失败 | 预览就绪 | 否 |
| 试用态 | 阻断门禁全部通过，但存在 Warning | 试用态 | 否 |
| 发布候选 | 阻断门禁全部通过且没有 Warning | 发布候选 | 是 |

刚创建、AppSpec 还没生成出来时，应用状态是「规格生成中」；Gate 0 通过后变为「规格就绪」，之后按上表由门禁结果决定。开启公开分享后应用状态变为「已发布」；关闭分享后回到按就绪状态推导的应用状态。
