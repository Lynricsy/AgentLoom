# 生成应用

用一句话描述业务需求，AgentLoom 会把它整理成应用规格（AppSpec），经过一组门禁验证后，生成一个终端用户不登录就能打开的公开应用。本页前半部分是操作步骤，后半部分「门禁与就绪状态」解释公开链接什么时候可用。

- 外部系统如何接入生成应用的公开接口，见[生成应用接入](/api/generated-apps)。
- 服务端的生成、门禁与公开运行实现，见[生成应用（服务端）](/dev/server/generated-apps)。

## 操作指南

### 前置条件

- 组织角色为 owner、admin 或 creator。operator 与 viewer 可以浏览列表和详情，但不能创建应用、运行生成或管理公开链接（`agentloom-server/src/modules/generated-app/generated-app.controller.ts` 中各端点的 `@Roles`）。

### 1. 创建应用并运行生成

1. 在左侧导航「构建」组点击「生成应用」，进入 `/generated-apps`。
2. 在「一句话描述你要的应用」输入框中写需求，例如占位文字中的「自动化中医问诊系统，能逐步提问并生成分析报告」。输入上限 4000 字符。
3. 点击「创建并生成应用」。

按钮变为「正在生成」，直到本次生成运行返回。结束后右上角出现提示：

- 「自动生成与验证已完成」：所有步骤跑完，可进入详情查看结果。
- 「自动生成与验证未通过」：提示内容是失败原因。
- 「应用已创建，但自动生成启动失败」：应用已保存，需要在详情页重新运行。

输入框下方出现一张结果卡片，显示应用名、本次运行摘要和写入证据的 Gate 数量，点击「进入详情」打开 `/generated-apps/<appId>`。

### 2. 查看生成结果

详情页顶部的两个徽标分别是应用状态（如「预览就绪」「试用态」「发布候选」「已发布」「失败」）与就绪状态（「预览态」「试用态」「发布候选」「已阻断」），含义见下文[门禁与就绪状态](#门禁与就绪状态)。页面各区块：

| 区块 | 用来确认什么 |
| --- | --- |
| 自动生成与验证 | 当前阻断项与 Warning 数量；「运行自动生成与验证」（已有门禁结果时为「重新运行自动生成与验证」）再次运行生成 |
| AppSpec 摘要 | 从需求整理出的目标、角色、数据策略（「公开提交持久化」「创建者可删除提交」「终端用户需登录」）与核心需求 |
| Acceptance scenarios | 按 Given / When / Then 列出的验收场景 |
| Gate 0-7 结果 | 每个门禁的状态与摘要 |
| Traceability | 核心需求到验收场景和证据的对应关系 |
| 生成证据/运行记录 | 历次生成运行、修复尝试与 Gate 运行证据，可按运行状态筛选 |
| Artifacts | Preview URL、源码与测试报告链接，以及交付物内容；只在 Studio 中对创建者展示 |
| Resource bindings | 生成的 Agent 与 Workflow；「打开 Agent 专业编辑器」「打开 Workflow 专业编辑器」进入对应编辑页 |

阻断项不为 0 时，先在「Gate 0-7 结果」与「生成证据/运行记录」中查看失败原因，再点击「重新运行自动生成与验证」。运行结束后徽标与「Gate 0-7 结果」随之刷新。

### 3. 确认提交会启动 Workflow

Gate 7 通过时，生成运行会创建并发布一个运行用 Workflow，绑定到应用上。「Runtime binding readiness」区块显示终端用户提交表单后是否会启动这个 Workflow；徽标旁的文字是「公开提交可创建异步执行」或「公开提交不会启动 Workflow」。

| 徽标 | 含义 | 处理 |
| --- | --- | --- |
| 可启动 Workflow | 绑定的 Workflow 已发布，公开提交会创建异步执行 | 无需处理 |
| 尚未发布 | 绑定的 Workflow 当前不是已发布状态 | 用「打开 Workflow 专业编辑器」进入并发布，见[版本管理](/guide/workflows/versions) |
| Workflow 不可用 | 绑定的 Workflow 已不存在或当前组织无权访问 | 点击「重新运行自动生成与验证」 |
| 编辑器草稿 | 绑定的是专业编辑器草稿，公开提交不会自动执行它 | 点击「重新运行自动生成与验证」；Gate 7 通过后改为绑定运行用 Workflow |
| Deterministic only | 应用还没有绑定 Workflow，公开提交只返回本地生成的报告 | 点击「重新运行自动生成与验证」，直到 Gate 7 通过 |

处理后刷新详情页，徽标变为「可启动 Workflow」。这一项不影响公开链接能否开启。

### 4. 开启公开链接

公开链接的开关在列表卡片右侧与详情页「Public share」区块，两处相同：

- 就绪状态为「发布候选」时，显示「启用公开分享」。点击后应用状态变为「已发布」，区块显示「公开分享已启用」、浏览次数和公开链接，可复制或在新标签页打开。
- 其他就绪状态下按钮为灰色的「公开分享不可用」，鼠标悬停显示原因。

公开链接形如 `/generated-apps/public/<token>`，打开时不要求登录。链接开启后：

- 「重新生成」换一个新的 token，旧链接随即失效。
- 「关闭分享」使当前链接失效；之后再次启用会得到新的链接。
- 门禁结果变化导致就绪状态不再是「发布候选」时，详情页「公开访问」显示「门禁不可用」。

### 5. 查看终端用户的提交

终端用户在公开页面填写「业务表单」并提交后，结果在同一页面展示。创建者在详情页「提交记录」区块查看：

- 按状态筛选提交；每条显示提交时间、Workflow 执行进度（总步骤、完成步骤、失败步骤）与报告。
- 单条删除或勾选后批量删除。删除后，该提交在创建者列表、详情和公开结果页都不再可见。

## 门禁与就绪状态

为什么有的应用只能预览、不能公开？公开链接面向不登录的终端用户，所以只对通过全部门禁、且没有任何 Warning 的应用开放。

每次生成运行会写入 Gate 0 到 Gate 7 的结果（`agentloom-server/src/modules/generated-app/generated-app.gates.ts`），全部为阻断门禁：

| Gate | 名称 | 检查内容 |
| --- | --- | --- |
| 0 | 需求规格门禁 | AppSpec 完整性、风险分类与验收场景 |
| 1 | 架构计划门禁 | 实现计划是否覆盖 AppSpec、页面、编排、插件与测试计划 |
| 2 | 静态合约门禁 | TypeScript、API 契约、图 schema、DAG 与插件 manifest |
| 3 | 构建与单元门禁 | 前端构建、插件构建、单元测试、组件测试与 golden tests |
| 4 | 集成门禁 | 生成应用、Agent/Workflow dry-run 与插件沙箱 smoke test |
| 5 | 浏览器验收门禁 | Playwright 跑核心验收场景，检查 console 与 network |
| 6 | 独立审查门禁 | 独立 verifier 审查 AppSpec、证据矩阵与运行结果 |
| 7 | 发布候选门禁 | 所有阻断门禁通过后生成发布候选 |

就绪状态由门禁结果推导，按以下顺序判断：

| 就绪状态 | 条件 | 应用状态 | 能否公开 |
| --- | --- | --- | --- |
| 已阻断 | 任一阻断门禁失败 | 失败 | 否 |
| 预览态 | 仍有阻断门禁未通过（等待中、运行中等），但没有失败 | 预览就绪 | 否 |
| 试用态 | 阻断门禁全部通过，但存在 Warning | 试用态 | 否 |
| 发布候选 | 阻断门禁全部通过且没有 Warning | 发布候选 | 是 |

开启公开分享后应用状态变为「已发布」；关闭分享后回到按就绪状态推导的应用状态。
