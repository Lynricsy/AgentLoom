# MCP 工具

## 功能说明

MCP 工具节点通过 Model Context Protocol（模型上下文协议）连接外部工具，并将工具能力暴露给工作流中的 AI 推理节点。MCP 是一种标准化协议，用于让 AI 模型与外部工具、数据源和服务进行交互。

通过 MCP 工具节点，你可以将搜索引擎、数据库查询、文件操作、代码执行等各种外部能力接入工作流，让 Agent 在推理过程中按需调用。

## 使用场景

- **搜索增强**：连接搜索引擎工具，让 Agent 在回答问题时可以实时搜索最新信息。
- **数据库操作**：连接数据库查询工具，让 Agent 可以读取和分析数据库中的数据。
- **第三方集成**：连接各种第三方服务的 MCP 适配器，扩展 Agent 的能力边界。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口 |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 工具 | tool | 连接后该 MCP 工具将注册到 Agent，Agent 可按需调用 |

## 配置项

### MCP 工具选择

在放置 MCP 工具节点时，你需要选择一个已在平台中注册的 MCP 工具定义。

> 界面提示：MCP 工具节点在节点面板中位于 "Tool" 分类下。放置后在配置面板中可以查看和修改工具的配置。

### 工具定义信息

MCP 工具节点会显示所选工具的以下信息：

| 信息 | 说明 |
|------|------|
| 工具名称 | MCP 工具的唯一标识名 |
| 工具描述 | 工具功能的文字说明 |
| 参数定义 | 工具接受的输入参数 Schema |

这些信息来自 MCP 工具的定义，Agent 在推理时会参考工具描述和参数定义来决定何时以及如何调用该工具。

## 使用示例

### 示例一：为 Agent 添加搜索能力

1. 在 MCP 服务管理页面注册一个搜索引擎的 MCP 工具。
2. 在工作流画布上放置一个 **Agent** 节点，在配置面板中选择一个已发布的 Agent。
3. 放置一个 **MCP 工具** 节点，选择该搜索工具。
4. 将 MCP 工具的"工具"输出端口连接到 Agent 节点的"扩展工具"输入端口。
5. Agent 在推理过程中如果需要查找信息，会自动调用搜索工具并利用搜索结果来回答。

### 示例二：多工具组合

为一个 Agent 同时配备多种工具：

1. 放置多个 **MCP 工具** 节点（搜索工具、计算器工具、天气工具等）。
2. 将每个工具节点的"工具"端口都连接到同一个 Agent 节点的"扩展工具"端口（该端口支持多连接）。
3. Agent 在对话中会根据用户请求自动判断调用哪个工具。

### 示例三：为工作流中的 Agent 节点增加工具

当你在工作流中使用 Agent 节点（引用独立 Agent）时，可以通过 MCP 工具节点为它额外添加工具，这些工具会叠加在 Agent 定义自身的工具配置之上：

1. 放置一个 **Agent** 节点，选择已发布的 Agent。
2. 放置一个 **MCP 工具** 节点，选择该 Agent 原本没有配置的工具。
3. 将 MCP 工具的"工具"端口连接到 Agent 节点的"扩展工具"端口。
4. 工作流执行时，Agent 可以同时使用自身定义的工具和通过端口额外连接的工具。

## MCP 协议基础

### 什么是 MCP

Model Context Protocol（MCP）是一种开放标准协议，旨在规范 AI 模型与外部工具之间的通信方式。通过 MCP，工具开发者只需按协议标准实现工具描述和调用接口，就能让任何支持 MCP 的 AI 系统使用该工具。

### MCP 工具的组成

一个 MCP 工具通常包含以下信息：

| 组成部分 | 说明 |
|----------|------|
| 工具名称 | 唯一标识，Agent 通过名称来识别和调用工具 |
| 工具描述 | 自然语言描述工具的功能，Agent 据此判断是否需要使用 |
| 输入参数 Schema | JSON Schema 格式定义工具接受的输入参数 |
| 返回值 Schema | 定义工具返回的数据结构 |

### 工具注册流程

1. 在 AgentLoom 的 MCP 服务管理页面添加 MCP 服务连接。
2. 系统会自动发现该服务提供的工具列表。
3. 每个工具可以在工作流画布上作为 MCP 工具节点使用。

## 注意事项

1. **MCP 工具需先注册**：在使用 MCP 工具节点之前，需要先在 MCP 服务管理页面注册对应的工具定义。没有注册的工具无法在画布上选择。
2. **工具描述质量**：Agent 依赖工具的描述文本来判断何时调用该工具。确保工具描述清晰准确，否则 Agent 可能无法正确识别何时应该使用它。描述应该明确说明"这个工具做什么"和"什么情况下应该使用它"。
3. **数据类型兼容**：MCP 工具节点输出的是 `tool` 类型端口（六边形图标），只能连接到 Agent 类节点的工具输入端口。不能连接到其他类型的端口。
4. **Legacy 兼容**：对于使用旧版格式（number、boolean 等）定义的工具参数，系统会自动回退转换为 json 类型处理。你不需要做额外的兼容处理。
5. **工具调用权限**：在不同的自主决策模式下，Agent 调用 MCP 工具可能需要用户确认。具体行为取决于所绑定 Agent 自身的自主决策配置——它在 Agent 配置中设定，不在工作流的 Agent 节点上。在全自动工作流（如定时触发）中，建议为该 Agent 选用 RULE_BASED 或 LLM_SUGGEST 模式以避免人工阻塞。
6. **工具数量建议**：虽然可以为一个 Agent 连接多个工具，但过多的工具会增加 Token 消耗（工具描述需要注入提示中），也可能降低 Agent 选择正确工具的准确度。建议每个 Agent 连接不超过 10-15 个工具。
