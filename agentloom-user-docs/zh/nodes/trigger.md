# 触发器节点

## 功能说明

触发器节点定义了工作流的启动方式。每个工作流至少需要一个触发器来决定何时以及如何开始执行。AgentLoom 提供四种类型的触发器，覆盖手动操作、定时调度、外部 HTTP 回调和 API 事件驱动等常见场景。

## 使用场景

- **手动执行**：用户在 Studio 中点击"运行"按钮，通过表单或对话方式提交输入参数后启动工作流。
- **定时调度**：按照 Cron 表达式周期性自动执行工作流，如每天凌晨 2 点生成日报。
- **外部回调**：通过 Webhook URL 接收外部系统的 HTTP 请求来触发工作流，如 GitHub Push 事件。
- **API 事件驱动**：通过 AgentLoom 的 API 事件端点接收外部事件并触发工作流，支持多种事件源适配。

## 触发器类型

### 手动触发器（Manual Trigger）

最基础的触发方式。用户在 Studio 中手动点击运行按钮来启动工作流。

**输出端口：**

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 触发数据 | json | 手动触发时用户填写的表单参数 |

**配置项：** 无额外配置。输入参数通过工作流级别的 `input_schema` 定义。

### 定时触发器（Schedule Trigger）

按照 Cron 表达式定时自动执行工作流。

**输出端口：**

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 触发数据 | json | 调度信息（触发时间、Cron 表达式等） |

**配置项：**

| 配置 | 必需 | 说明 |
|------|------|------|
| Cron 表达式 | 是 | 标准的 Cron 表达式，定义执行周期 |
| 时区 | 否 | Cron 时区，默认为 UTC |

**Cron 表达式示例：**

| 表达式 | 含义 |
|--------|------|
| `0 2 * * *` | 每天凌晨 2:00 执行 |
| `0 */6 * * *` | 每 6 小时执行一次 |
| `0 9 * * 1` | 每周一上午 9:00 执行 |
| `0 0 1 * *` | 每月 1 日零点执行 |

### Webhook 触发器（Webhook Trigger）

通过唯一的 Webhook URL 接收外部 HTTP 请求来触发工作流。外部系统（如 CI/CD 平台、监控系统等）可以向此 URL 发送 POST 请求。

**输出端口：**

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 触发数据 | json | Webhook 请求携带的 JSON Body |

**配置项：**

| 配置 | 必需 | 说明 |
|------|------|------|
| 鉴权模式 | 否 | `simple`（简单令牌）或 `signed`（签名验证） |
| IP 白名单 | 否 | 限制允许触发的源 IP 地址 |

> 安全提示：如果使用 signed 鉴权模式，外部系统需要使用正确的签名方式签署请求。签名验证失败的请求会被记录到触发历史中。

### API 事件触发器（API Event Trigger）

通过 AgentLoom 的统一 API 事件端点（`POST /api/v1/api-events`）接收外部事件。系统会根据事件来源和类型自动匹配并触发对应的工作流。

**输出端口：**

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 触发数据 | json | 外部 API 事件携带的 JSON 数据 |

**配置项：**

| 配置 | 必需 | 说明 |
|------|------|------|
| 事件来源 | 是 | 事件的来源标识（如 `github`、`custom`） |
| 事件类型 | 是 | 事件的类型标识（如 `push`、`pull_request`） |
| 过滤表达式 | 否 | 用于进一步过滤事件的条件表达式 |

**内置事件适配器：**

| 适配器 | 说明 |
|--------|------|
| GitHub Webhook | 支持 HMAC-SHA256 签名验证，解析 GitHub 事件格式 |
| 通用事件（Generic） | 透传任意 JSON 事件载荷，不做额外验证 |

## 使用示例

### 示例一：手动触发的翻译工作流

1. 放置一个 **手动触发器** 节点。
2. 在工作流设置中定义输入参数（原文本、目标语言）。
3. 将触发器输出连接到 LLM Agent 节点。
4. 用户点击"运行"后填写表单即可启动。

### 示例二：定时生成周报

1. 放置一个 **定时触发器** 节点，Cron 设为 `0 9 * * 1`（每周一上午 9 点）。
2. 后续节点从数据库或 API 获取过去一周的数据。
3. LLM Agent 根据数据生成周报。
4. 文本输出节点展示报告，同时通过通知模块发送到相关人员。

### 示例三：GitHub Push 自动触发代码审查

1. 放置一个 **API 事件触发器** 节点，事件来源设为 `github`，事件类型设为 `push`。
2. 在 GitHub 仓库的 Webhook 设置中，将 URL 指向 AgentLoom 的 API 事件端点。
3. 每次 Push 时，GitHub 发送事件到 AgentLoom，自动触发代码审查工作流。

## 注意事项

1. **每个工作流至少一个触发器**：没有触发器的工作流无法被执行。
2. **多触发器支持**：一个工作流可以有多个触发器节点。例如同时支持手动触发和定时触发。
3. **Webhook 安全**：在生产环境中，建议为 Webhook 触发器启用签名验证和 IP 白名单，防止未授权的触发请求。
4. **触发历史**：所有触发器类型都会记录触发历史，包括成功和失败的触发尝试。你可以在触发历史中排查问题。
5. **租户隔离**：触发器的执行在租户事务提交后才会入队执行，确保多租户环境下的隔离性。
