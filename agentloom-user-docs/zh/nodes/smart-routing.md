# 智能路由

## 功能说明

智能路由节点根据预设的策略从多个候选 LLM 模型中选择一个最优模型进行后续推理。它解决了"该用哪个模型"的问题——你不需要将整条工作流绑定到单一模型上，而是让系统根据成本、质量、延迟等维度动态选择最合适的模型。

## 使用场景

- **成本优化**：有些请求只需要轻量模型就能处理，复杂请求才需要高端模型。通过智能路由让系统自动选择，降低整体成本。
- **高可用回退**：当首选模型不可用时，自动切换到备用模型，保证工作流不中断。
- **A/B 测试**：对多个模型的输出效果进行评估比较，逐步收敛到最优选择。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口 |
| 模型 1 | model | 是 | 第一个候选模型 |
| 模型 2 | model | 是 | 第二个候选模型 |
| 模型 3 ~ 模型 N | model | 否 | 可动态添加更多候选模型端口（最多 10 个） |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 选定模型 | model | 根据策略选出的模型实例（可连接最多 5 个下游） |

## 配置项

### 路由策略

智能路由支持多种策略，在配置面板中选择。

**基础策略：**

| 策略 | 说明 |
|------|------|
| random | 从候选模型中随机选择一个 |
| round_robin | 按轮询方式依次选择候选模型 |
| rules | 根据自定义规则条件选择模型 |
| fallback_chain | 回退链 — 按优先级逐个尝试，首选不可用时自动切换下一个 |

**机器学习策略：**

| 策略 | 说明 |
|------|------|
| knn | K 最近邻 — 根据历史相似请求的最佳模型选择 |
| mlp | 多层感知机 — 通过在线训练的神经网络预测最佳模型 |
| elo | Elo 评分 — 基于模型历史对抗表现的评分体系 |

**高级策略：**

| 策略 | 说明 |
|------|------|
| llm_as_router | 使用 LLM 自身来判断哪个模型最适合当前请求 |
| memory_bank | 基于记忆库中积累的模型性能记录做决策 |
| wasm_plugin | 使用自定义 WASM 插件实现路由逻辑 |

### 候选模型端口管理

> 界面提示：在配置面板中，你可以点击"添加模型端口"来增加更多的候选模型输入端口，最少 2 个，最多 10 个。也可以删除多余的端口或调整端口顺序。

### 模型健康状态

配置面板会实时显示每个已连接模型的健康状态：

| 状态 | 说明 |
|------|------|
| 正常（healthy） | 模型服务正常可用 |
| 降级（degraded） | 模型服务部分可用，响应可能变慢 |
| 断路（open） | 模型服务不可用，请求将被路由到其他模型 |

## 使用示例

### 示例一：成本优化路由

构建一个翻译工作流，希望在保证质量的前提下降低成本：

1. 放置两个 **LLM 模型** 节点：
   - 模型 A：高端模型（如 GPT-4），质量最优但成本较高。
   - 模型 B：轻量模型（如 GPT-3.5），成本低但质量略逊。
2. 放置一个 **智能路由** 节点，策略选择 `fallback_chain`。
3. 将模型 A 连接到"模型 1"端口，模型 B 连接到"模型 2"端口。
4. 将智能路由的"选定模型"端口连接到 LLM Agent 节点。

这样，系统会优先使用模型 A，当模型 A 不可用时自动切换到模型 B。

### 示例二：多模型 A/B 测试

想比较两个模型的效果：

1. 放置两个 LLM 模型节点配置不同的模型。
2. 使用智能路由节点，策略选择 `round_robin`。
3. 每次执行工作流时，系统会轮询使用不同模型，方便你比较输出结果。

## 注意事项

1. **至少两个模型**：智能路由至少需要连接 2 个候选模型才能正常工作。
2. **默认策略**：默认策略为回退链（fallback_chain），这对大多数场景来说是最安全的选择。
3. **机器学习策略需要数据**：KNN、MLP、Elo 等策略需要积累一定的历史执行数据才能做出有效决策。刚开始使用时建议先用基础策略。
4. **回退链的非认证失败**：当使用 fallback_chain 策略时，只有非认证类的失败才会触发回退。如果是因为 API Key 错误导致的失败，不会自动切换到下一个模型。
