# 知识库节点

## 功能说明

知识库节点将一个向量知识库连接到工作流中，为 AI 推理节点提供 RAG（检索增强生成）能力。当 Agent 收到问题时，可以先在知识库中检索相关文档片段，然后结合检索结果生成更准确、有依据的回答。

知识库底层使用 Qdrant 向量数据库进行语义检索，支持按相似度排序返回最相关的文档片段。

## 使用场景

- **企业知识问答**：将公司文档、产品手册、FAQ 等导入知识库，让 Agent 基于这些资料回答员工或客户的问题。
- **技术文档检索**：将 API 文档、设计文档导入知识库，Agent 在编写代码或回答技术问题时自动检索参考。
- **合规审查**：将法规、政策文档导入知识库，Agent 在审查内容时可以引用相关条款。

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 知识库 | knowledge | 向量知识库引用，连接到 Agent 后可检索其中的文档 |

## 配置项

### 知识库选择

在配置面板中选择要绑定的知识库。

> 界面提示：配置面板提供一个知识库下拉列表，显示当前组织中所有可用的知识库。每个知识库会显示名称和文档数量等基本信息。

| 配置 | 必需 | 说明 |
|------|------|------|
| Knowledge Base ID | 是 | 选择要绑定的知识库 |

### 前提条件

使用知识库节点前，你需要先在 AgentLoom 的知识库管理模块中：

1. 创建一个知识库。
2. 向知识库中导入文档（支持多种文档格式）。
3. 等待文档向量化处理完成。

## 使用示例

### 示例一：基于知识库的问答

1. 放置一个 **手动触发器** — 用户输入问题。
2. 放置一个 **知识库** 节点，选择"产品文档知识库"。
3. 放置一个 **LLM Agent** 节点，系统提示词指示它"根据检索到的文档内容回答用户问题"。
4. 将知识库的"知识库"端口连接到 Agent 的知识库输入端口。
5. 将触发器的文本输出连接到 Agent 的消息输入端口。
6. Agent 收到问题后会先检索知识库，然后基于检索结果生成回答。

### 示例二：多知识库协同

为一个 Agent 同时绑定多个知识库：

1. 放置两个 **知识库** 节点，分别选择"技术文档库"和"FAQ 文档库"。
2. 将两个知识库的输出端口都连接到同一个 Agent 节点的知识库输入端口（该端口支持多连接）。
3. Agent 在检索时会在两个知识库中同时搜索，综合结果进行回答。

### 示例三：Agent 节点 + 知识库 + 技能组合

将知识库与技能一起连接到 Agent，实现增强的文档问答：

1. ���置一个 **知识库** 节点，选择"公司制度文档库"。
2. 放置一个 **技能** 节点，选择"文档编写"技能。
3. 放置一个 **Agent** 节点（引用已发布的客服助手 Agent）。
4. 将知识库端口连接到 Agent 的知识库输入，技能端口连接到 Agent 的 Skills 输入。
5. Agent 在回答时会检索制度文档，同时按照文档编写技能的规范来组织回答内容。

## RAG 检索原理

### 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与 AI 生成结合的技术。其核心思路是：

1. **检索**：当 Agent 收到问题时，先在知识库中搜索与问题语义最相关的文档片段。
2. **增强**：将检索到的文档片段作为上下文注入到 Agent 的提示中。
3. **生成**：Agent 基于检索到的上下文生成回答，而不是仅依赖模型自身的训练数据。

### RAG 的优势

| 优势 | 说明 |
|------|------|
| 知识可控 | Agent 的回答基于你导入的文档，不会编造不存在的信息 |
| 实时更新 | 只要更新知识库中的文档，Agent 的回答就会相应更新 |
| 领域专注 | Agent 可以深入理解你的专属领域知识，而不是泛泛而谈 |
| 可追溯 | Agent 的回答有明确的文档来源，可以验证准确性 |

### 影响检索质量的因素

- **文档质量**：文档内容应准确、完整、结构清晰。
- **文档切分**：过长的文档会被切分为片段，切分的粒度影响检索精度。
- **问题表述**：用户提问的方式会影响检索结果。明确具体的问题比模糊的问题能获得更好的检索结果。

## 注意事项

1. **知识库需提前准备**：知识库节点本身不负责文档管理。你需要先在知识库管理页面创建知识库并导入文档。节点只是将已有知识库连接到工作流中。
2. **向量化延迟**：新导入的文档需要经过向量化处理才能被检索。大量文档的向量化可能需要一些时间。在文档处理完成前，检索结果可能不完整。
3. **检索质量**：RAG 的效果取决于知识库中文档的质量和检索参数的配置。确保导入的文档内容准确、组织清晰。低质量的文档可能导致 Agent 给出不准确的回答。
4. **多知识库支持**：Agent 节点的知识库端口支持多连接。当连接多个知识库时，Agent 可以统一通过 `search_knowledge` 工具在所有绑定的知识库中显式选择检索。
5. **端口类型**：知识库节点输出的是 `knowledge` 类型端口（书本形图标），只能连接到 Agent 类节点的知识库输入端口。不能连接到其他类型的端口。
6. **知识库容量**：知识库的文档数量和总大小会影响检索性能。建议按主题划分知识库，避免将所有文档放入一个知识库。
