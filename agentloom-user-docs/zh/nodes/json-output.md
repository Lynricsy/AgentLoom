# JSON 输出

## 功能说明

JSON 输出节点用于展示工作流的结构化 JSON 结果。它与文本输出节点类似，是一个终端节点，但专门用于接收和展示 JSON 格式的数据。当工作流的产出是结构化数据（如分析结果、配置对象、数据列表、提取的实体等）时，使用 JSON 输出节点可以获得更好的展示效果。

JSON 输出节点同样支持内联输出预览功能——在工作流执行过程中，你就能在画布上看到该节点已接收到的 JSON 数据。

## 使用场景

- **展示结构化分析结果**：AI 按照 JSON Schema 约束生成的结构化分析报告。例如让 LLM Agent 从一段文本中提取关键实体、情感倾向和摘要，并以 JSON 格式输出。
- **展示 API 响应**：HTTP 请求节点从外部 API 获取的 JSON 响应数据直接通过 JSON 输出节点展示，方便查看和调试。
- **数据管道终点**：经过多步处理（过滤、转换、合并）后的结构化数据作为工作流的最终产出。
- **调试与验证**：在开发工作流时，临时放置 JSON 输出节点来查看中间步骤的 JSON 数据，确认数据结构和内容是否正确。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口，前序节点完成后触发输出节点接收数据 |
| JSON | json | 否 | 接收要作为工作流最终结果展示的 JSON 数据 |

> 界面提示：JSON 输入端口在画布上显示为方形图标，使用 JSON 类型的配色，便于与其他类型端口区分。

### 输出端口

JSON 输出节点没有输出端口，它是工作流的终端节点。数据到达此节点后不再往下游传递。

## 配置项

JSON 输出节点没有额外的配置项。它是一个纯展示节点，只负责接收上游传递来的 JSON 数据并展示。

你不需要在这个节点上做任何配置——只需要将它放在画布上，并将上游节点的 JSON 输出端口连接到它的 JSON 输入端口即可。

## 使用示例

### 示例一：结构化数据提取

创建一个从非结构化文本中提取结构化信息的工作流：

1. **手动触发器** — 用户输入一段会议纪要文本。
2. **LLM Agent** — 系统提示词指示 Agent 将会议纪要提取为如下 JSON 结构：
   - `participants`：参与者列表
   - `decisions`：做出的决策
   - `actionItems`：待办事项（每项包含负责人和截止日期）
   - `summary`：会议摘要
3. **JSON 输出** — 展示提取后的结构化 JSON 数据。

在这个示例中，LLM Agent 的"结构化"输出端口连接到 JSON 输出节点的"JSON"输入端口。执行完成后，你可以在结果页面看到格式化的 JSON 输出。

### 示例二：API 数据展示

将外部 API 的响应数据直接展示：

1. **Webhook 触发器** — 接收外部请求。
2. **HTTP 请求节点** — 配置为 GET 方法，调用第三方数据 API。
3. **JSON 输出** — 直接展示 API 返回的 JSON 响应。

HTTP 请求节点的"响应体"端口直接连接到 JSON 输出节点，API 返回的完整 JSON 数据会被原样展示。

### 示例三：多分支结构化输出

在条件分支工作流中，不同分支产出不同结构的 JSON 数据：

1. **手动触发器** — 用户提交请求。
2. **LLM Agent** — 分析请求类型。
3. **条件分支** — 根据类型分流。
4. **JSON 输出 A**（IF 分支）— 展示分析报告 JSON。
5. **JSON 输出 B**（ELSE 分支）— 展示错误信息 JSON。

每个分支可以有自己的 JSON 输出节点，展示该分支特有的结构化结果。

### 示例四：调试中间数据

在开发阶段，你可以在工作流的任意中间位置插入 JSON 输出节点来检查数据：

1. 在 HTTP 请求节点之后放置一个 JSON 输出节点。
2. 将 HTTP 响应连接到这个 JSON 输出节点。
3. 运行工作流后查看 JSON 输出，确认 API 返回的数据结构是否符合预期。
4. 确认无误后，可以删除这个临时的 JSON 输出节点。

## 与文本输出的对比

| 对比维度 | JSON 输出 | 文本输出 |
|----------|-----------|----------|
| 接收数据类型 | json | text |
| 展示格式 | 格式化缩进的 JSON 视图 | 纯文本或 Markdown 渲染 |
| 适用内容 | 结构化数据、对象、数组 | 自然语言文本、报告、代码 |
| 端口形状 | 方形（JSON 类型） | 圆形（Text 类型） |

如果不确定用哪个，参考以下判断标准：

- 上游输出的是 LLM Agent 的"回复"端口（text 类型） — 使用 **文本输出**。
- 上游输出的是 LLM Agent 的"结构化"端口（json 类型） — 使用 **JSON 输出**。
- 上游输出的是 HTTP 请求的"响应体"端口（json 类型） — 使用 **JSON 输出**。

## 注意事项

1. **数据类型**：JSON 输出节点接收 json 类型的端口数据。如果上游输出的是纯文本（text 类型），端口类型不兼容，你需要在中间使用输入预处理器节点将文本转换为 JSON。
2. **内联预览**：与文本输出节点类似，JSON 输出节点在执行过程中会在画布卡片上实时显示收到的数据片段，无需等待整个工作流完成。
3. **格式化展示**：执行结果页面会以美化缩进（Pretty Print）的方式展示 JSON 数据，层级关系清晰可读。
4. **大数据量**：如果 JSON 数据量非常大（如包含大量数组元素），展示时可能会被截断。核心数据建议控制在合理范围内。
5. **非 JSON 数据**：如果通过某种方式传入了无法解析为 JSON 的数据，节点会展示原始内容并标记格式异常。
