# 代码沙箱

## 功能说明

代码沙箱节点为工作流中的 Agent 提供一个隔离的代码执行环境。沙箱基于容器化技术，运行在独立的 Linux 环境中，Agent 可以在其中编写和运行代码、操作文件系统、执行终端命令。

沙箱环境与你的本地机器完全隔离，Agent 在沙箱中的任何操作都不会影响外部系统。

## 使用场景

- **代码开发**：让 Agent 在沙箱中编写、运行和调试代码。
- **数据处理**：Agent 编写脚本处理数据文件并生成结果。
- **多 Agent 协作**：多个 Agent 节点共享同一个沙箱，前一个 Agent 创建的文件后一个 Agent 可以继续操作。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口，前序节点完成后创建或恢复沙箱会话 |
| 工作区 | volume | 否 | 可选挂载持久化工作区，沙箱内的文件读写将保存到该工作区 |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口，沙箱准备完成后触发下游节点 |
| 沙箱 | sandbox | 提供隔离的代码执行环境（可连接到多个 Agent） |

## 配置项

### 资源限制

| 配置 | 默认值 | 说明 |
|------|--------|------|
| CPU | 1 核 | 沙箱可使用的 CPU 核心数 |
| Memory | 512 MB | 沙箱可使用的内存上限 |
| Disk | 2 GB | 沙箱可使用的磁盘空间 |
| Timeout | 2 小时 | 沙箱的最大存活时间 |

### 生命周期模式

| 模式 | 说明 |
|------|------|
| session | 会话模式（默认）。沙箱在最后一个直接使用它的节点完成后销毁。适合一次性执行的场景。 |
| persistent | 持久模式。沙箱在节点解绑后回到就绪状态，可被后续执行复用。适合需要保持环境状态的场景。 |

### 持久化沙箱

在持久模式下，你可以选择一个已有的持久化沙箱来复用。

> 界面提示：配置面板中会列出可用的持久化沙箱（状态为 ready 或 stopped 的），你可以选择其中一个进行绑定。

## 使用示例

### 示例一：为单个 Agent 提供沙箱

1. 放置一个 **沙箱** 节点，使用默认配置。
2. 放置一个 **Agent** 节点，在配置面板中选择一个已发布且采用 sandbox 运行模式的 Agent。
3. 将沙箱的"沙箱"输出端口连接到 Agent 节点的"沙箱"输入端口。
4. Agent 在执行时可以在沙箱中运行代码、操作文件。

### 示例二：多 Agent 共享沙箱

让"架构师 Agent"和"开发者 Agent"在同一个环境中协作：

1. 放置一个 **沙箱** 节点。
2. 放置两个 **Agent** 节点（架构师和开发者）。
3. 将沙箱的输出端口分别连接到两个 Agent 节点的沙箱输入端口。
4. 架构师 Agent 先在沙箱中创建项目结构，然后开发者 Agent 在同一环境中编写代码。

### 示例三：持久化工作区

1. 放置一个 **工作区** 节点，选择已有的持久化工作区。
2. 放置一个 **沙箱** 节点。
3. 将工作区的"工作区"输出端口连接到沙箱的"工作区"输入端口。
4. 沙箱内的文件操作会保存到持久化工作区，即使沙箱销毁文件也不会丢失。

## 注意事项

1. **一个沙箱可供多个 Agent 使用**：沙箱的"沙箱"输出端口支持多连接，可以同时为多个下游 Agent 节点提供执行环境。
2. **资源共享**：多个 Agent 共享沙箱时，CPU 和内存是共享的。如果多个 Agent 都有较重的计算需求，建议适当增加资源配置。
3. **超时控制**：沙箱有最大存活时间。超时后沙箱会被自动清理。对于长时间运行的任务，需要调大超时配置。
4. **容器环境**：沙箱基于 Linux 容器（Arch Linux），预装了常用的开发工具和运行时。Agent 还可以通过终端安装额外的软件包。
5. **文件安全**：沙箱中的文件在会话模式下会随沙箱销毁而丢失。如果需要保留重要文件，请使用持久化工作区或在沙箱销毁前导出文件。
6. **终端并发限制**：每个沙箱最多支持 5 个并发终端会话，每个终端默认最大存活时间为 300 秒。
