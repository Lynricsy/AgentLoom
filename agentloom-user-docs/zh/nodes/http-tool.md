# HTTP 请求

## 功能说明

HTTP 请求节点用于在工作流中发送 HTTP 请求到外部 API 或 Web 服务。它支持常见的 HTTP 方法（GET、POST、PUT、PATCH、DELETE），可以配置请求头、查询参数、请求体和认证方式。你可以用它来集成第三方服务、获取外部数据、或向外部系统推送结果。

## 使用场景

- **调用第三方 API**：获取天气数据、股票信息、翻译服务等外部 API 的数据。
- **推送通知**：向 Slack、飞书、企业微信等消息平台发送通知。
- **数据同步**：将工作流的处理结果写入外部数据库或存储服务。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口 |
| 请求体 | json | 否 | HTTP 请求发送的 JSON Body 数据 |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口 |
| 响应体 | json | HTTP 响应返回的 JSON Body 数据 |

## 配置项

### 基本配置

| 配置 | 必需 | 说明 |
|------|------|------|
| URL | 是 | 请求的目标地址。支持包含查询参数的完整 URL |
| HTTP 方法 | 是 | GET、POST、PUT、PATCH 或 DELETE |
| 超时时间 | 否 | 请求超时时间（秒），默认 30 秒 |

### 请求头（Headers）

以键值对的形式配置请求头。

> 界面提示：配置面板中有一个请求头编辑区，支持添加、删除键值对。

常见请求头示例：

| Header | 值 | 说明 |
|--------|----|------|
| Content-Type | application/json | 指定请求体格式 |
| Accept | application/json | 指定期望的响应格式 |

### 查询参数（Query Params）

以键值对的形式配置 URL 查询参数。配置的参数会自动拼接到 URL 后面。

### 请求体（Body）

对于 POST、PUT、PATCH 方法，你可以配置请求体内容。请求体以 JSON 格式编写。

此外，如果将上游节点的输出连接到"请求体"输入端口，端口接收的数据会作为请求的 JSON Body 发送。

### 认证方式

| 方式 | 说明 |
|------|------|
| none | 无认证 |
| bearer | Bearer Token 认证，在请求头中添加 `Authorization: Bearer <token>` |
| basic | HTTP Basic 认证，使用用户名和密码 |
| api-key | API Key 认证，在请求头或查询参数中添加密钥 |

## 使用示例

### 示例一：获取外部 API 数据

创建一个获取天气信息的工作流步骤：

1. 放置一个 **HTTP 请求** 节点。
2. 配置 URL 为天气 API 的端点，方法为 GET。
3. 在查询参数中添加城市名称和 API Key。
4. 将响应体输出连接到下游的 Agent 节点，让 AI 解读天气数据。

### 示例二：向 Slack 发送通知

1. 放置一个 **HTTP 请求** 节点。
2. URL 设为 Slack 的 Incoming Webhook URL。
3. 方法设为 POST。
4. 将上游 Agent 的输出通过输入端口传入，作为 Slack 消息的 Body。

## 注意事项

1. **查询参数保留**：如果 URL 中已经包含查询参数（如 `?key=value`），配置面板中额外添加的查询参数会正确追加，不会覆盖 URL 中已有的参数。
2. **超时处理**：默认超时为 30 秒。对于响应较慢的 API，记得调大超时时间。超时后节点会报错。
3. **错误处理**：当 HTTP 请求返回非 2xx 状态码时，节点会将响应信息传递到输出端口（如果有的话），但同时会标记为执行失败。建议在下游使用条件分支处理可能的错误响应。
4. **敏感信息**：API Key 和认证令牌属于敏感信息。建议使用认证配置而不是直接将密钥写在 URL 或请求头中。
5. **响应格式**：输出端口期望 JSON 格式的响应。如果外部 API 返回非 JSON 格式，可能需要额外处理。
