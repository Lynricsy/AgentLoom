# LLM Agent 节点

## 功能说明

LLM Agent 节点（在画布中显示为 "Chat Agent"）是工作流中最核心的 AI 推理节点。它允许你在工作流内直接配置大语言模型的参数，让 Agent 执行对话、推理和决策任务。你可以为它设置系统提示词、连接模型、挂载工具和知识库，使其在工作流的某个步骤中完成复杂的 AI 处理。

与 Agent 节点不同，LLM Agent 节点的所有配置都内嵌在工作流中，不依赖外部的 Agent 定义。

## 使用场景

- **内容生成**：根据上游输入的主题或大纲，让 LLM 生成文章、报告、邮件等文本内容。
- **数据分析与决策**：接收结构化数据，让 LLM 进行分析并给出决策建议。
- **多步骤推理链**：在工作流中串联多个 LLM Agent 节点，前一个节点的输出作为后一个节点的输入，逐步深化分析。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口，前序节点完成后触发此节点 |
| 消息 | json | 否 | 传入的对话消息列表，包含历史消息用于多轮对话 |
| 模型 | model | 否 | 指定使用的 LLM 模型，决定推理能力和成本 |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口，节点完成后触发下游节点 |
| 回复 | text | Agent 生成的自然语言文本回复 |
| 结构化 | json | Agent 按 Schema 约束输出的结构化 JSON 数据 |

## 配置项

### 系统提示词（System Prompt）

定义 Agent 的角色和行为准则。这是影响 LLM 输出质量最关键的配置。

> 界面提示：配置面板中提供了一个代码编辑器用于编写系统提示词，支持语法高亮。

### 自主决策模式（Autonomy Mode）

控制 Agent 在需要调用工具或做出决策时的行为。

| 模式 | 说明 |
|------|------|
| MANUAL_CONFIRM | 手动确认 — 所有工具调用都需要用户审批 |
| RULE_BASED | 规则匹配 — 根据预设规则自动决策 |
| LLM_SUGGEST | LLM 建议 — 由 LLM 自行判断是否需要确认 |

### 确认阈值（Confirmation Threshold）

数值范围 0 到 1。当推断置信度低于此阈值时，需要人工确认。默认值为 0.8。

### 回退策略（Fallback Strategy）

当 Agent 无法完成自主决策时的处理方式。

| 策略 | 说明 |
|------|------|
| REQUIRE_CONFIRMATION | 保留待确认项，等待人工继续 |
| USE_DEFAULT | 使用预设默认值补齐字段 |
| SKIP_FIELD | 跳过当前字段，继续执行 |
| ABORT_EXECUTION | 终止执行 |

### 允许推断字段（Allowed Inference Fields）

在规则匹配或 LLM 建议模式下，指定允许 Agent 自动推断的字段路径白名单。

## 使用示例

### 示例一：简单的文本处理

创建一个工作流，将用户输入的文本翻译成英文：

1. 放置一个 **手动触发器** 节点作为入口。
2. 放置一个 **LLM Agent** 节点，设置系统提示词为"你是一名专业翻译，请将用户输入的中文翻译成英文。只返回翻译结果，不要添加解释。"
3. 连接一个 **LLM 模型** 节点到 LLM Agent 的模型端口。
4. 放置一个 **文本输出** 节点接收翻译结果。
5. 用连线将执行流和数据端口按顺序连接。

### 示例二：多步推理链

创建一个代码审查工作流：

1. **LLM Agent 1**（角色：代码分析师）— 分析代码结构和潜在问题。
2. **LLM Agent 2**（角色：安全专家）— 基于分析结果检查安全隐患。
3. **LLM Agent 3**（角色：报告生成器）— 将所有发现整合为一份结构化审查报告。

每个节点的输出连接到下一个节点的输入，形成逐步深化的推理链。

## 注意事项

1. **模型连接**：如果不连接 LLM 模型节点，Agent 将使用系统默认模型。建议总是显式连接一个模型节点以确保行为可预测。
2. **提示词长度**：系统提示词会占用 LLM 的上下文窗口。过长的提示词会压缩可用于输入和输出的 Token 空间。
3. **自主决策模式**：在自动化工作流中（如定时触发），建议使用 RULE_BASED 或 LLM_SUGGEST 模式，因为 MANUAL_CONFIRM 模式会阻塞等待人工操作。
4. **组织级策略上限**：自主决策模式可能受组织级策略的约束。如果组织策略上限为 RULE_BASED，即使节点配置为 LLM_SUGGEST 也会被降级执行。
