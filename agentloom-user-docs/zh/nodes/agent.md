# Agent 节点

## 功能说明

Agent 节点用于在工作流中引用一个已创建并发布的独立 Agent 定义，直接复用该 Agent 的系统提示词、模型配置、工具绑定、知识库、记忆等能力。

这使得你可以先精心调优一个 Agent，然后在多个工作流中反复引用它，保持行为的一致性。

## 使用场景

- **复用已有 Agent**：你已经创建了一个"代码审查专家" Agent 并精心调优了它的提示词和工具配置。现在你想在代码审查工作流、CI/CD 工作流、PR 审核工作流中都使用这个 Agent。
- **Agent 流水线**：将多个专业 Agent 串联在一起，形成一条处理流水线。例如"需求分析 Agent" -> "架构设计 Agent" -> "代码生成 Agent"。
- **带记忆的工作流节点**：独立 Agent 可以携带长期记忆。在工作流中使用 Agent 节点，Agent 可以利用它在独立对话中积累的知识。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口，前序节点完成后触发 Agent 执行 |
| 文本 | text | 是 | 发送给 Agent 的输入文本，通常来自上游节点 |
| 系统提示词 | text | 否 | 临时覆盖 Agent 定义自带的系统提示词 |
| 沙箱 | sandbox | 否 | 绑定沙箱执行环境（仅 sandbox 模式的 Agent 可用） |
| 上下文 | json | 否 | 传入附加上下文 JSON 数据，Agent 推理时可作为参考 |
| Skills | skill | 否 | 启用额外的技能模板（可连接多个） |
| 扩展工具 | tool | 否 | 额外挂载 MCP 工具（可连接多个） |
| 子 Agent | agent | 否 | 注册子 Agent（可连接多个） |
| Schema | json | 否 | 定义 Agent 输出的 JSON Schema，约束回复格式 |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口，Agent 完成后触发下游节点 |
| 回复 | text | Agent 生成的自然语言文本回复（可连接多个下游） |
| 结构化 | json | Agent 按 Schema 约束输出的结构化 JSON 数据（可连接多个下游） |

## 配置项

### Agent 选择

在配置面板中，你需要从已发布的 Agent 列表中选择一个 Agent。

> 界面提示：配置面板提供搜索框用于按名称筛选 Agent。列表只显示已发布状态的 Agent。

### 版本选择

选择 Agent 后，你可以指定使用哪个已发布的版本。默认使用最新的已发布版本。

### 输入映射

你可以配置字段映射关系，指定工作流数据如何传递到 Agent 的输入参数。映射以键值对形式设置。

### 临时覆盖系统提示词

Agent 自身的系统提示词来自所绑定的 Agent 定义。如果只想在当前工作流中临时覆盖它，可以添加一个**文本节点**，将文本节点的“文本”输出连接到 Agent 节点的“系统提示词”输入端口。此设置只作用于该工作流中的这次引用，不会修改 Agent 定义。

## 使用示例

### 示例一：复用代码助手 Agent

假设你已经创建了一个名为"前端代码助手"的 Agent，配置了 React 相关的系统提示词和工具。

1. 在工作流画布上放置一个 **Agent 节点**。
2. 在配置面板中搜索并选择"前端代码助手"。
3. 将触发器的文本输出连接到 Agent 节点的"文本"输入端口。
4. 将一个沙箱节点连接到 Agent 节点的"沙箱"端口（如果 Agent 需要执行代码）。
5. 将 Agent 节点的"回复"端口连接到文本输出节点。

### 示例二：多 Agent 协作流水线

创建一个文档生成工作流：

1. **Agent 节点 A**（引用"需求分析师" Agent）— 将用户需求拆解为结构化的功能列表。
2. **Agent 节点 B**（引用"技术文档专家" Agent）— 根据功能列表生成技术文档。
3. 将 A 的文本输出连接到 B 的文本输入。
4. 两个节点共享同一个沙箱，文档专家可以直接在沙箱中创建 Markdown 文件。

## 注意事项

1. **必须先发布**：Agent 节点只能引用已发布的 Agent。如果列表为空，说明你还没有发布过 Agent。请先到 Agent 管理页面创建并发布一个 Agent。
2. **必须完成绑定**：每个 Agent 节点都必须选择一个 Agent。存在未绑定节点时，服务端会拒绝发布工作流（HTTP 422），并逐个指出未绑定的节点。
3. **版本锁定**：选择特定版本后，Agent 节点会固定使用该版本。即使后续发布了新版本，也不会自动切换。需要手动更新。
4. **模型由 Agent 决定**：节点上没有模型输入端口。LLM 模型节点和智能路由节点的模型输出都不能连接到 Agent 节点；如需更换模型，请到所绑定 Agent 的配置中修改并发布。
5. **运行时模式适配**：如果选择的 Agent 运行时模式为 `no_sandbox`，配置面板中的沙箱端口会自动隐藏。
6. **额外能力叠加**：通过端口连接的技能、工具和子 Agent 是叠加在 Agent 定义之上的额外能力，不会覆盖 Agent 原有的配置。
7. **结构化输出**：如果需要 Agent 返回特定格式的 JSON，需要通过 Schema 端口传入 JSON Schema。否则 Agent 会以自然语言形式回复。
