# 条件分支

## 功能说明

条件分支节点根据你定义的条件表达式，将工作流的执行路径引导到不同的分支。它类似于编程中的 `if/else if/else` 语句——根据数据满足的条件，选择不同的处理路径。

条件分支节点支持多个分支规则，按从上到下的优先级顺序匹配。如果所有条件都不满足，数据会走"ELSE"兜底分支。

## 使用场景

- **请求分类**：根据用户输入的类型（编程问题、文档任务、数据分析等）路由到不同的 Agent 节点处理。
- **结果过滤**：根据上游 AI 的判断结果（满意/不满意、通过/不通过）选择后续处理步骤。
- **错误处理**：根据 HTTP 请求返回的状态码选择成功路径或错误处理路径。

## 端口说明

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口 |
| 输入 1 | json（接受任意类型） | 否 | 第一个条件输入口，接收上游数据用于条件判断 |
| 输入 2 ~ 输入 N | json（接受任意类型） | 否 | 可动态添加更多输入口 |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| IF | json | 第一个条件匹配时从此分支输出 |
| ELSE IF (可选) | json | 后续条件匹配时从对应分支输出 |
| ELSE | json | 所有条件都不满足时走此兜底分支 |

## 配置项

### 分支规则

每个分支（IF、ELSE IF）都有一组条件规则。条件分支支持两种配置模式。

**可视化模式**

以表单方式配置条件规则，不需要编写表达式。每条规则包含：

- 输入源（选择哪个输入端口的数据）
- 字段路径（指定判断哪个字段）
- 比较运算符（等于、不等于、包含、大于、小于等）
- 比较值

多条规则之间可以用 AND 或 OR 逻辑连接。

**表达式模式**

使用表达式语法编写条件。适合复杂的判断逻辑。

### 添加和管理分支

> 界面提示：在配置面板中，你可以通过"添加分支"按钮增加更多的 ELSE IF 分支。每个分支可以通过上下箭头调整优先级顺序，也可以删除（第一个 IF 分支不可删除）。

### 分支优先级

条件匹配的顺序为从上到下：

1. 首先检查 IF 分支的条件。
2. 如果不满足，依次检查 ELSE IF 分支。
3. 如果所有分支条件都不满足，数据走 ELSE 分支。
4. 一旦某个分支匹配成功，后续分支不再检查。

## 使用示例

### 示例一：按请求类型分流

根据用户输入中的关键词将任务路由到不同的 Agent：

1. 将触发器的输出连接到条件分支的输入端口。
2. 配置 IF 分支条件：输入文本包含 "代码" 或 "编程"。
3. 添加 ELSE IF 分支条件：输入文本包含 "文档" 或 "写作"。
4. ELSE 分支作为默认处理。
5. 将 IF、ELSE IF、ELSE 的 JSON 输出分别连接到对应 Agent 的「上下文」端口；同时为每个 Agent 的必需「文本」端口提供任务指令。

### 示例二：基于 API 响应做决策

根据 HTTP 请求节点返回的状态判断后续操作：

1. 将 HTTP 请求的 JSON 响应连接到条件分支。
2. IF 条件：`status` 字段等于 `"success"`。
3. ELSE 分支处理失败情况。
4. IF 分支连接后续数据处理节点，ELSE 分支连接错误通知节点。

## 注意事项

1. **ELSE 兜底**：ELSE 分支始终存在且不可删除。即使你认为所有情况都被 IF/ELSE IF 覆盖了，ELSE 仍然作为安全网存在。建议为 ELSE 分支连接适当的处理逻辑。
2. **输入端口可扩展**：默认有一个输入端口，你可以在配置中添加更多输入端口来接收不同来源的数据，并在条件规则中引用它们。
3. **数据透传**：满足条件的分支会将输入数据透传给该分支的下游节点。数据本身不会被修改。
4. **类型兼容**：条件输入端口接受任意数据类型（标记为 json 但设置了 acceptsAnyDataType），这意味着你可以连接 text、json 等多种类型的上游端口。
