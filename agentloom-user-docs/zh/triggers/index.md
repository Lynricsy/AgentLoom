# 自动化触发

触发器（Trigger）是 AgentLoom 中用于自动启动工作流执行的机制。通过配置触发器，你可以让工作流在特定条件满足时自动运行，无需手动点击执行按钮。

## 触发器概述

在日常使用中，你可能需要工作流在以下场景下自动运行：

- 每天早上 9 点自动生成数据报告
- 当代码仓库收到新的提交时自动执行代码审查
- 当外部系统发生特定事件时自动触发处理流程

触发器就是用来实现这些自动化需求的。每个工作流可以配置多个触发器，它们独立工作，互不影响。

## 三种触发器类型

AgentLoom 支持三种触发器类型，适用于不同的自动化场景：

### 定时触发（Cron）

按照预设的时间表定期执行工作流。使用标准的 cron 表达式定义执行计划，支持从「每分钟」到「每年一次」的各种时间粒度。

- **典型场景**：定时报告生成、周期性数据处理、定时巡检
- **特点**：完全自主，不依赖外部信号

详细说明请参考 [定时触发](./cron.md)。

### Webhook 触发

通过 HTTP 请求触发工作流执行。AgentLoom 为每个 Webhook 触发器生成一个唯一的 URL，外部系统向这个 URL 发送请求即可触发工作流。

- **典型场景**：CI/CD 流程集成、表单提交后处理、第三方服务回调
- **特点**：由外部系统主动发起，支持签名验证确保安全

详细说明请参考 [Webhook 触发](./webhook.md)。

### API 事件触发

监听通过 AgentLoom API 接口发送的事件，当事件匹配预设条件时触发工作流。支持 GitHub Webhook 和通用事件两种适配器。

- **典型场景**：GitHub 仓库事件处理、跨系统事件驱动、自定义事件总线
- **特点**：支持事件来源识别和类型匹配，有专门的安全验证

详细说明请参考 [API 事件触发](./api-event.md)。

## 三种类型对比

| 对比项 | 定时触发 | Webhook 触发 | API 事件触发 |
|--------|---------|-------------|-------------|
| 触发方式 | 按时间表自动触发 | 接收 HTTP 请求触发 | 接收 API 事件触发 |
| 触发来源 | 系统内部定时器 | 任意外部系统 | AgentLoom API 入口 |
| 安全机制 | 无需额外配置 | Token 验证 / 签名验证 | 事件源适配器验证 |
| 携带数据 | 无额外数据 | HTTP 请求体 | 事件载荷 |
| 适用场景 | 周期性任务 | 外部系统集成 | 事件驱动架构 |
| 配置复杂度 | 低 | 中 | 中高 |

## 选择建议

### 选择定时触发的情况

- 任务需要定期运行，与外部事件无关
- 执行频率是固定的，例如每天、每周、每小时
- 不需要外部系统发送信号

### 选择 Webhook 触发的情况

- 需要与已有的第三方服务或内部系统集成
- 外部系统支持配置 Webhook 回调 URL
- 希望用最简单的方式实现外部触发

### 选择 API 事件触发的情况

- 需要集成 GitHub 等平台的 Webhook 事件
- 需要对事件来源和类型进行精确匹配
- 需要构建事件驱动的自动化体系

## 通用配置

无论选择哪种触发器类型，都需要设置以下基本信息：

- **名称**（必填）：为触发器设置一个清晰的名称，最长 255 个字符
- **描述**（选填）：说明触发器的用途和触发条件，最长 2000 个字符
- **启用状态**：触发器创建后默认启用。你可以随时切换启用/禁用状态

## 触发器的管理

### 创建触发器

触发器是绑定在工作流上的。要创建触发器，你需要先进入工作流的设置页面。

> 界面提示：在工作流编辑页面中，找到触发器管理区域，点击「创建触发器」按钮。

创建触发器需要所有者（Owner）、管理员（Admin）或创建者（Creator）角色。

### 查看触发器列表

> 界面提示：在工作流的触发器管理区域，可以看到该工作流下所有触发器的列表，包括类型、状态和基本配置信息。

### 启用与禁用

你可以随时切换触发器的启用状态。禁用后的触发器不会触发工作流执行，但配置信息会被保留，方便后续重新启用。

### 查看执行历史

每个触发器都记录了完整的触发历史，帮助你了解触发器的工作情况：

- **成功（Success）**：触发成功并启动了工作流执行
- **失败（Failed）**：触发过程中出现错误
- **跳过（Skipped）**：触发条件满足但因其他原因（如工作流未发布）未执行
- **签名失败（Signature Failed）**：Webhook 签名验证未通过（仅 Webhook 类型）

### 删除触发器

如果不再需要某个触发器，可以将其删除。删除操作不可撤销。

## 注意事项

- 触发器创建后，工作流需要处于已发布状态才能被触发执行
- 一个工作流可以配置多个触发器，它们独立工作
- 触发器的执行遵循组织的资源配额限制（如并发执行数、日执行量上限等）
- 触发产生的工作流执行会计入组织的执行统计
