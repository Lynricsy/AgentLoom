# 运行与监控

工作流搭建完成后，下一步就是运行它。本页详细介绍如何触发工作流执行、理解执行状态、利用实时监控功能跟踪运行进度，以及如何查看各节点的执行结果。

---

## 触发工作流执行

### 手动运行

手动运行是最直接的触发方式，适合开发和测试阶段。

1. 打开工作流的画布编辑器页面。

2. 找到画布顶部版本工具栏中的"运行"按钮（蓝色按钮，带播放图标）。

> 界面提示：运行按钮位于版本工具栏的最右侧区域。只有在工作流未归档的情况下才能看到此按钮。

3. 点击"运行"按钮：
   - 如果工作流没有定义输入参数，执行会立即开始
   - 如果定义了输入参数，系统会先弹出参数收集界面，要求你填写输入数据后再开始执行

4. 运行按钮会变为"执行中"状态，显示加载动画，此时无法重复点击。

### 通过触发器自动运行

除了手动运行，工作流还支持三种自动触发方式。你需要先在版本工具栏中点击"触发器"按钮来配置它们。

**定时触发 (Schedule)**

通过 Cron 表达式定义运行时间表。例如：
- 每天早上 8 点运行：`0 8 * * *`
- 每周一上午 9 点运行：`0 9 * * 1`
- 每小时运行一次：`0 * * * *`

配置时可以指定时区（默认 UTC）。

**Webhook 触发**

生成一个 Webhook URL，外部系统向该 URL 发送 HTTP 请求即可触发工作流。支持配置鉴权模式（简单模式或签名模式）和 IP 白名单。

**API 事件触发**

监听来自外部平台的 API 事件。例如配置监听 GitHub 的 Push 事件或 PR 事件。你需要指定事件来源、事件类型和可选的过滤表达式。

> 注意：触发器需要工作流处于"已发布"状态才能生效。如果工作流还是草稿，触发器虽然可以配置但不会实际运行。

### 通过 API 运行

如果你的系统需要程序化地触发工作流，可以使用 AgentLoom 的 REST API。通过 `POST /api/v1/workflow-definitions/:id/run` 接口发送请求即可启动执行。调用时需要提供 API Key（在设置中创建）或 JWT 认证。

## 理解执行状态

每次工作流运行都会经历多个状态阶段。了解这些状态有助于你判断工作流的运行情况。

### 整体执行状态

| 状态 | 显示 | 说明 |
|------|------|------|
| pending | 等待中 | 执行已创建，系统正在准备运行环境 |
| queued | 排队中 | 等待系统分配资源（在高并发时可能出现） |
| running | 执行中 | 工作流正在运行，节点依次或并行执行 |
| completed | 已完成 | 所有节点成功执行完毕，工作流结束 |
| failed | 失败 | 运行过程中某个节点出错，导致执行中断 |
| cancelled | 已取消 | 用户手动取消了本次执行 |

> 界面提示：执行状态在画布底部状态栏中实时显示，附带进度信息（如"执行中 (2/5)"表示 5 个节点中已完成 2 个）。

### 节点级执行状态

在工作流运行过程中，每个节点也有自己的状态：

| 状态 | 显示 | 说明 |
|------|------|------|
| pending | 等待中 | 节点尚未开始运行 |
| queued | 排队中 | 等待前序节点完成 |
| running | 执行中 | 节点正在运行 |
| completed | 已完成 | 节点成功完成 |
| failed | 失败 | 节点执行出错 |
| skipped | 已跳过 | 节点在本次执行中被跳过（如条件分支未走到的路径） |
| cancelled | 已取消 | 节点执行被取消 |
| waiting_intervention | 等待干预 | 节点需要人工审批后才能继续 |

## 实时监控

AgentLoom 提供了实时的执行监控能力。你不需要刷新页面 -- 所有状态更新和输出内容都会自动推送到你的界面。

### 画布实时反馈

工作流运行时，画布上的节点会实时显示执行状态：

- **等待中的节点**：保持默认外观
- **正在运行的节点**：显示高亮边框和运行动画
- **已完成的节点**：显示绿色的完成标记
- **失败的节点**：显示红色的错误标记
- **被跳过的节点**：显示灰色的跳过标记

这种视觉反馈让你可以直观地看到执行"流过"整个工作流的过程。

### 状态栏进度

画布底部的状态栏会实时显示执行进度。例如：

- "执行中 (0/5)" -- 刚开始，5 个节点都还没完成
- "执行中 (3/5)" -- 5 个节点中已有 3 个完成
- "已完成" -- 全部执行成功

### 节点属性面板实时更新

选中某个节点后，右侧属性面板的"实时执行"区段会持续更新：

**运行中的节点**：
- 状态显示为"执行中"（带高亮标记）
- 流式状态显示为"接收中"
- 输出流区域实时显示 Agent 正在生成的文本（逐字逐句出现）

**完成后的节点**：
- 状态切换为"已完成"
- 显示开始时间和完成时间
- 输出流显示完整的输出结果

**失败的节点**：
- 状态显示为"失败"（红色标记）
- 展示错误信息区块，包含具体的错误描述

### 工具调用监控

如果 Agent 在运行过程中调用了工具（如 HTTP 请求、代码执行等），工具调用的列表会实时出现在属性面板的执行区段中。你可以查看每次工具调用的参数和结果。

### 人工干预

如果工作流配置了介入策略，某些 Agent 的工具调用可能需要你手动审批。

当出现需要干预的情况时：
1. 节点状态变为"等待干预"（黄色标记）
2. 属性面板会显示干预面板，展示需要审批的操作详情
3. 你可以选择"批准"让操作继续，或"拒绝"阻止该操作
4. 处理完成后，节点会继续执行或根据策略执行后续动作

## 查看节点执行结果

### 在画布中查看

执行完成后，你可以在画布上点击任意节点，在右侧属性面板中查看该节点的执行结果。

属性面板的"实时执行"区段包含：

- **步骤 ID**：此节点在本次执行中的唯一标识
- **执行状态**：已完成/失败/已跳过等
- **重试进度**：如果发生了自动重试，显示重试次数（如 1/3）
- **开始时间**和**完成时间**
- **执行错误**：如果节点失败，显示错误详情
- **工具调用列表**：Agent 发起的所有工具调用及其结果
- **输出流**：节点产生的文本输出

**输出流内容说明**：

| 节点状态 | 输出流显示 |
|---------|-----------|
| 正在流式输出 | "正在接收实时输出..."并持续显示新内容 |
| 已完成 | 显示完整的输出文本 |
| 已完成但无输出 | "该节点已完成，但这次运行没有文本输出。" |
| 失败 | "节点执行失败，暂无可展示的输出内容。" |
| 等待干预 | "节点正在等待人工干预，恢复后会继续写入输出。" |
| 已跳过 | "该节点在本次执行中被跳过，没有产生输出。" |
| 已取消 | "该节点执行已取消，没有产生输出。" |
| 空闲（未运行） | "选择节点后，这里会显示最近一次执行输出。" |

### 在执行调试页面查看

对于更详细的分析，你可以进入执行调试页面。在工作流运行完成后，执行记录会出现在执行历史中。

> 界面提示：执行调试页面的路径为 `/executions/执行ID`。你可以从工作流编辑器或执行历史中跳转到该页面。

执行调试页面提供三栏布局：

**左栏 -- 只读画布**
- 展示执行时刻的工作流快照
- 节点上叠加显示执行状态

**中栏 -- 执行时间线**
- 按时间顺序列出每个节点的执行记录
- 每条记录包含：节点名称、状态、持续时间、输入输出摘要
- 失败的节点会以醒目的样式显示错误信息

**右栏 -- 节点详情**
- 选中时间线中某个节点后，右栏显示详细信息
- 包含完整的输入数据、输出数据、工具调用历史
- 对于 Agent 节点，可以查看完整的对话消息和工作区文件

## 执行历史

AgentLoom 会记录工作流的所有执行历史。你可以随时回顾之前的运行记录。

### 查看执行历史

在画布编辑器中，你可以通过执行历史面板查看当前工作流的所有执行记录。每条记录显示：

- 执行 ID
- 执行状态（成功/失败/取消等）
- 启动时间
- 持续时长
- 触发来源（手动/定时/Webhook 等）

点击任意记录可以进入对应的执行调试页面。

## 取消运行中的执行

如果你发现一次执行存在问题，或者不再需要其结果，可以取消正在运行的执行。

取消执行后：
- 所有正在运行的节点会被中断
- 尚未开始的节点不会再执行
- 执行状态变为"已取消"
- 已完成节点的输出结果仍然保留

## 常见问题

### 运行按钮是灰色的/不可点击？

可能的原因：
- 工作流已归档（归档状态下不能运行）
- 当前已有一次执行正在进行中
- 画布上没有任何节点

### 执行一直停在"等待中"？

可能的原因：
- 系统资源繁忙，正在排队等待
- 检查是否有资源配额限制（在"设置 > 资源配额"页面查看）

### 某个节点执行失败了怎么办？

1. 点击失败的节点，查看右侧面板中的错误信息
2. 根据错误信息调整节点配置
3. 重新运行工作流

详细的排查方法请参考 [调试工作流](./debugging.md)。
