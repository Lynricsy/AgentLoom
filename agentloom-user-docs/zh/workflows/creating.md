# 创建工作流

本页详细介绍如何在画布编辑器中创建和编辑工作流，包括新建工作流、添加和管理节点、连接端口、以及画布操作技巧。

---

## 新建工作流

### 从空白创建

1. 在工作流列表页面（`/workflows`），点击右上角的"新建工作流"按钮。

2. 在弹出的对话框中填写：
   - **名称**（必填）：为工作流起一个清晰的名字，如"客户反馈自动分类"
   - **描述**（可选）：简要说明工作流的用途
   - **图标**（可选）：点击名称左侧的图标区域，选择一个自定义图标，方便在列表中辨识

3. 点击"创建"按钮，系统会自动跳转到画布编辑器，面前是一个空白画布。

### 从其他来源创建

除了空白创建，你还可以通过以下方式创建工作流：

- **从模板创建**：在创建时选择一个预置模板，详见 [使用模板](./templates.md)
- **从分享链接创建**：打开他人的分享链接后复制工作流
- **从市场安装**：在市场页面安装社区工作流
- **从文件导入**：导入 `.agentloom-workflow.json` 文件，详见 [分享与导出](./sharing.md)

## 添加节点

### 从节点面板拖拽

这是添加节点最常用的方式。

1. 在画布左侧找到节点面板。节点按分类分组显示：

   | 分类 | 包含的节点 |
   |------|-----------|
   | Agent 智能体 | Chat Agent、LLM 模型、智能路由、Agent、Skill |
   | 工具 | HTTP Request、Code Executor、MCP Tool、Sandbox、输入预处理器、Workspace |
   | 触发器 | Manual Trigger、Schedule、Webhook、API Event |
   | 知识与记忆 | Knowledge Base、Memory |
   | 输出 | Text Output、JSON Output |
   | 流程控制 | Condition、Loop、Iteration、Merge、Reusable Block |

2. 找到你需要的节点类型，用鼠标按住该节点项。

3. 按住不放，将节点拖拽到画布中你想放置的位置。

4. 松开鼠标，节点就被添加到画布上了。

> 界面提示：部分节点类型（如循环内部的 Loop Start、Iteration Start、Loop State、Result、Break、Continue）不会出现在节点面板中，因为它们是由容器节点自动创建的。

### 通过右键菜单添加

在画布空白区域右键点击，会弹出上下文菜单，其中包含"添加节点"选项。这提供了另一种快速添加节点的方式。

---

## 管理节点

### 选中节点

单击画布上的节点即可选中。选中后：
- 节点会显示选中高亮效果
- 右侧会弹出属性配置面板
- 你可以在面板中修改节点的配置

### 移动节点

按住节点拖拽即可移动到新位置。移动节点时，已连接的边会自动跟随调整。

### 修改节点名称

选中节点后，在右侧属性面板的头部区域可以看到节点名称。点击名称即可编辑。给节点起有意义的名称有助于理解工作流的逻辑，例如将默认的"Chat Agent"改为"安全审查 Agent"。

### 删除节点

选中节点后，按键盘的 Delete 键或 Backspace 键即可删除。删除节点时，连接到该节点的所有边也会一并删除。

### 框选多个节点

在画布空白区域按住鼠标拖拽，可以画出一个矩形选区。选区内的所有节点会被同时选中，你可以一起移动或删除它们。

## 连接节点端口

连线是构建工作流的关键步骤。通过连线，你定义了数据在节点之间的传递路径和执行顺序。

### 如何连线

1. 将鼠标移到源节点的输出端口上，端口会高亮显示。

2. 按住鼠标左键，从输出端口开始拖拽。你会看到一条跟随鼠标移动的虚线。

3. 将虚线拖拽到目标节点的输入端口上。如果两个端口的数据类型兼容，目标端口会显示"可连接"的视觉提示。

4. 松开鼠标，连线建立成功。连线在画布上显示为一条平滑的曲线。

### 端口数据类型兼容规则

并非所有端口都能互相连接。系统会自动检查源端口和目标端口的数据类型是否兼容。

**基本规则**：相同数据类型的端口可以互连。例如：
- `text` 输出端口 -> `text` 输入端口
- `json` 输出端口 -> `json` 输入端口
- `model` 输出端口 -> `model` 输入端口
- `sandbox` 输出端口 -> `sandbox` 输入端口
- `knowledge` 输出端口 -> `knowledge` 输入端口
- `skill` 输出端口 -> `skill` 输入端口
- `tool` 输出端口 -> `tool` 输入端口
- `agent` 输出端口 -> `agent` 输入端口

**特殊规则**：
- 某些输入端口标记为"接受任意数据类型"（如条件分支节点的输入端口），可以接收任何类型的数据
- 执行流端口（箭头形状）只能与执行流端口连接，用于定义节点的执行顺序
- 某些端口支持多条连线（如 Agent 的"扩展工具"输入端口可以接收多个 MCP 工具的连线）

**连接被阻止时**：
如果你尝试连接不兼容的端口，系统会阻止连线并给出提示。这个检查机制帮助你避免构建出无法正确运行的工作流。

> 界面提示：AgentLoom 使用了类型引擎（Type Engine）来进行端口兼容性检查。不同的端口类型在画布上用不同的颜色和形状显示，帮助你在视觉上快速判断。

### 连接执行流

除了数据连线，大多数节点还需要连接"执行流"来定义运行顺序。

执行流端口通常显示为箭头形状，颜色与数据端口不同。它的作用是告诉执行引擎："这个节点完成后，接下来运行那个节点。"

**执行流的重要性**：
- 即使两个节点已经有数据连线，通常也需要额外的执行流连线
- 执行流决定了节点的运行顺序
- 没有入度执行流的节点会作为起始节点运行

### 删除连线

1. 点击画布上的连线将其选中（选中后连线会高亮）。
2. 按 Delete 键删除。

### 修改连线

如果需要修改一条连线的端点，最简单的方式是删除旧连线然后建立新连线。

## 配置节点

添加和连线完成后，需要对各节点进行参数配置。

### 打开配置面板

单击画布上的节点，右侧会弹出属性配置面板。不同类型的节点有不同的配置选项。

### 常见节点的配置要点

**Chat Agent 节点**
- **System Prompt**：定义 Agent 的角色和行为方式。这是最重要的配置项，好的提示词能大幅提升 Agent 的表现

**LLM 模型节点**
- 选择 AI 模型提供商和具体模型
- 配置模型参数（如温度、最大 token 数等）
- 需要先在"资源 > LLM 模型"页面添加模型配置

**HTTP Request 节点**
- **URL**（必填）：请求地址
- **Method**（必填）：HTTP 方法（GET/POST/PUT/PATCH/DELETE）
- **Headers**：请求头
- **Query Params**：查询参数
- **Body**：请求体
- **认证方式**：支持 none、Bearer Token、Basic Auth、API Key 四种

**Code Executor 节点**
- **语言**（必填）：TypeScript、JavaScript、Python 或 Bash
- **代码**：要执行的代码内容
- **超时时间**：执行超时限制（默认 30 秒）

**知识库节点**
- **Knowledge Base ID**（必填）：绑定的知识库。需要先在"资源 > 知识库"页面创建知识库

**Sandbox 节点**
- **CPU**：CPU 分配（默认 1 核）
- **Memory**：内存分配（默认 512MB）
- **Disk**：磁盘空间（默认 2GB）
- **Timeout**：会话超时（默认 2 小时）

**条件分支节点**
- 配置条件规则，定义数据满足什么条件时走哪个分支
- 默认有一个 IF 分支和一个 ELSE 兜底分支

### 无需配置的节点

某些节点（如 Text Output、JSON Output）不需要额外配置，它们会自动处理接收到的数据。选中这类节点时，配置面板会显示"该节点无需额外配置"。

## 画布操作技巧

### 平移画布

- **方法一**：按住空格键的同时拖拽鼠标
- **方法二**：使用鼠标中键拖拽
- **方法三**：在触控板上双指拖动

### 缩放画布

- **鼠标滚轮**：向上滚动放大，向下滚动缩小
- **触控板**：捏合手势缩放
- 当前缩放比例显示在画布底部状态栏中

### 使用小地图

画布右下角有一个小地图（MiniMap），以缩略图形式展示整个画布的全貌。

- 小地图上的蓝色矩形表示当前视口位置
- 点击小地图可以快速定位到画布的特定区域
- 当工作流节点较多时，小地图特别有用

### 搜索节点

画布提供了节点搜索功能。当工作流比较复杂时，可以通过搜索快速定位到某个节点。

### 自动保存

画布编辑器会自动保存你的修改。底部状态栏会显示当前的保存状态：

- 黄色圆点 + "未保存"：有未保存的修改
- 加载动画 + "保存中..."：正在保存
- 绿色勾号 + "已保存 . X 分钟前"：最后保存时间

自动保存只保存到当前草稿，不会创建版本快照。如果你想创建一个明确的保存点，请使用版本工具栏中的"保存快照"功能。

## 工作流设计建议

### 从简单开始

不要一开始就试图构建复杂的工作流。先用两三个节点验证核心逻辑，确认可行后再逐步扩展。

### 给节点起有意义的名称

默认的节点名称（如"Chat Agent"、"HTTP Request"）在节点较多时会难以区分。养成修改节点名称的习惯，比如改为"安全审查 Agent"、"获取用户数据"，这样画布上的流程一目了然。

### 注意连接执行流

数据连线和执行流连线都很重要。有时候你会发现工作流运行不符合预期，可能是因为忘记了连接执行流，导致节点的运行顺序不正确。

### 利用条件分支处理异常

在关键节点之后添加条件分支，根据执行结果决定后续走向。这样可以优雅地处理异常情况，而不是让整个工作流因为一个节点的异常输出而产生错误结果。

### 善用可复用块

如果某一组节点的组合在多个工作流中重复出现，可以将它们封装为"可复用块"。这样在不同的工作流中可以直接引用，避免重复搭建。
