# 输入参数

工作流的输入参数功能允许你为每次运行提供不同的数据。通过定义输入参数，同一个工作流可以在不同场景下复用，只需在运行时提供对应的输入即可。

---

## 什么是输入参数

输入参数是你为工作流预先定义的一组数据字段。当用户运行工作流时，系统会要求用户填写这些字段的值，然后将这些值传递给工作流中的各个节点使用。

**举个例子**：你创建了一个"客户反馈分类"工作流。每次运行时需要输入不同的反馈内容。你可以定义一个名为"反馈内容"的文本输入字段，这样每次运行时用户只需把具体的反馈文本粘贴进去就行了。

---

## 配置入口

在画布编辑器中，点击版本工具栏中的"输入参数"按钮来打开输入参数配置面板。

> 界面提示："输入参数"按钮位于版本工具栏中间区域，图标为滑块图标。点击后按钮会高亮，再次点击则关闭面板。按钮文字会在打开时变为"隐藏输入参数"。

## 三种输入收集模式

AgentLoom 支持三种输入收集模式，你需要在配置时选择最适合你场景的模式。

### 表单模式 (form)

这是最常用的模式。用户在运行工作流前会看到一个表单界面，依次填写你定义的各个字段。

**适用场景**：
- 输入数据结构明确（如选择一种语言、填写一个URL、输入一段代码）
- 用户一次性提供所有参数
- 需要对输入做格式校验（长度、范围等）

**工作方式**：
1. 用户点击"运行"按钮
2. 系统弹出表单，显示你定义的所有字段
3. 用户逐一填写，点击提交
4. 工作流使用填写的数据开始执行

### 对话模式 (conversation)

对话模式下，系统通过一轮或多轮对话来收集输入参数。适合参数之间有依赖关系或需要引导用户逐步提供信息的场景。

**适用场景**：
- 输入内容开放式，不好用固定的表单字段框定
- 需要根据用户回答动态调整后续问题
- 希望用更自然的方式引导用户提供信息

**工作方式**：
1. 用户点击"运行"按钮
2. 系统启动一个对话界面，按照预设的对话计划提问
3. 用户逐轮回答问题
4. 对话完成后（达到最大轮次或信息收集完毕），工作流开始执行

**对话计划配置**：
- **系统提示词**：指导对话 Agent 如何收集信息
- **最大对话轮次**：限制对话的最大轮数

### 混合模式 (hybrid)

混合模式结合了表单和对话两种方式。一部分确定性的参数通过表单收集，另一部分开放性的内容通过对话补充。

**适用场景**：
- 部分参数结构明确（如选择报告类型），部分参数需要对话补充（如详细需求描述）
- 希望先用表单快速收集基本信息，再用对话深入了解细节

## 定义输入字段

在输入参数配置面板中，你可以添加和管理输入字段。每个字段包含以下配置项：

### 基本属性

| 属性 | 说明 |
|------|------|
| 字段 ID | 字段的唯一标识符，在节点中引用此参数时使用 |
| 类型 | 字段的数据类型（见下方说明） |
| 标签 | 用户在表单中看到的字段显示名称 |
| 描述 | 对字段的补充说明，帮助用户理解需要填什么 |
| 收集提示 | 在对话模式中，指导对话 Agent 如何向用户询问此字段 |
| 是否必填 | 用户是否必须填写此字段才能运行工作流 |
| 默认值 | 字段的预设值，用户可以直接使用或修改 |

### 支持的字段类型

**文本 (text)**

普通文本输入，适合名称、描述、代码片段等内容。

可配置的校验规则：
- **最小长度** (minLength)：文本的最少字符数
- **最大长度** (maxLength)：文本的最多字符数

**数字 (number)**

数字输入，适合数量、阈值、限制等数值参数。

可配置的校验规则：
- **最小值** (min)：允许的最小数字
- **最大值** (max)：允许的最大数字

**单选 (single_select)**

从预定义选项中选择一个值。适合类型选择、级别选择等场景。

配置项：
- **选项列表** (options)：定义可选的值列表

例如定义一个"编程语言"字段，选项可以是 TypeScript、JavaScript、Python、Go、Java、Rust。

**多选 (multi_select)**

从预定义选项中选择多个值。适合标签选择、多维度勾选等场景。

配置项：
- **选项列表** (options)：定义可选的值列表

例如定义一个"审查重点"字段，选项可以是"安全"、"性能"、"可维护性"、"测试覆盖"、"代码规范"，用户可以同时选择多个。

### 条件显示

你可以配置字段的条件显示规则，让某些字段只在特定条件下才出现在表单中。

- **关联字段**：指定依赖的其他字段
- **匹配值**：当关联字段的值等于指定值时，当前字段才会显示

例如：当"报告类型"字段选择"自定义"时，才显示"自定义模板"字段。

## 实际示例

以下是几个预置模板中使用的输入参数配置，供你参考：

### 每日竞品分析

```
收集模式：表单 (form)

字段列表：
1. topic (文本) - "分析主题"，必填，最大 200 字符
2. depth (单选) - "分析深度"，必填，选项：浅度/中度/深度
3. output_format (多选) - "输出格式"，可选，选项：文本/表格/图表
4. max_iterations (数字) - "最大迭代次数"，可选，范围 1-10，默认值 3
```

### 客户反馈智能分类

```
收集模式：表单 (form)

字段列表：
1. feedback_text (文本) - "客户反馈内容"，必填，5-2000 字符
2. channel (单选) - "反馈渠道"，可选，选项：工单/邮件/应用内反馈/社交媒体
3. focus_topics (多选) - "重点关注主题"，可选，选项：功能需求/易用性/性能/稳定性/定价
```

### 技术博客创作工作流

```
收集模式：表单 (form)

字段列表：
1. topic (文本) - "博客主题"，必填，最大 150 字符
2. audience_level (单选) - "目标读者层级"，必填，选项：入门/进阶/专家
3. target_length (数字) - "目标字数"，可选，范围 800-5000，默认值 1800
4. sections (多选) - "需要包含的章节"，可选，选项：背景介绍/原理分析/代码示例/最佳实践/常见误区
```

### 代码审查助手

```
收集模式：表单 (form)

字段列表：
1. code_snippet (文本) - "待审查代码"，必填，20-8000 字符
2. language (单选) - "编程语言"，必填，选项：TypeScript/JavaScript/Python/Go/Java/Rust
3. review_focus (多选) - "审查重点"，可选，选项：安全/性能/可维护性/测试覆盖/代码规范
4. severity_threshold (数字) - "问题输出阈值"，可选，范围 1-5，默认值 3
```

## 在节点中使用输入参数

定义好输入参数后，你需要让工作流中的节点能够使用这些参数值。

### 通过触发器节点传递

触发器节点（如手动触发器）有一个"触发数据"输出端口（类型为 JSON）。当工作流运行时，用户填写的输入参数会通过这个端口以 JSON 格式向下游传递。

你可以将触发器的「触发数据」输出连接到接收 JSON 的节点，例如 Agent 的「上下文」端口；如果下游需要纯文本，则先通过输入预处理器转换，再把其「文本」输出连接到 Agent 的「文本」端口。

### 通过系统提示词引用

你也可以在系统提示词里说明如何处理接收到的输入数据，例如写明"请基于用户提供的反馈内容进行情感分析和主题分类"。提示词有两个来源：所绑定 Agent 自身的配置，以及连接到 Agent 节点「系统提示词」端口的文本节点——后者只对当前工作流生效。

## 设计建议

### 字段命名清晰

使用明确的标签和描述，让用户不需要看文档就能理解每个字段要填什么。

### 合理设置默认值

对于有常用值的字段，设置默认值可以减少用户的填写工作量。比如"最大迭代次数"默认 3，"超时时间"默认 30 秒。

### 善用校验规则

通过设置最小/最大长度和数值范围，可以在运行前就拦截不合理的输入，避免因为输入问题导致工作流运行失败。

### 选择合适的收集模式

- 参数结构明确、数量有限时，使用**表单模式**
- 需要灵活收集开放式信息时，使用**对话模式**
- 两者兼有时，使用**混合模式**

大多数场景下，表单模式就足够了。
