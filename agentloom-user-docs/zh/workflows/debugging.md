# 调试工作流

即使是精心设计的工作流，在实际运行中也可能遇到各种问题。本页介绍如何利用 AgentLoom 提供的调试工具来排查和解决这些问题。

---

## 调试的基本思路

排查工作流问题的一般步骤：

1. **定位出错的节点** -- 找到哪个节点执行失败或产出了异常结果
2. **查看错误信息** -- 阅读节点的错误详情，理解失败的具体原因
3. **检查输入数据** -- 确认上游节点传递给出错节点的数据是否正确
4. **调整配置** -- 根据问题原因修改节点配置
5. **重新运行** -- 运行修改后的工作流，验证问题是否解决

---

## 在画布中快速定位问题

### 查看节点执行状态

工作流运行完成后（或运行中），画布上的每个节点会显示执行状态覆盖层：

- 绿色标记：节点成功完成
- 红色标记：节点执行失败
- 灰色标记：节点被跳过
- 黄色标记：节点等待人工干预

如果某个节点显示红色标记，它就是需要关注的故障点。

### 查看节点错误信息

1. 点击显示红色标记的节点。

2. 在右侧属性面板的"实时执行"区段中，你会看到一个红色边框的错误信息区块。

> 界面提示：错误信息区块标题为"执行错误"，下方显示具体的错误描述文本。

3. 阅读错误信息。常见的错误类型包括：
   - **模型调用失败**：AI 模型 API 返回错误（如 API Key 无效、超出配额、模型不可用）
   - **HTTP 请求错误**：外部 API 返回非 200 状态码或连接超时
   - **代码执行错误**：代码节点中的代码运行时出错（语法错误、运行时异常）
   - **超时错误**：节点运行时间超过设定的超时限制
   - **配置错误**：节点的必填配置项缺失或无效

### 查看节点输出

即使节点执行成功，输出结果也可能不符合预期。在属性面板的"输出流"区域查看节点的实际输出内容，对比预期结果来判断问题。

## 使用执行调试页面

对于复杂工作流的调试，执行调试页面提供了更全面的信息。

### 进入执行调试页面

> 界面提示：执行调试页面的路径格式为 `/executions/执行ID`。

### 利用执行时间线

执行时间线（中栏）按时间顺序展示了每个节点的执行过程。这对于理解执行流程特别有用：

**你可以看到**：
- 每个节点的执行顺序
- 每个节点的执行持续时间
- 哪些节点并行运行了
- 失败节点的错误信息
- 被跳过的节点（以及跳过原因）

**时间线上的每条记录包含**：
- 节点名称和类型
- 执行状态徽章
- 持续时间
- 输入输出的摘要信息
- 审计证据标记（如果有）

### 查看节点详情

在时间线中点击某个节点，右栏会显示该节点的完整执行详情：

- **完整输入数据**：上游传入该节点的所有数据
- **完整输出数据**：该节点产出的所有数据
- **工具调用历史**：Agent 发起的每次工具调用的参数和返回值
- **对话消息**（Agent 节点）：Agent 与模型之间的完整对话记录
- **工作区文件**（如果 Agent 使用了沙箱）：Agent 在工作区中创建或修改的文件

### 使用终端标签页

如果工作流中使用了沙箱节点，执行调试页面提供了"终端"标签页，可以查看 Agent 在沙箱中执行的终端命令和输出。

## 单步检查法

当工作流较长且不确定问题出在哪里时，可以采用"单步检查"的方法：

### 方法一：逐节点验证

1. 从工作流的起点开始，检查第一个节点的输入和输出是否正确。
2. 确认第一个节点没问题后，继续检查第二个节点。
3. 依次向下游推进，直到发现输入或输出异常的节点。
4. 异常首次出现的节点就是问题根源。

### 方法二：简化工作流

1. 如果工作流很复杂，可以先临时删除或断开后半部分的节点。
2. 只运行前半部分，确认它们工作正常。
3. 逐步恢复后续节点，每次增加一两个，运行测试。
4. 当增加某个节点后出现问题，那个节点就是问题所在。

> 提示：在简化工作流时，建议先保存一个版本快照，这样可以随时恢复完整的工作流。

## 常见问题排查

### Agent 输出质量差

**现象**：Agent 返回了内容，但内容质量不高、不准确或不符合预期。

**排查方向**：
1. 检查系统提示词（System Prompt）是否足够清晰和具体
2. 确认选择的 AI 模型是否适合当前任务（更复杂的任务可能需要更强的模型）
3. 检查上游传入的数据是否完整，Agent 是否获得了足够的上下文信息
4. 如果使用了知识库，确认知识库中的文档与任务相关

**解决建议**：
- 优化系统提示词，增加更多细节和约束条件
- 尝试更换更高能力的模型
- 确保上游节点正确传递了所有必要信息

### HTTP 请求失败

**现象**：HTTP Request 节点显示红色错误标记。

**排查方向**：
1. 检查 URL 是否正确
2. 确认 HTTP 方法（GET/POST 等）与目标 API 的要求一致
3. 检查请求头和认证信息是否正确
4. 查看错误信息中的 HTTP 状态码（如 401 未认证、403 无权限、404 未找到、500 服务器错误）
5. 检查超时设置是否合理

**解决建议**：
- 先用 API 测试工具（如 curl 或 Postman）独立验证目标 API
- 检查 API Key 或 Token 是否过期
- 适当增加超时时间

### 条件分支走错了路径

**现象**：数据走了非预期的分支路径。

**排查方向**：
1. 查看条件分支节点的输入数据，确认数据格式和值与你预期的一致
2. 检查条件表达式是否正确
3. 注意数据类型 -- 字符串 "1" 和数字 1 在条件判断中可能表现不同

**解决建议**：
- 在条件分支前添加输入预处理器，确保数据格式统一
- 简化条件表达式，避免过于复杂的判断逻辑

### 工作流运行超时

**现象**：执行长时间停留在"执行中"状态，最终失败。

**排查方向**：
1. 检查是否有节点的处理耗时过长（如大量数据的 AI 处理）
2. 确认外部 API 调用是否存在响应延迟
3. 查看沙箱节点的超时设置

**解决建议**：
- 增加相关节点的超时时间设置
- 拆分大任务为多个小任务
- 确保外部依赖（API、数据库等）的可用性

### 节点之间数据传递异常

**现象**：下游节点接收到的数据与上游节点的输出不一致。

**排查方向**：
1. 确认连线的端口类型是否匹配
2. 检查是否有多条连线导致数据覆盖
3. 查看输入预处理器（如果有）的转换规则是否正确

**解决建议**：
- 删除可能冲突的多余连线
- 使用执行调试页面对比上游输出和下游输入的具体数据

### 执行受到资源配额限制

**现象**：执行直接失败，错误信息提到"配额"或"限制"。

**排查方向**：
1. 检查组织的资源配额设置（在"设置 > 资源配额"页面）
2. 可能触及了并发执行数限制、每日执行量限制或 API 调用限额

**解决建议**：
- 联系组织管理员调整配额
- 减少同时运行的工作流数量
- 优化工作流减少 API 调用次数

---

## 调试技巧总结

1. **保持冷静，从错误信息开始**：大多数问题都可以从错误信息中找到线索
2. **善用执行调试页面**：它提供了远比画布属性面板更丰富的调试信息
3. **逐步排查**：复杂问题不要试图一次性解决，先缩小范围找到根本原因
4. **保存版本再改动**：调试前先保存一个版本快照，避免调试过程中误改了正常的部分
5. **利用输出流验证**：在关键节点的输出中检查实际数据，确保每一步的数据传递都正确
6. **检查执行流连线**：很多"节点不运行"的问题是因为忘记了连接执行流
7. **关注资源限制**：如果反复运行失败，考虑是否触及了系统的资源配额限制
