# 检索配置

知识库的检索效果取决于多个因素的配合。AgentLoom 提供了丰富的检索配置选项，帮助你根据不同场景调整检索策略，获得更准确的检索结果。

## 检索策略概览

知识库的检索流程涉及以下几个关键环节，每个环节都可以单独配置：

1. **分块策略** -- 决定文档内容如何被切分为检索单元
2. **嵌入模型** -- 决定文本如何被转换为向量
3. **检索参数** -- 决定返回多少结果以及筛选条件
4. **重排策略** -- 对检索结果进行二次排序以提高准确性
5. **查询编排** -- 对用户问题进行预处理以改善检索效果

> 界面提示：在知识库详情页中，点击「设置」标签页可以查看和修改所有检索相关配置。

## 分块策略

分块策略决定了文档内容如何被切分为一个个独立的知识片段。合适的分块策略可以显著影响检索的准确性。

### 句子分块（Sentence）

将文档按句子为基本单位进行分块。你可以调整两个参数：

- **分块大小（Chunk Size）**：每个分块包含的最大 token 数量。默认值为 512，可选范围是 64 到 8192。
  - 较小的值：每个分块包含的信息更聚焦，检索精度更高，但可能丢失上下文
  - 较大的值：每个分块包含更多上下文，但可能引入不相关的信息
- **分块重叠（Chunk Overlap）**：相邻分块之间重叠的 token 数量。默认值为 64，可选范围是 0 到 4096。
  - 适当的重叠可以确保跨分块边界的信息不会丢失
  - 重叠过大会导致索引体积膨胀，降低检索效率

**适用场景**：通用文档、长文本、FAQ 类内容。

### 句子窗口（Sentence Window）

以句子为中心，同时包含其前后若干个句子作为上下文窗口。这种策略能更好地保留语义上下文。

- **窗口大小（Window Size）**：中心句子前后各包含的句子数量。默认值为 3，可选范围是 1 到 12。
  - 窗口越大，每个分块的上下文越完整，但分块体积也越大
  - 窗口越小，分块更精炼，适合信息密度较高的文档

**适用场景**：需要保留上下文关系的文档，如教程、技术文档、叙述性内容。这是默认的分块策略。

### Markdown 分块

按照 Markdown 文档的标题层级结构进行分块。系统会识别 Markdown 标题（`#`、`##`、`###` 等），将每个章节作为独立的分块。

**适用场景**：结构化的 Markdown 文档，如技术文档、知识库文章、API 参考。

## 嵌入模型

嵌入模型负责将文本转换为向量表示。AgentLoom 默认使用 `text-embedding-3-small` 模型，它在效率和质量之间取得了良好的平衡。

如果你的组织配置了其他嵌入模型，可以在创建知识库或修改设置时选择不同的模型。

**注意**：更换嵌入模型后，需要重建知识库索引才能使新模型生效。不同嵌入模型生成的向量不兼容，不能混合检索。

## 检索参数

检索参数直接影响每次检索返回的结果数量和质量。

### 返回数量（Top K）

Top K 决定了每次检索返回多少个最相关的知识片段。

- **默认值**：8
- **可选范围**：1 到 50
- **调优建议**：
  - 如果你需要 Agent 综合多个知识片段来回答问题，可以适当增大 Top K
  - 如果知识库中每个文档都是独立完整的答案（如 FAQ），较小的 Top K 即可
  - Top K 过大可能引入不相关的内容，反而干扰 Agent 的回答质量

### 相似度阈值（Similarity Threshold）

相似度阈值用于过滤掉与查询问题相关度太低的结果。只有相似度得分高于该阈值的结果才会被返回。

- **可选范围**：0 到 1
- **默认值**：未设置（不过滤）
- **调优建议**：
  - 设置为 0.7 左右是一个常见的起点
  - 较高的阈值（如 0.8 以上）可以确保只返回高度相关的内容，但可能遗漏一些有用的结果
  - 较低的阈值（如 0.5 以下）会返回更多结果，但可能包含不太相关的内容
  - 建议使用知识库的「测试检索」功能来验证阈值设置的效果

## 重排策略

重排（Reranking）是在初始检索之后，对结果进行二次排序以提高准确性的技术。初始检索基于向量相似度，而重排可以使用更复杂的模型来评估文档与查询之间的相关性。

### 不使用重排（None）

不对检索结果进行重排，直接使用向量相似度排序。这是默认设置，适合大多数场景。

### Cohere 重排

使用 Cohere 提供的重排模型对检索结果进行二次排序。可配置的参数包括：

- **模型**：Cohere 重排模型名称，默认为 `rerank-english-v2.0`
- **Top N**：重排后保留的结果数量，默认为 5，可选范围 1 到 50。这个值通常小于检索的 Top K，意味着重排会进一步精选结果
- **API Key**：Cohere 服务的 API Key。需要在平台中配置 Cohere 的 API 密钥
- **Base URL**：自定义的 Cohere API 地址。如果使用代理或私有部署，可以指定此参数
- **超时时间**：API 调用的超时时间，最大 120 秒

**适用场景**：对检索精度要求较高的场景，尤其是知识库规模较大或文档内容相似度较高时。

## 查询编排

查询编排是对用户的原始查询进行预处理，以改善检索效果的策略。

### 不使用查询编排（None）

直接使用用户的原始查询进行检索。这是默认设置，适合大多数场景。

### HyDE（Hypothetical Document Embeddings）

HyDE 策略会先让 AI 模型根据用户的查询生成一个假设性的答案文档，然后使用这个假设答案（而非原始查询）去知识库中检索。这种方法可以缩小查询与知识库文档之间的「语义鸿沟」。

可配置的参数包括：

- **模型配置**：用于生成假设答案的 AI 模型
- **提示词模板**：自定义的提示词模板，用于指导模型生成假设答案，最长 10000 个字符

**适用场景**：当用户的查询风格与知识库文档的表述方式差异较大时，HyDE 可以帮助改善检索效果。

## 测试检索效果

修改检索配置后，建议使用知识库内置的测试检索功能来验证效果。

> 界面提示：在知识库详情页中，可以找到「测试检索」区域。输入一个测试问题，系统会立即返回检索结果，帮助你评估当前配置的效果。

测试检索会显示以下信息：

- 检索到的知识片段内容
- 每个片段的相似度得分
- 片段所属的文档名称

你可以通过对比不同配置下的检索结果，找到最适合你的知识库的配置方案。

## 配置调优建议

| 场景 | 推荐配置 |
|------|---------|
| FAQ 知识库（短问答） | 句子分块，Chunk Size 256，Top K 3-5 |
| 技术文档（长文本） | 句子窗口，Window Size 3-5，Top K 8-10 |
| Markdown 文档集 | Markdown 分块，Top K 5-8 |
| 高精度需求 | 启用 Cohere 重排，Top N 3-5 |
| 查询风格与文档差异大 | 启用 HyDE 查询编排 |
