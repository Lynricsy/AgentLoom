# 在工作流中使用知识库

知识库能力通过 **Agent 配置**绑定。创建或编辑 Agent 时，在 Agent 配置画布上把知识库节点连接到 Agent Main 的「知识库」端口；工作流引用已发布的 Agent 后，会自动使用该 Agent 已绑定的知识库。

工作流画布也提供知识库节点，其「知识库」输出为 `knowledge` 类型。但当前工作流画布没有任何节点能接收 `knowledge` 类型：工作流中的 Agent 节点没有知识库输入端口，其「上下文」端口是 `json` 类型，也不能接收该输出。

## 为 Agent 绑定知识库

### 第一步：准备知识库

在 **资源 > 知识库** 中创建知识库、上传文档，并等待文档处理完成。建议先使用测试检索功能确认检索结果符合预期。

### 第二步：打开 Agent 配置画布

创建或编辑需要知识检索能力的 Agent。在 Agent 配置画布中：

1. 添加一个知识库节点并选择目标知识库。
2. 将知识库节点的「知识库」输出连接到 Agent Main 的「知识库」输入端口。
3. 如需多个知识来源，可添加多个知识库节点，并分别连接到 Agent Main 的「知识库」端口。
4. 保存并发布 Agent。

这些操作发生在 **Agent 配置画布**，不是工作流画布。详细步骤参见[创建 Agent](../agents/creating.md)。

### 第三步：在工作流中引用 Agent

在工作流画布中添加 Agent 节点，选择上一步发布的 Agent。知识库绑定属于 Agent 定义，会随该 Agent 一起生效，不需要也无法在工作流画布中再连一次。

一个最小的知识问答工作流可以是：

```text
[文本节点「文本」] --> [Agent「文本」] --> [文本输出「文本」]
```

其中两条数据连线都是 `text` 类型；Agent 使用的知识库来自 Agent 配置。

## 工作流知识库节点的端口

知识库节点的端口为：

- **输入端口**：「执行流」，类型为 `exec`。
- **输出端口**：「执行流」，类型为 `exec`；「知识库」，类型为 `knowledge`。

当前没有工作流节点提供 `knowledge` 类型输入端口，因此「知识库」输出不能连接到 Agent 或其他工作流节点。不要把它连接到 Agent 的「上下文」端口；「上下文」只接收 `json`。

## 如何更新知识库

更新文档或检索配置后，已绑定该知识库的 Agent 会继续引用相同的知识库资源。若要更换或增减知识库，请回到 Agent 配置画布调整绑定，重新发布 Agent，并在工作流的 Agent 节点中选择所需版本。

## 实时状态更新

当知识库发生变化时（例如新文档处理完成或知识库配置更新），系统会通过实时通信通道通知工作流画布。如果你正在编辑的工作流引用了该知识库，画布上的知识库节点会自动更新显示的状态信息。

Agent 执行时会使用其 Agent 配置中绑定的知识库进行检索。如果知识库不可用、文档尚未处理完成或检索配置不合适，请到知识库管理页和 Agent 配置画布检查状态与绑定。

## 常见问题

### Agent 没有使用预期的知识库

可能的原因：
- 目标知识库没有绑定到该 Agent 的 Agent Main 节点
- 工作流引用的 Agent 版本不是最新发布版本
- 知识库中没有处理完成的文档

解决方案：在 Agent 配置画布确认知识库绑定，保存并发布 Agent，然后在工作流中选择正确版本。

### 检索结果不够准确

可能的原因：
- 分块策略不适合当前文档类型
- Top K 设置过大，返回了不相关的内容
- 相似度阈值过低或未设置

解决方案：参考[检索配置](./retrieval.md)文档调优检索参数，并使用测试检索功能验证效果。

### 检索结果中缺少期望的内容

可能的原因：
- 文档尚未处理完成
- 分块策略导致相关内容被分散到多个片段中
- Top K 设置过小

解决方案：检查文档状态，适当增大 Top K 值，或尝试更换分块策略。

## 最佳实践

1. **提前准备知识库**：绑定前确保知识库已创建、文档已上传且处理完成。
2. **测试检索效果**：使用知识库的测试检索功能验证检索质量。
3. **合理设置 Top K**：通常 5-10 个片段就足够，过多结果反而可能干扰 Agent 判断。
4. **按领域分库**：不同领域的文档使用不同知识库，并在 Agent 配置中绑定所需知识来源。
5. **检查 Agent 版本**：修改知识库绑定并发布 Agent 后，在工作流中选择需要使用的 Agent 版本。
