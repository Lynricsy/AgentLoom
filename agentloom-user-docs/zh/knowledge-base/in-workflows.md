# 在工作流中使用知识库

知识库创建并处理完成后，你可以将它接入到工作流中，让 Agent 在执行任务时自动从知识库中检索相关信息。本文介绍如何在工作流画布中添加和配置知识库节点。

## 基本概念

在 AgentLoom 的工作流中，知识库通过专门的「知识库节点」接入。知识库节点的作用是：接收上游节点传入的查询文本，从指定的知识库中检索最相关的知识片段，然后将检索结果传递给下游节点（通常是 Agent 节点）。

这意味着知识库不是直接附加在 Agent 上的，而是作为工作流中的一个独立节点存在。这种设计让你可以灵活控制检索的时机、来源和方式。

## 添加知识库节点

### 第一步：打开工作流画布

> 界面提示：在 AgentLoom Studio 中，进入你要编辑的工作流，即可看到可视化画布编辑器。

### 第二步：添加知识库节点

> 界面提示：在画布左侧的节点面板中，找到「知识库」节点类型，将其拖拽到画布上，或点击画布空白区域后从弹出的节点选择器中添加。

知识库节点在画布上会显示为一个带有知识库图标的节点卡片。

### 第三步：配置知识库节点

点击画布上的知识库节点，在右侧的配置面板中进行设置：

1. **选择知识库**：从下拉列表中选择一个已创建的知识库。列表会显示知识库的名称、文档数量和状态信息。
2. **确认状态**：确保所选知识库的状态为「可用」。如果知识库处于「处理中」或「异常」状态，检索可能无法正常工作。

> 界面提示：配置面板位于画布右侧。选择知识库后，面板会显示该知识库的基本信息，包括文档数量和知识节点数量。

## 连接知识库节点

知识库节点需要与其他节点配合使用。以下是最常见的连接方式：

### 标准连接模式

最常见的使用方式是将知识库节点连接到 Agent 节点：

```
[用户输入] --> [知识库节点] --> [Agent 节点] --> [输出]
```

在这个模式中：

1. 用户输入或上游节点提供查询文本
2. 知识库节点从知识库中检索相关内容
3. 检索结果传递给 Agent 节点
4. Agent 基于检索到的知识生成回答

### 多知识库模式

如果你需要同时从多个知识库中检索信息，可以并排放置多个知识库节点：

```
                 [知识库节点 A] ──┐
[用户输入] ──┤                    ├──> [Agent 节点] --> [输出]
                 [知识库节点 B] ──┘
```

这种方式适合需要综合多个领域知识的场景，例如同时参考产品文档和技术规范。

### 条件检索模式

你可以在知识库节点上游添加条件分支节点，根据不同的条件决定使用哪个知识库：

```
                           ┌──> [产品知识库] ──┐
[用户输入] --> [条件判断] ──┤                    ├──> [Agent 节点]
                           └──> [技术知识库] ──┘
```

## 连接端口说明

知识库节点有明确的输入和输出端口：

- **输入端口**：接收上游节点传入的查询文本。端口类型为 `knowledge`，兼容文本类型的数据。
- **输出端口**：输出检索到的知识片段。同样为 `knowledge` 类型。

在连接节点时，需要确保上游节点的输出端口类型与知识库节点的输入端口类型兼容。AgentLoom 的画布会在连线时自动提示端口是否兼容。

## 检索结果的使用

当知识库节点完成检索后，它会将以下信息传递给下游节点：

- **检索到的知识片段**：按相关度排序的文本内容列表
- **相似度得分**：每个片段与查询之间的相似度分数
- **来源信息**：片段所属的文档名称和位置

Agent 节点接收到这些信息后，会将检索到的知识片段作为参考资料注入到提示词中。Agent 在生成回答时可以引用这些资料，从而给出更加准确和有据可依的回答。

## 实时状态更新

当知识库发生变化时（例如新文档处理完成或知识库配置更新），系统会通过实时通信通道通知工作流画布。如果你正在编辑的工作流引用了该知识库，画布上的知识库节点会自动更新显示的状态信息。

## 运行时行为

当工作流执行到知识库节点时：

1. 节点从上游接收查询文本
2. 使用知识库配置的检索策略和参数执行检索
3. 返回检索结果给下游节点
4. 如果知识库不可用（已删除或状态异常），节点会报告错误并终止当前执行路径

## 常见问题

### 知识库节点显示"无数据"

可能的原因：
- 知识库中没有处理完成的文档
- 知识库处于「空库」或「处理中」状态
- 查询文本为空或过短

解决方案：确认知识库状态为「可用」，且至少有一个「就绪」状态的文档。

### 检索结果不够准确

可能的原因：
- 分块策略不适合当前文档类型
- Top K 设置过大，返回了不相关的内容
- 相似度阈值过低或未设置

解决方案：参考[检索配置](./retrieval.md)文档调优检索参数，并使用测试检索功能验证效果。

### 检索结果中缺少期望的内容

可能的原因：
- 文档尚未处理完成
- 分块策略导致相关内容被分散到多个片段中
- Top K 设置过小

解决方案：检查文档状态，适当增大 Top K 值，或尝试更换分块策略。

## 最佳实践

1. **提前准备知识库**：在构建工作流之前，先确保知识库已创建、文档已上传且处理完成。
2. **测试检索效果**：使用知识库的测试检索功能验证检索质量，再将知识库接入工作流。
3. **合理设置 Top K**：不要盲目设置过大的 Top K。通常 5-10 个片段就足够了，过多的检索结果反而可能干扰 Agent 的判断。
4. **按领域分库**：将不同领域的文档放入不同的知识库，而不是把所有文档塞进一个巨大的知识库。这样可以在工作流中精准选择需要的知识来源。
5. **关注知识库状态**：定期检查知识库和文档的处理状态，确保 Agent 能够检索到最新的内容。
