# 多 Agent 协作管线

本教程将展示 AgentLoom 最强大的能力之一：让多个 Agent 在同一个工作流中协同工作。你将构建一个产品需求分析管线，让三个专业 Agent 依次完成需求分析、技术方案设计和代码生成。

## 你将学到什么

- 创建多个具有不同专业角色的 Agent
- 在工作流中串联多个 Agent 节点
- 配置共享沙箱实现 Agent 间的文件共享
- 使用智能路由为不同 Agent 选择合适的模型
- 理解多 Agent 协作的数据流

## 前置条件

- 已注册并登录 AgentLoom 平台
- 拥有 creator 或以上角色权限
- 组织已配置至少两个不同的 LLM 模型提供商（用于演示智能路由）
- 建议先完成前面的入门教程

## 场景说明

假设你的团队需要快速将一个产品需求文档转化为可执行的技术实现。传统流程中，产品经理、架构师、开发者需要多轮沟通。通过 AgentLoom 的多 Agent 协作，你可以搭建一条自动化管线：

1. **需求分析 Agent** -- 解读产品需求，提取功能点和验收标准
2. **技术方案 Agent** -- 基于功能点设计技术架构和实现方案
3. **代码生成 Agent** -- 根据技术方案生成初始代码骨架

三个 Agent 共享同一个沙箱环境，后一个 Agent 可以直接读取前一个 Agent 写入的文件。

## 第一步：创建三个专业 Agent

### 1.1 需求分析 Agent

1. 进入 **Agent** 页面，点击 **创建 Agent**。

2. 填写信息：
   - **名称**：需求分析师
   - **描述**：解读产品需求文档，提取结构化的功能需求和验收标准

3. 设置系统提示词：

   ```
   你是一个资深产品需求分析师。你的任务是：
   1. 仔细阅读产品需求描述
   2. 将模糊的需求拆解为明确的功能点
   3. 为每个功能点定义验收标准
   4. 识别潜在的风险和依赖
   5. 将分析结果写入工作区的 requirements.md 文件

   输出文件格式：
   # 需求分析报告
   ## 功能清单
   - [ ] 功能1：描述 + 验收标准
   - [ ] 功能2：描述 + 验收标准
   ## 风险评估
   - 风险1：描述 + 影响 + 建议
   ## 依赖关系
   - 依赖1：描述
   ```

4. 保存 Agent。

### 1.2 技术方案 Agent

1. 再次点击 **创建 Agent**。

2. 填写信息：
   - **名称**：技术架构师
   - **描述**：基于需求分析设计技术架构和实现方案

3. 设置系统提示词：

   ```
   你是一个资深软件架构师。你的任务是：
   1. 阅读工作区中 requirements.md 的需求分析结果
   2. 设计合适的技术架构
   3. 选择技术栈和核心组件
   4. 定义模块划分和接口设计
   5. 将技术方案写入工作区的 architecture.md 文件

   输出文件格式：
   # 技术方案
   ## 架构概览
   [整体架构描述]
   ## 技术栈
   - 前端：xxx
   - 后端：xxx
   - 数据库：xxx
   ## 模块设计
   ### 模块1
   - 职责：xxx
   - 接口：xxx
   ## 实现计划
   - 阶段1：xxx
   - 阶段2：xxx
   ```

4. 保存 Agent。

### 1.3 代码生成 Agent

1. 再次点击 **创建 Agent**。

2. 填写信息：
   - **名称**：代码生成器
   - **描述**：根据技术方案生成项目的代码骨架

3. 设置系统提示词：

   ```
   你是一个高效的代码生成专家。你的任务是：
   1. 阅读工作区中 requirements.md 和 architecture.md 文件
   2. 根据技术方案生成项目的初始代码骨架
   3. 创建必要的目录结构和核心文件
   4. 为每个模块生成接口定义和基本实现
   5. 生成 README.md 说明文档

   代码要求：
   - 遵循设计文档中定义的架构
   - 包含清晰的代码注释
   - 遵循所选技术栈的最佳实践
   - 每个文件都应该是可运行的初始版本
   ```

4. 保存 Agent。

## 第二步：搭建多 Agent 工作流

1. 进入 **工作流** 页面，点击 **创建工作流**。

2. 输入名称"产品需求自动化管线"，进入画布编辑器。

3. **添加文本输入节点**：
   - 拖拽一个 **文本输入** 节点
   - 配置变量名为 `productRequirement`
   - 这个节点接收原始的产品需求描述

4. **添加共享沙箱节点**：
   - 拖拽一个 **代码沙箱** 节点
   - 配置沙箱资源：
     - **CPU**：1 核
     - **内存**：512 MB
     - **超时**：5 分钟（因为涉及多 Agent 协作，需要更长时间）
   - 这个沙箱将被所有 Agent 共享，实现文件的读写交接

5. **添加智能路由节点**：
   - 拖拽一个 **智能路由** 节点
   - 在配置面板中设置路由策略为 **FALLBACK_CHAIN**（故障自动降级）
   - 添加两个或以上可用的 LLM 模型作为候选
   - 智能路由会自动为 Agent 选择最优模型，当首选模型不可用时自动切换到备选模型

6. **添加第一个 LLM Agent 节点（需求分析）**：
   - 拖拽一个 **LLM Agent** 节点
   - 在配置面板中，使用"需求分析师"的提示词配置
   - 连接端口：
     - 文本输入 --> LLM Agent 1（文本端口）
     - 沙箱 --> LLM Agent 1（沙箱端口）
     - 智能路由 --> LLM Agent 1（模型端口）

7. **添加第二个 LLM Agent 节点（技术方案）**：
   - 拖拽另一个 **LLM Agent** 节点
   - 配置"技术架构师"的提示词
   - 连接端口：
     - LLM Agent 1 --> LLM Agent 2（文本端口，传递上一步的结果作为上下文）
     - 沙箱 --> LLM Agent 2（沙箱端口，共享同一个沙箱）
     - 智能路由 --> LLM Agent 2（模型端口）

8. **添加第三个 LLM Agent 节点（代码生成）**：
   - 拖拽第三个 **LLM Agent** 节点
   - 配置"代码生成器"的提示词
   - 连接端口：
     - LLM Agent 2 --> LLM Agent 3（文本端口）
     - 沙箱 --> LLM Agent 3（沙箱端口）
     - 智能路由 --> LLM Agent 3（模型端口）

9. **添加文本输出节点**：
   - 拖拽一个 **文本输出** 节点
   - 连接：LLM Agent 3 --> 文本输出

10. 完整的工作流结构：

    ```
    文本输入 --> LLM Agent 1 --> LLM Agent 2 --> LLM Agent 3 --> 文本输出
                   ^   ^            ^   ^            ^   ^
    智能路由 ------+   |            +   |            +   |
    沙箱 (共享) -------+-----------+---+-----------+---+
    ```

11. 保存工作流。

## 第三步：理解共享沙箱

在这个工作流中，共享沙箱是关键。三个 Agent 节点连接到同一个沙箱节点，这意味着：

- **文件共享**：需求分析 Agent 写入的 `requirements.md` 文件，技术方案 Agent 可以直接读取
- **环境共享**：所有 Agent 在同一个隔离的执行环境中工作
- **生命周期管理**：沙箱在第一个 Agent 开始执行时创建，在最后一个 Agent 完成后自动销毁

::: tip 沙箱节点的连接
一个沙箱节点可以同时连接多个下游 Agent 节点。系统会按照 DAG 拓扑顺序依次执行各个 Agent，确保前一个 Agent 完成写入后，下一个 Agent 才开始读取。
:::

## 第四步：理解智能路由

智能路由节点为多 Agent 场景提供了灵活的模型选择能力。在这个工作流中：

- 所有三个 Agent 共用同一个智能路由配置
- 默认策略 FALLBACK_CHAIN 会尝试使用首选模型，如果失败则自动切换到下一个候选模型
- 你也可以为每个 Agent 使用不同的智能路由节点，选择不同的策略：
  - 需求分析：使用 QUALITY_FIRST（最高输出质量）
  - 技术方案：使用 QUALITY_FIRST
  - 代码生成：使用 COST_OPTIMIZED（最低成本，因为生成的代码量较大）

## 第五步：测试多 Agent 管线

1. 点击 **运行** 按钮。

2. 在输入面板中，输入一个产品需求描述，例如：

   ```
   我们需要开发一个在线问卷调查系统。主要功能包括：
   1. 问卷创建：支持多种题型（单选、多选、填空、评分）
   2. 问卷发布：生成分享链接，支持设置截止时间
   3. 数据收集：实时统计回收数量
   4. 结果分析：基本的统计图表（饼图、柱状图）
   5. 数据导出：支持导出为 Excel 格式

   目标用户：中小企业的市场调研人员
   预期上线时间：2 个月
   ```

3. 点击 **开始执行**，观察三个 Agent 依次工作。

4. 在执行状态栏中，你可以看到：
   - 第一阶段：需求分析 Agent 正在分析需求并写入 requirements.md
   - 第二阶段：技术方案 Agent 读取需求文件并撰写 architecture.md
   - 第三阶段：代码生成 Agent 读取前两个文件并生成代码骨架

5. 执行完成后，查看各个 Agent 节点的输出，以及沙箱中生成的文件。

## 第六步：查看协作成果

执行完成后，你可以在沙箱中查看所有 Agent 写入的文件：

- `requirements.md` -- 需求分析报告
- `architecture.md` -- 技术方案文档
- `README.md` -- 项目说明文档
- `src/` -- 代码骨架目录

每个 Agent 的输出都建立在前一个 Agent 的成果之上，形成完整的从需求到代码的自动化管线。

## 完成

你已经成功搭建了一个多 Agent 协作管线。核心要点回顾：

- 多个 Agent 节点可以在同一个工作流中串联，形成协作管线
- 共享沙箱让 Agent 之间可以通过文件进行数据交接
- 智能路由为不同的 Agent 灵活选择最优模型
- DAG 调度器确保 Agent 按正确的依赖顺序执行

### 进阶建议

- **并行分支**：如果某些 Agent 的工作不依赖彼此，可以创建并行分支让它们同时执行
- **条件分支**：添加条件节点，根据需求分析的结果动态决定后续流程
- **人工介入**：为关键节点配置介入策略，让人工审批关键决策后再继续执行
- **复用为模块**：将稳定的 Agent 组合保存为可复用块，在其他工作流中快速引用
- **Agent 节点替代**：如果你已经创建了独立 Agent，可以使用"Agent 节点"直接引用，而不需要在 LLM Agent 节点中重复配置
