# 在工作流中使用 Agent

AgentLoom 允许你在工作流中引用已发布的 Agent，将其作为 AI 推理节点使用。本文介绍使用前提、Agent 与版本选择、端口连接，以及多个 Agent 共享沙箱的配置方式。

## 使用前提

工作流中的 Agent 节点必须绑定一个已发布的 Agent 定义。开始配置工作流前，请先在 Agent 管理页面完成以下操作：

1. 创建 Agent。
2. 配置 Agent 的系统提示词、模型、工具、知识库和运行模式等能力。
3. 发布 Agent。

只有已发布的 Agent 才会出现在工作流节点的可选列表中。如果工作流中存在未绑定 Agent 的节点，服务端会拒绝发布工作流（HTTP 422），并逐个指出未绑定的节点。

## 添加并绑定 Agent 节点

### 第一步：打开工作流画布

进入要编辑的工作流，打开工作流画布编辑器。

### 第二步：添加 Agent 节点

在左侧节点面板中找到 **Agent 节点**，将其拖拽到画布上。

### 第三步：选择 Agent

点击画布上的 Agent 节点打开右侧配置面板，然后：

1. 在列表中搜索并选择目标 Agent。列表只显示已发布状态的 Agent。
2. 确认节点已经成功绑定该 Agent。
3. 根据需要选择已发布版本。

Agent 的系统提示词、模型、工具绑定、知识库和记忆等核心能力均来自所绑定的 Agent 定义，无需在工作流中重复配置。

## 选择并锁定版本

选择 Agent 后，可以指定要使用的已发布版本。默认使用最新的已发布版本。

如果选择了特定版本，节点会固定使用该版本。之后即使 Agent 发布了新版本，工作流也不会自动切换；需要在节点配置面板中手动选择新版本。

版本锁定可以确保同一个工作流在多次执行中使用一致的 Agent 配置。更新版本后，应重新检查输入、输出和运行模式是否仍符合工作流设计。

## 连接端口

Agent 节点通过端口接收工作流数据和附加能力，并将回复或结构化结果传递给下游节点。

### 输入端口

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| exec | exec | 否 | 执行流入口，前序节点完成后触发 Agent 执行 |
| 文本 | text | 是 | 发送给 Agent 的输入文本 |
| 系统提示词 | text | 否 | 临时覆盖 Agent 定义自带的系统提示词 |
| 沙箱 | sandbox | 否 | 绑定沙箱执行环境，仅 sandbox 运行模式的 Agent 可用 |
| 上下文 | json | 否 | 传入附加上下文 JSON 数据 |
| Skills | skill | 否 | 启用额外的技能模板，可连接多个 |
| 扩展工具 | tool | 否 | 额外挂载工具，可连接多个 |
| 子 Agent | agent | 否 | 注册子 Agent，可连接多个 |
| Schema | json | 否 | 定义 Agent 输出的 JSON Schema |

### 输出端口

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| exec | exec | 执行流出口，Agent 完成后触发下游节点 |
| 回复 | text | Agent 生成的自然语言文本回复，可连接多个下游 |
| 结构化 | json | Agent 按 Schema 约束输出的结构化 JSON 数据，可连接多个下游 |

连接时至少要为“文本”输入提供数据。通常还需要连接 exec 端口来控制执行顺序，并将“回复”或“结构化”输出连接到下游节点。

### 临时覆盖系统提示词

Agent 自带的系统提示词在 Agent 配置中设定。如果只想在当前工作流中临时覆盖它，可以添加一个**文本节点**，将文本节点的“文本”输出连接到 Agent 节点的“系统提示词”输入端口。此连接不会修改 Agent 定义。

### 模型配置

模型由所绑定的 Agent 定义决定。Agent 节点没有模型输入端口，LLM 模型节点和智能路由节点的模型输出不能连接到 Agent 节点。如需更换模型，请到 Agent 配置中修改模型并发布，再在工作流中选择相应版本。

### 结构化输出

如果需要 Agent 返回特定格式的 JSON 数据，可以将 JSON Schema 连接到“Schema”输入端口。Agent 会按 Schema 约束生成结果，下游节点可以从“结构化”输出端口获取数据。

## 配置沙箱

选择 Agent 后，节点会根据该 Agent 的运行模式调整沙箱端口：

- **sandbox 模式**：显示“沙箱”输入端口，可以连接沙箱节点。
- **no_sandbox 模式**：不显示“沙箱”输入端口。

运行模式由 Agent 定义决定。如需修改，请在 Agent 配置中调整并发布相应版本。

## 共享沙箱

一个沙箱节点可以同时连接到多个 sandbox 模式的 Agent 节点，让这些 Agent 在同一个代码执行环境中协作。

### 配置步骤

1. 在画布上放置一个沙箱节点，并配置 CPU、内存、磁盘和超时等资源参数。
2. 将沙箱节点的输出分别连接到多个 Agent 节点的“沙箱”输入端口。
3. 用 exec 和文本连线安排各 Agent 的执行顺序和数据传递。
4. 执行工作流。一个 Agent 在沙箱中创建的文件可由后续 Agent 读取和修改。

### 沙箱生命周期

| 模式 | 说明 |
|------|------|
| session | 沙箱在最后一个直接使用它的节点完成后销毁，适合一次性执行。 |
| persistent | 沙箱在节点解绑后回到就绪状态，可被后续执行复用，适合需要保持环境状态的场景。 |

多个 Agent 共享同一沙箱时，也会共享 CPU 和内存配额。计算任务较重时，需要相应提高沙箱资源配置。

## 常见工作流模式

### 单 Agent 任务

```text
[触发器] ---> [Agent 节点] ---> [文本输出]
```

触发器向 Agent 的“文本”端口提供输入，Agent 的“回复”端口连接到文本输出节点。

### 多 Agent 流水线

```text
[触发器] ---> [Agent A] ---> [Agent B] ---> [Agent C] ---> [输出]
                  \              |              /
                   `--- [共享沙箱] ---'
```

每个 Agent 节点分别绑定一个已发布的专业 Agent，前一个节点的回复作为后一个节点的文本输入。sandbox 模式的 Agent 还可以共享同一个沙箱。

### 条件路由

```text
[触发器] ---> [条件分支] ---> [代码 Agent]（编程任务）
                         ---> [文档 Agent]（文档任务）
                         ---> [分析 Agent]（数据分析任务）
```

每个分支中的 Agent 节点绑定适合该任务的已发布 Agent。

### 使用 Agent 自带的知识库

如果工作流需要检索专属资料，请先在 Agent 配置中绑定知识库并发布 Agent，再由工作流中的 Agent 节点引用该版本。知识库能力随 Agent 定义一起生效。

## 注意事项

1. **先发布再引用**：未发布的 Agent 不会出现在选择列表中。
2. **所有节点都要绑定**：存在未选择 Agent 的节点时，工作流发布会被拒绝。
3. **版本不会自动切换**：固定版本后，发布新的 Agent 版本不会自动更新工作流节点。
4. **模型在 Agent 中配置**：工作流不能向 Agent 节点连接模型输出。
5. **沙箱模式必须匹配**：只有 sandbox 模式的 Agent 可以连接沙箱。
6. **共享资源需要规划**：多个 Agent 共享沙箱时，应为整体负载配置足够的 CPU、内存和超时时间。
7. **错误会向下游传播**：Agent 节点执行失败时，错误会按照工作流的错误处理规则传播。
