# 在工作流中使用 Agent

AgentLoom 允许你将独立创建的 Agent 嵌入到工作流中作为一个执行节点。本文介绍 Agent 节点与 LLM Agent 节点的区别、如何在工作流中添加和配置 Agent 节点，以及如何共享沙箱资源。

## 两种 Agent 节点的区别

工作流画布中有两种与 AI 推理相关的节点，它们虽然名称相似，但定位和使用场景有本质区别。

### LLM Agent 节点（Chat Agent）

LLM Agent 节点是工作流中最基础的 AI 推理节点。它在工作流内部直接配置 LLM 参数进行推理。

**特点：**

- 配置内嵌在工作流中（系统提示词、模型、工具等都在工作流画布上配置）。
- 不引用外部 Agent 定义，所有参数独立于 Agent 管理体系。
- 支持自主决策模式配置（手动确认 / 规则匹配 / LLM 建议）。
- 支持连接模型、工具、知识库、沙箱等端口。
- 适合在工作流中需要一次性的 AI 推理步骤，且不需要复用 Agent 配置的场景。

### Agent 节点

Agent 节点是对已创建并发布的独立 Agent 的引用。它让你可以在工作流中复用之前精心配置的 Agent。

**特点：**

- 引用一个已发布的 Agent 定义和版本。
- Agent 的核心配置（系统提示词、模型、工具绑定、知识库等）由 Agent 定义管理，无需在工作流中重复配置。
- 支持通过连线为 Agent 提供额外的输入（文本、上下文、沙箱、技能、工具、子 Agent、输出 Schema）。
- 适合需要复用已有 Agent 能力的场景，或者需要在多个工作流中使用同一个 Agent 的场景。

### 对比表

| 对比维度 | LLM Agent 节点 | Agent 节点 |
|----------|---------------|-----------|
| 配置方式 | 在工作流画布中直接配置 | 引用已发布的独立 Agent |
| 复用性 | 仅限当前工作流 | 可在多个工作流中引用同一 Agent |
| 系统提示词 | 在节点配置面板中编写 | 由 Agent 定义管理 |
| 模型选择 | 在节点上连接 LLM 模型 | 由 Agent 定义管理 |
| 版本管理 | 无（随工作流保存） | 遵循 Agent 版本体系 |
| 记忆能力 | 无 | 可携带 Agent 的记忆实例 |
| 子 Agent | 不支持 | 可连接子 Agent 端口 |

### 如何选择

- **选择 LLM Agent 节点**：当你只需要一个简单的 AI 推理步骤，配置比较轻量，且不打算在其他地方复用时。
- **选择 Agent 节点**：当你已经精心配置了一个 Agent（设置了系统提示词、绑定了工具和知识库、调优了参数），并且希望在工作流中复用它的全部能力时。

## 添加 Agent 节点到工作流

### 第一步：打开工作流画布

进入你要编辑的工作流，打开工作流画布编辑器。

### 第二步：从面板中拖拽 Agent 节点

> 界面提示：在左侧节点面板的 "Agent" 分类下，找到 "Agent" 节点，将其拖拽到画布上。

### 第三步：选择 Agent 定义

放置节点后，点击节点打开右侧配置面板。在配置面板中：

1. 从 Agent 列表中搜索并选择目标 Agent。列表只显示已发布（published）状态的 Agent。
2. 选择 Agent 后，系统会自动加载该 Agent 的已发布版本列表。
3. 你可以选择特定版本，或使用最新的已发布版本。

> 界面提示：配置面板顶部有搜索框可以按名称筛选 Agent，下方列表显示可选的 Agent 及其描述。

### 第四步：连接端口

Agent 节点提供了丰富的输入和输出端口。

**输入端口：**

| 端口名称 | 数据类型 | 必需 | 说明 |
|----------|----------|------|------|
| 文本 | text | 是 | 发送给 Agent 的输入文本 |
| 沙箱 | sandbox | 否 | 绑定沙箱执行环境 |
| 上下文 | json | 否 | 传入附加上下文 JSON 数据 |
| Skills | skill | 否 | 启用技能模板（可多个） |
| 扩展工具 | tool | 否 | 额外挂载 MCP 工具（可多个） |
| 子 Agent | agent | 否 | 注册子 Agent（可多个） |
| Schema | json | 否 | 定义 Agent 输出的 JSON Schema |

**输出端口：**

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| 回复 | text | Agent 生成的自然语言文本回复 |
| 结构化 | json | Agent 按 Schema 约束输出的 JSON 数据 |

将前序节点的输出连接到 Agent 节点的输入端口，即可在工作流执行时将数据传递给 Agent。

## 配置 Agent 节点

### 输入映射

Agent 节点支持输入映射配置，允许你指定工作流中的数据如何传递到 Agent 的输入。在配置面板中可以设置字段映射关系。

### 运行时模式感知

选择 Agent 后，节点会根据该 Agent 的运行时模式（sandbox / no_sandbox）自动调整可用端口：

- 如果 Agent 是 sandbox 模式：沙箱输入端口可见，你可以连接沙箱节点。
- 如果 Agent 是 no_sandbox 模式：沙箱输入端口自动隐藏。

### 结构化输出

如果你需要 Agent 返回特定格式的 JSON 数据（而不是自由文本），可以将一个 JSON Schema 通过"Schema"端口传入。Agent 会尝试按照 Schema 约束生成结构化输出，输出可从"结构化"端口获取。

## 共享沙箱

工作流中的沙箱（Sandbox）节点可以同时供多个 Agent 节点共享。这意味着多个 Agent 可以在同一个代码执行环境中协作。

### 共享沙箱的工作方式

1. 在画布上放置一个沙箱节点，并配置资源参数（CPU、内存、磁盘、超时等）。
2. 将沙箱节点的输出端口分别连接到多个 Agent 节点的沙箱输入端口。
3. 工作流执行时，这些 Agent 节点会共享同一个沙箱会话。
4. 一个 Agent 创建的文件，后续的 Agent 可以读取和修改。

### 沙箱生命周期

工作流中的沙箱有两种生命周期模式：

| 模式 | 说明 |
|------|------|
| session | 沙箱在最后一个直接使用它的节点完成后销毁。适合一次性执行的场景。 |
| persistent | 沙箱在节点解绑后回到就绪状态，可被后续执行复用。适合需要保持环境状态的场景。 |

### 共享沙箱使用场景

**多 Agent 流水线式协作**

一个典型的场景是将多个 Agent 组成流水线：

1. "架构师 Agent" 在沙箱中创建项目结构和设计文档。
2. "开发者 Agent" 在同一个沙箱中编写代码实现。
3. "测试 Agent" 在同一个沙箱中编写并运行测试。

因为共享沙箱，后一个 Agent 可以直接看到前一个 Agent 的产出。

**工作区持久化**

如果你需要在多次工作流执行之间保留沙箱中的文件，可以在沙箱节点上连接一个工作区（Workspace）节点。工作区提供持久化存储卷，即使沙箱销毁，工作区中的文件仍然保留。

## 常见工作流模式

### 模式一：单 Agent 任务执行

最简单的模式——一个触发器 + 一个 Agent + 一个输出：

```
[手动触发] ---> [Agent 节点] ---> [文本输出]
```

触发器将用户输入传给 Agent，Agent 处理后将回复输出到文本输出节点。

### 模式二：多 Agent 流水线

多个 Agent 按顺序执行，每个 Agent 接收前一个 Agent 的输出：

```
[触发器] ---> [Agent A] ---> [Agent B] ---> [Agent C] ---> [输出]
                  \              |              /
                   `--- [共享沙箱] ---'
```

### 模式三：条件路由到不同 Agent

根据条件选择不同的 Agent 来处理：

```
[触发器] ---> [条件分支] ---> [代码 Agent]（IF: 编程任务）
                         ---> [文档 Agent]（ELSE IF: 文档任务）
                         ---> [分析 Agent]（ELSE: 数据分析任务）
```

### 模式四：Agent + 知识库增强

为 Agent 节点额外连接知识库，让它在工作流中也能检索专属资料：

```
[触发器] ---> [知识库节点] ---knowledge---> [Agent 节点] ---> [输出]
                                              ^
[技能节点] ---skill--------------------------'
```

## 注意事项

1. **只能引用已发布的 Agent**：Agent 节点只能选择状态为 "published" 的 Agent 定义。如果目标 Agent 还是草稿状态，需要先发布。
2. **版本锁定**：选择特定版本后，即使 Agent 发布了新版本，该节点仍然使用你选择的版本。如果你想使用最新版本，需要手动更新配置。
3. **沙箱资源限制**：多个 Agent 共享沙箱时，CPU 和内存是共享的。如果每个 Agent 都有较重的计算需求，可能需要增加沙箱资源配置。
4. **超时控制**：Agent 在工作流中的执行超时受沙箱的超时设置和工作流整体超时的双重约束。
5. **错误传播**：如果 Agent 节点执行失败，错误会按照工作流的错误处理规则传播到下游节点。
