# 创建 Agent

本文将引导你从零开始创建一个 Agent，并详细介绍每个配置项的作用。

## 创建流程

### 第一步：进入 Agent 管理页面

> 界面提示：点击左侧导航栏中的 "Agents" 菜单项，进入 Agent 列表页面。

在 Agent 列表页面，你可以看到所有已创建的 Agent，包括它们的名称、状态和创建时间。

### 第二步：点击创建

> 界面提示：点击页面右上角的 "创建 Agent" 按钮，打开创建对话框。

在创建对话框中，你需要填写以下基本信息：

- **名称**：为你的 Agent 取一个有意义的名字，例如"代码助手"、"文档生成器"。
- **描述**（可选）：简要描述这个 Agent 的用途和能力，帮助团队成员理解它的定位。

填写完成后，点击确认，系统会创建一个草稿状态的 Agent 并自动跳转到 Agent 配置画布。

### 第三步：在配置画布中完善 Agent

创建完成后，你将进入 Agent 配置画布。这是一个可视化的编辑器，通过拖拽和连线的方式来组装 Agent 的能力模块。

画布的中心是 **Agent Main** 节点——这是 Agent 的核心控制节点，所有能力模块都需要连接到它的对应端口上。

## 配置画布详解

Agent 配置画布与工作流画布类似，但它用于组装 Agent 的能力组件，而不是编排执行步骤。

### Agent Main 节点

Agent Main 节点是画布中的核心节点，每个 Agent 画布有且只有一个。它具有以下输入端口：

| 端口名称 | 数据类型 | 说明 |
|----------|----------|------|
| 模型 | model | 指定 Agent 使用的 LLM 模型 |
| 工具 | tool | 挂载 MCP 工具（可连接多个） |
| 知识库 | knowledge | 绑定向量知识库（可连接多个） |
| 沙箱 | sandbox | 绑定代码执行沙箱环境（最多一个） |
| Skills | skill | 启用技能模板（可连接多个） |
| 记忆 | memory | 绑定长期记忆存储（可连接多个） |
| 系统提示词 | text | 注入自定义系统提示词（最多一个） |
| 子 Agent | agent | 注册子 Agent（可连接多个） |
| 输入预处理 | json | 连接输入预处理管道（最多一个） |

### 可用的能力节点

你可以从左侧节点面板中拖拽以下节点到画布上，然后连接到 Agent Main 节点：

**LLM 模型节点** — 配置 Agent 使用的大语言模型。选择模型提供商（如 OpenAI、Anthropic 等）和具体模型（如 GPT-4、Claude 等），以及温度、最大 Token 等参数。将其输出端口连接到 Agent Main 的"模型"端口。

**智能路由节点** — 如果你需要在多个模型之间做智能选择（例如根据成本、质量、延迟等策略自动选择最合适的模型），可以使用智能路由节点。将多个 LLM 模型节点连接到智能路由的输入端口，再将智能路由的输出连接到 Agent Main。

**MCP 工具节点** — 为 Agent 添加外部工具能力。每个 MCP 工具节点代表一个通过 MCP 协议连接的外部工具。Agent 在对话中可以按需调用这些工具。

**知识库节点** — 绑定向量知识库，让 Agent 在回答问题时可以检索相关文档。你需要先在"知识库"模块中创建并导入文档，然后在这里选择对应的知识库。

**Memory 节点** — 绑定长期记忆实例。Agent 可以跨对话保留关键信息和用户偏好。每个 Memory 节点可以配置角色（primary 或 readonly）和融合优先级。

**Skill 节点** — 启用预定义的技能模板。技能会注入到 Agent 的系统提示中，引导 Agent 按照特定的流程和标准执行任务。

**沙箱环境节点** — 为 Agent 提供隔离的代码执行环境。每个 Agent 最多配置一个沙箱节点。

**工作区节点** — 为 Agent 提供持久化工作区存储卷，可以跨多次对话保留文件。需要连接到沙箱节点使用。

**子 Agent 节点** — 注册另一个 Agent 作为子 Agent，主 Agent 可以在对话中将子任务委派给它。

**输入预处理器节点** — 对用户输入进行转换预处理，支持 JMESPath、JSONata、模板和脚本四种转换方式。

## 核心配置项详解

### 系统提示词

系统提示词定义了 Agent 的角色、行为准则和能力边界。这是影响 Agent 表现最关键的配置。

好的系统提示词应该包含：

- **角色定义**：Agent 扮演什么角色（例如"你是一名资深前端开发者"）。
- **行为准则**：Agent 应该如何处理请求（例如"始终先理解需求再编写代码"）。
- **输出格式**：期望的回复风格和格式（例如"用中文回复，代码注释使用英文"）。
- **能力边界**：Agent 不应该做什么（例如"不要修改生产数据库"）。

> 界面提示：系统提示词可以直接在 Agent 设置面板中编写，也可以通过将文本节点连接到 Agent Main 的"系统提示词"端口来注入。

### 模型选择

选择合适的 LLM 模型对 Agent 的效果至关重要。不同模型在以下维度有所差异：

| 考量维度 | 说明 |
|----------|------|
| 推理能力 | 更强的模型适合复杂推理任务 |
| 响应速度 | 较小的模型通常响应更快 |
| 成本 | 不同模型的调用成本不同 |
| 上下文长度 | 模型能处理的最大文本长度 |

如果你不确定选择哪个模型，可以使用智能路由节点设置回退链（Fallback Chain），让系统自动在多个模型之间做选择和切换。

### 沙箱配置

当 Agent 需要执行代码或操作文件时，你需要为它配置沙箱环境。沙箱的资源参数包括：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| CPU 限制 | 1 核 | 沙箱可使用的 CPU 核心数 |
| 内存限制 | 512 MB | 沙箱可使用的内存上限 |
| 超时时间 | 300 秒 | 单次操作的超时时间 |
| 对话空闲自动结束 | 10 分钟 | 对话空闲多久后自动关闭沙箱 |

沙箱环境基于容器化技术，完全与你的本地环境隔离。

### 运行时模式

Agent 支持两种运行时模式：

- **sandbox**（默认）：Agent 在沙箱环境中运行，具备代码执行和文件操作能力。适合需要编程辅助的场景。
- **no_sandbox**：Agent 不使用沙箱，仅依靠 LLM 推理和外部工具完成任务。适合纯对话或只需要 API 调用的场景。选择此模式后，配置画布中的沙箱相关端口会自动隐藏。

### 原生工具策略

当 Agent 配有沙箱时，你可以精细控制 Agent 对原生文件工具的访问权限：

| 工具权限 | 说明 |
|----------|------|
| 读取 (read) | 允许 Agent 读取沙箱中的文件内容 |
| 写入 (write) | 允许 Agent 创建新文件 |
| 编辑 (edit) | 允许 Agent 修改已有文件内容 |
| 终端 (terminal) | 允许 Agent 执行终端命令 |

### 自主决策模式

自主决策模式控制 Agent 在遇到需要用户确认的决策时如何处理：

| 模式 | 说明 |
|------|------|
| 手动确认（MANUAL_CONFIRM） | 所有工具调用都需要用户明确批准才能执行。最安全。 |
| 规则匹配（RULE_BASED） | 根据预设规则自动放行或拦截特定操作。中间路线。 |
| LLM 建议（LLM_SUGGEST） | 由 LLM 自行判断是否需要请求用户确认。最灵活。 |

你还可以配置当 Agent 无法完成自主决策时的回退策略：

- 需要人工确认（保留待确认项，等待用户操作）
- 使用默认值（自动补齐缺失字段）
- 跳过字段（忽略当前字段继续执行）
- 终止执行（在关键字段缺失时停止）

## Agent 版本管理

Agent 像代码一样拥有版本管理机制，帮助你安全地迭代和回溯。

### 版本状态

| 状态 | 说明 |
|------|------|
| 草稿（draft） | 新创建或正在编辑中的 Agent |
| 已发布（published） | 当前可用的正式版本 |
| 已归档（archived） | 不再使用但保留历史记录的版本 |

### 发布新版本

当你在配置画布中完成修改后：

1. 点击工具栏中的"发布"按钮。
2. 系统会创建一个新的版本快照，包含当前画布的所有节点、连线和配置。
3. 新版本发布后，所有引用该 Agent 的工作流节点会使用最新的已发布版本。

> 界面提示：版本工具栏位于配置画布的顶部区域，显示当前版本号和操作按钮。

### 版本快照

每个版本快照记录了以下内容：

- 画布中的所有节点和连线
- 运行时模式
- 运行时配置（模型、工具、知识库绑定等）
- 节点数和边数统计
- 变更说明（可选）

### 回溯到历史版本

如果发布后发现问题，你可以查看历史版本列表，选择任意版本进行查看或作为新版本的基础进行修改。

## 最佳实践

### 系统提示词编写建议

1. **具体明确**：避免模糊的描述，用具体的指令代替。例如用"先用 TypeScript 编写单元测试，再实现功能代码"代替"写好的代码"。
2. **分层结构**：用标题和列表组织提示词，让 Agent 更容易解析。
3. **示例驱动**：提供输入输出示例，帮助 Agent 理解期望的行为模式。
4. **迭代优化**：基于实际对话效果不断调整提示词。

### Agent 设计建议

1. **单一职责**：每个 Agent 聚焦一个领域或任务类型，而不是试图覆盖所有场景。
2. **合理配备工具**：只启用 Agent 真正需要的工具，过多的工具可能增加 Token 消耗并降低选择准确度。
3. **善用子 Agent**：对于复杂任务，将其分解为多个子 Agent 各司其职，比让一个 Agent 承担所有工作更有效。
4. **利用记忆**：为需要长期协作的 Agent 启用记忆功能，让它积累对项目的理解。
