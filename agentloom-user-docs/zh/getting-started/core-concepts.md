# 核心概念

在开始深入使用 AgentLoom 之前，了解以下核心概念将帮助你更好地理解平台的运作方式。本页用通俗的语言解释每个概念，并通过日常类比帮助你快速建立直觉。

---

## 工作流 (Workflow)

**一句话理解**：工作流就是你的"自动化流水线"。

### 什么是工作流

工作流是 AgentLoom 的核心载体。它定义了一组 AI 智能体和工具如何按照特定的顺序和逻辑协同工作，最终完成一个完整的任务。

### 类比

把工作流想象成一条工厂流水线。流水线上有多个工位（节点），每个工位负责一道特定工序。原材料从起点进入，在各个工位之间依次传递和加工，最终从终点产出成品。

你不需要时刻盯着流水线运转 -- 只要前期设计好流程并配置好各工位的参数，之后只需按下启动按钮，流水线就会自动运行。

### 关键特征

- **可视化设计**：工作流在画布上以流程图的形式呈现
- **可重复运行**：设计一次，可以多次执行
- **版本管理**：支持保存快照、发布正式版本、回滚和归档
- **三种状态**：草稿（编辑中）、已发布（生产就绪）、已归档（停用保留）

---

## Agent 智能体

**一句话理解**：Agent 就是你的"AI 员工"，每个 Agent 有自己的专长和工作方式。

### 什么是 Agent

Agent 是 AgentLoom 中执行 AI 推理任务的核心单元。每个 Agent 都由一个 LLM（大语言模型）驱动，并通过系统提示词来定义它的角色、能力和行为方式。

AgentLoom 中的 Agent 有两种使用方式：

1. **工作流中的 Agent 节点**：作为工作流的一个环节，接收上游数据、完成处理后将结果传递给下游
2. **独立 Agent**：作为一个独立的 AI 助手，你可以直接和它进行对话交流

### 类比

把 Agent 想象成公司里的一个专业员工。他有自己的岗位职责（系统提示词）、使用的工具（MCP 工具、沙箱等）、参考的资料（知识库），以及对过去经历的记忆（Memory）。

在工作流中，多个 Agent 就像一个项目团队 -- 产品经理、开发者、测试工程师各自分工，按照预定流程协作完成项目。

### 关键特征

- **专精定义**：通过系统提示词定义 Agent 的角色和行为
- **工具使用**：Agent 可以调用外部工具（HTTP 请求、代码执行、MCP 工具等）
- **知识增强**：Agent 可以连接知识库来检索私有文档
- **记忆系统**：独立 Agent 支持跨对话的长期记忆
- **沙箱执行**：Agent 可以在隔离的沙箱环境中运行代码

---

## 节点 (Node)

**一句话理解**：节点是工作流中的"功能积木"，每个节点负责完成一项具体任务。

### 什么是节点

节点是工作流画布上的基本构建单元。每个节点代表一个具体的操作，比如"调用一个 AI 模型"、"发送 HTTP 请求"、"做条件判断"等。你通过将不同类型的节点拖放到画布上并连接起来，来构建你想要的工作流。

### 类比

把节点想象成乐高积木中的一块。每块积木有自己特定的形状和用途，你通过不同的组合方式搭出不同的作品。简单的工作流可能只需要两三个节点，复杂的则可能使用十几个节点的组合。

### 节点分类

AgentLoom 中的节点按功能分为以下几大类：

**Agent 智能体类节点**

- **Chat Agent**：对话型 Agent，接收消息并生成回复
- **LLM 模型**：配置 AI 模型的参数（提供商、模型名称等），为 Agent 提供推理能力
- **智能路由 (Smart Routing)**：从多个候选模型中按策略选择最优模型
- **Agent**：调用一个已发布的独立 Agent 执行任务
- **Skill**：为 Agent 增加预定义的能力模板

**工具类节点**

- **HTTP Request**：向外部 API 发送 HTTP 请求
- **Code Executor**：执行 TypeScript、JavaScript、Python 或 Bash 代码
- **MCP Tool**：接入 MCP（Model Context Protocol）工具
- **Sandbox**：创建隔离的代码执行沙箱环境
- **输入预处理器**：对数据进行格式转换和预处理
- **Workspace**：持久化工作区，跨多次执行保留文件

**触发器类节点**

- **手动触发 (Manual Trigger)**：用户手动点击运行来触发
- **定时触发 (Schedule)**：按照 Cron 表达式定时触发
- **Webhook**：接收外部 HTTP 请求触发
- **API Event**：监听外部 API 事件（如 GitHub Webhook）触发

**知识与记忆类节点**

- **知识库 (Knowledge Base)**：连接向量知识库，让 Agent 可以检索文档
- **Memory**：为 Agent 提供图谱记忆能力，跨对话保留信息

**输出类节点**

- **Text Output**：将上游的文本内容作为工作流最终结果输出
- **JSON Output**：将上游的 JSON 数据作为工作流最终结果输出

**流程控制类节点**

- **Condition**：条件分支，根据规则将数据导向不同路径
- **Loop**：循环容器，重复执行内部子图
- **Iteration**：迭代容器，对数组中的每一项执行内部子图
- **Merge**：合并节点，将多条分支的数据汇合
- **Reusable Block**：可复用块，将一组节点封装为单个可复用单元

## 边 (Edge) / 连线

**一句话理解**：边就是节点之间的"数据管道"，数据和控制指令通过边从一个节点流向另一个节点。

### 什么是边

边（也叫连线）是连接两个节点端口的线段。它定义了数据在工作流中的流动方向和路径。在画布上，边显示为从一个节点的输出端口到另一个节点的输入端口之间的平滑曲线。

### 类比

想象一栋办公楼里的气动传送管（或者更直白地说：水管系统）。不同的房间（节点）通过管道（边）相连，文件和信息通过管道从一个房间传递到另一个房间。管道有规定的输入口和输出口，且只有匹配的接口才能对接。

### 两种边

AgentLoom 中的边分为两种角色：

1. **数据边**：传递实际的业务数据（文本、JSON、模型引用等）
2. **执行流边**：控制节点的运行顺序，告诉引擎"先运行这个节点，完成后再运行那个节点"

你在画布上连线时，系统会根据端口类型自动识别是数据边还是执行流边。

---

## 端口 (Port)

**一句话理解**：端口是节点上的"接口"，决定了节点能接收和输出什么类型的数据。

### 什么是端口

端口是节点上用于连接边的连接点。每个端口有明确的数据类型和方向（输入或输出）。端口在画布上显示为节点边缘的小图形，不同的形状和颜色代表不同的数据类型。

### 类比

把端口想象成电子设备上的接口。USB-C 口只能接 USB-C 线，HDMI 口只能接 HDMI 线。同样，AgentLoom 中"文本"类型的输出端口只能连接到"文本"类型的输入端口。这种类型约束确保了数据在节点之间的传递是安全和正确的。

### 端口数据类型

AgentLoom 支持以下数据类型：

| 数据类型 | 标识 | 说明 |
|---------|------|------|
| Model | model | LLM 模型配置实例 |
| Text | text | 纯文本或自然语言内容 |
| JSON | json | 结构化 JSON 数据 |
| Image | image | 图片数据 |
| Audio | audio | 音频数据 |
| Tool | tool | 工具描述符，供 Agent 调用 |
| Sandbox | sandbox | 沙箱执行环境 |
| Knowledge | knowledge | 知识库引用 |
| Skill | skill | 技能模板 |
| Agent | agent | Agent 智能体引用 |

每种数据类型在画布上有独特的颜色和形状，帮助你在视觉上快速识别。

### 端口的关键属性

- **方向**：输入（左侧）或输出（右侧）
- **必填**：标记为必填的输入端口在运行前必须有连线
- **多连接**：某些端口支持同时连接多条边（如 Agent 的"扩展工具"端口可以连多个工具）
- **类型兼容性**：系统在连线时会自动检查两端的数据类型是否兼容

---

## 执行 (Execution)

**一句话理解**：执行就是工作流的"一次运行"。

### 什么是执行

执行是工作流的一个运行实例。每当你点击"运行"按钮（或通过触发器自动启动），系统就会创建一次新的执行。每次执行有自己独立的输入数据、运行状态和输出结果。

### 类比

如果工作流是一份食谱，那每次执行就是"按照这份食谱做一次饭"。同一份食谱可以做很多次，每次用的食材（输入数据）可能不同，做出来的菜（输出结果）也可能不同，但流程（步骤和顺序）是相同的。

### 执行状态

一次执行会经历以下几种状态：

| 状态 | 说明 |
|------|------|
| 等待中 (pending) | 执行已创建，正在准备 |
| 排队中 (queued) | 等待系统资源分配 |
| 执行中 (running) | 正在运行，节点依次执行 |
| 已完成 (completed) | 所有节点成功执行完毕 |
| 失败 (failed) | 运行过程中某个节点出错导致中断 |
| 已取消 (cancelled) | 用户手动取消了执行 |

### 实时监控

执行过程中，AgentLoom 会通过实时通道（基于 Socket.IO）持续推送每个节点的状态更新和流式输出。你可以在画布上看到节点依次亮起、在属性面板中看到实时输出内容、在底部状态栏看到整体进度。

## 版本 (Version)

**一句话理解**：版本是工作流在某个时刻的"快照"，让你可以放心修改而不怕丢失之前的状态。

### 什么是版本

版本是工作流画布在某个时间点的完整保存记录。它包含了当时的所有节点、连线、配置和视口位置。你可以在编辑过程中随时保存版本（快照），也可以将某个版本正式发布。

### 类比

版本就像文档的"存档点"。就像你在编辑重要文件时会定期"另存为"一个备份一样，AgentLoom 的版本功能让你可以在工作流开发的各个阶段保存进度。如果后续的修改出了问题，你随时可以回到之前保存的版本。

### 版本与发布

AgentLoom 区分两种版本操作：

1. **保存快照**：保存当前画布状态为一个带标签的快照版本。这是一个轻量的保存操作，不影响工作流的运行状态。
2. **发布**：将当前状态或指定版本发布为正式版本。发布后，工作流状态从"草稿"变为"已发布"，可以被分享、被触发器自动运行、被发布到市场。

### 工作流生命周期

一个工作流的典型生命周期：

```
草稿 → (编辑/保存快照) → 发布 → (继续编辑/保存/再次发布) → 归档
```

- **草稿 (draft)**：新创建的工作流默认处于草稿状态，可以自由编辑和运行
- **已发布 (published)**：发布后进入正式状态，可以被分享和自动触发
- **已归档 (archived)**：不再使用的工作流可以归档，归档后不能编辑和运行，但保留历史记录

## 概念之间的关系

让我们把上面的概念串起来，看看它们是如何协同工作的：

1. 你创建一个**工作流**
2. 在画布上添加多个**节点**
3. 通过**边**连接节点的**端口**，定义数据流和执行顺序
4. 配置各个节点的参数（如 **Agent** 的提示词、模型选择等）
5. 保存**版本**以记录进度
6. 点击运行按钮启动一次**执行**
7. 观察执行过程，查看各节点状态和输出
8. 满意后**发布**工作流，使之可以被自动触发或分享给他人

这就是 AgentLoom 的基本工作循环。理解了这些概念后，你就可以开始探索更高级的功能了。
