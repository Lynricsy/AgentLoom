# Database Guidelines

> Drizzle ORM patterns, schema definitions, RLS, and transaction handling in agentloom-server.

---

## Overview

All database access uses Drizzle ORM with PostgreSQL. Schemas are defined as `pgTable` with RLS policies. Multi-tenancy is enforced through RLS via `TenantTransactionInterceptor`. Migrations are raw SQL generated by Drizzle Kit.

---

## Schema Definitions

Schemas live in `src/database/schema/`, with a barrel export in `schema/index.ts`.

### Schema File Convention

File naming: `{table-name}.schema.ts` (kebab-case, matching SQL table name).

```typescript
// src/database/schema/api-keys.schema.ts
import { pgTable, uuid, varchar, boolean, timestamp, index } from 'drizzle-orm/pg-core';
import { createDirectTenantPolicies } from './rls-policies';

export const apiKeyStatusEnum = pgEnum('api_key_status', ['active', 'revoked']);

export const apiKeys = pgTable(
  'api_keys',
  {
    id: uuid('id').primaryKey().default(sql`uuid_generate_v7()`),
    tenantId: uuid('tenant_id').notNull(),
    organizationId: uuid('organization_id').notNull(),
    provider: varchar('provider', { length: 50 }).notNull(),
    label: varchar('label', { length: 255 }).notNull(),
    status: apiKeyStatusEnum('status').notNull().default('active'),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => [
    index('idx_api_keys_tenant').on(table.tenantId),
    ...createDirectTenantPolicies('api_keys'),
  ],
);

// Type exports
export type ApiKey = typeof apiKeys.$inferSelect;
export type NewApiKey = typeof apiKeys.$inferInsert;
```

### Standard Column Patterns

| Column | Pattern |
|--------|---------|
| Primary key | `uuid('id').primaryKey().default(sql\`uuid_generate_v7()\`)` |
| Tenant ID | `uuid('tenant_id').notNull()` |
| Timestamps | `timestamp('...', { withTimezone: true }).notNull().defaultNow()` |
| Enums | `pgEnum()` defined in the same schema file |
| Status fields | Enum type with `.default('initial_status')` |

## RLS Policy Helpers

File: `src/database/schema/rls-policies.ts`

| Helper | Use Case |
|--------|----------|
| `createDirectTenantPolicies(tableName)` | Tables with `tenant_id` column (SELECT/INSERT/UPDATE/DELETE) |
| `createAppendOnlyTenantPolicies(tableName)` | Append-only tables like audit logs (SELECT + INSERT only) |
| `createJoinTenantPolicies(tableName, fkColumn, parentTable)` | Child tables without `tenant_id`, using EXISTS subquery |

**Every tenant-scoped table MUST include RLS policies** in its table builder's third argument.

## Drizzle Query Patterns

### Select with Conditions

```typescript
const [key] = await this.tenantDb
  .select()
  .from(apiKeys)
  .where(and(eq(apiKeys.id, id), eq(apiKeys.tenantId, tenantId)));
```

### Select with Specific Columns

```typescript
const keys = await this.tenantDb
  .select({ id: apiKeys.id, provider: apiKeys.provider, label: apiKeys.label })
  .from(apiKeys)
  .where(eq(apiKeys.tenantId, tenantId));
```

### Insert with Returning

```typescript
const [created] = await this.tenantDb
  .insert(apiKeys)
  .values({ tenantId, organizationId: org.id, provider, label })
  .returning();
```

### Update with Returning

```typescript
const [updated] = await this.tenantDb
  .update(apiKeys)
  .set({ label: newLabel, updatedAt: new Date() })
  .where(and(eq(apiKeys.id, id), eq(apiKeys.tenantId, tenantId)))
  .returning();
```

### Count

```typescript
const [result] = await this.tenantDb
  .select({ count: sql<number>`count(*)::int` })
  .from(apiKeys)
  .where(eq(apiKeys.tenantId, tenantId));
return result?.count ?? 0;
```

## Transaction Patterns

### Per-Request Tenant Transaction (automatic)

The `TenantTransactionInterceptor` wraps every authenticated request in a transaction with RLS context. Services access it transparently via `this.tenantDb`.

### After-Commit Hooks

Schedule work to run after transaction commits:

```typescript
registerAfterCommitHook(async () => {
  await this.notificationService.send(notification);
});
```

### Explicit Transaction in Workers

Workers run outside the HTTP interceptor chain, so they call `runInTenantTransaction` directly:

```typescript
await runInTenantTransaction(this.db, tenantId, async () => {
  await this.executionService.initializeSteps(executionId);
});
```

### Raw Transaction (no RLS)

Used in background jobs that operate across tenants:

```typescript
await this.db.transaction((tx) =>
  this.archiveExpiredHotRows(tx, tenantId, cutoff, batchSize),
);
```

## Migrations

- Location: `src/database/migrations/`
- Format: Raw SQL files, numbered sequentially (`0000_` through `0052_+`)
- Generated by Drizzle Kit: `pnpm db:generate`
- Applied via: `pnpm db:migrate`
- Statement separator: `-->\s*statement-breakpoint`

---

## Forbidden Patterns

1. **TypeORM entities** — all schema uses Drizzle `pgTable`
2. **Missing RLS policies** — every tenant-scoped table MUST include `createDirectTenantPolicies`
3. **Bypassing `tenantDb`** — never use `this.db` directly for tenant-scoped operations
4. **`db.transaction()` in request-scoped code** — let `TenantTransactionInterceptor` handle it
5. **Manual RLS setup** — always use the RLS policy helpers
