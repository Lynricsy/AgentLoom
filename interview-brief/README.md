# AgentLoom · 面试用双册

两本 A4 PDF，共用一套瑞士国际主义视觉（IKB 克莱因蓝）。

| 册 | 页数 | 用途 |
| --- | ---: | --- |
| **`out/AgentLoom-系统设计与开放问题.pdf`** | 41 | **主线**。面向学术/工程硕博面试：问题域、核心抽象、可迁移设计原则、在已有工作中的定位、评估方法与五个开放问题、参考与核实 |
| `out/AgentLoom-实现细节参考册.pdf` | 53 | 附册。模块、数据表、接口、协议信封、队列策略。**仅在被追问具体机制时翻阅** |

在学术场合先讲实现，等于宣布自己没有抽象层。因此主线永远是设计册。

## 重新生成

```bash
cd interview-brief
node build.mjs            # 两册都构建
node build.mjs design     # 只构建设计册
```

构建脚本会：

1. 拼接 `shared/head.html` + `decks/<deck>/*.html`（按文件名排序）；
2. 注入页眉、页码，并按 `data-ref` ↔ `data-sec` 解析目录页码；
3. 用 headless Chrome 输出 A4 PDF（`preferCSSPageSize`，`@page { margin: 0 }`，每页固定 210×297mm）；
4. 版面体检：纵向溢出、横向滚动、任意后代越出页面内容盒、目录引用未解析——任一命中即列出页号并以非零码退出。

## 目录结构

```text
interview-brief/
├── shared/head.html          # 设计系统：字体挂载、配色、排版层级、组件
├── decks/design/             # 设计册（主线）
│   ├── 01-front  封面 / 定位说明 / 目录 / 一页纸主张
│   ├── 02-partI  问题域：四个本质困难、三组张力、设计空间、四条可证伪立场
│   ├── 03-partII 核心抽象：二元计算模型、状态与调度、追溯vs重放、有界展开、
│   │              类型协商、能力单调收窄、单向断言、记忆表示
│   ├── 04-partIII 可迁移原则：配置漂移、fail-closed 边界、中断粒度、隔离选择、状态外置
│   ├── 05/05b-partIV 定位：编排框架、持久化引擎、隔离谱系、协议层、记忆检索、三条差异
│   ├── 06-partV  评估方法、未做的评估、五个开放问题
│   ├── 07-close  学术问答、三分钟陈述脚本
│   ├── 07b-references 参考与核实：论文/官方文档出处 + 核实日期
│   └── 08-back   封底（必须排在最后，文件名排序即页序）
└── decks/implementation/     # 实现册（附册）
```

## 字体依赖

需要 `noto-fonts-cjk`、`inter-font`、`ttf-jetbrains-mono`。CSS 通过 `file://` 直接挂载字体文件，绕开 Chrome 侧 fontconfig 泛用族解析失效的问题。

## 内容纪律

- **量级数字**：本项目**有**单元与集成测试（服务端 80% 覆盖率门槛），但**没有性能基准、故障注入、逃逸测试与对照实验**。设计册中不出现任何未经自测的性能数字；相关工作的数字必须带出处与测量条件。
- **能力宣称**：凡是「我做到了 X」都必须能对应到源码；核实过程中已推翻多条初稿断言（如工具级审批并非本系统独有、进程崩溃后无工具级恢复、调度并非「水平扩展免费」）。
- **局限**：一律收敛到设计册 § V.2 与实现册 F1，正文不做粉饰。
